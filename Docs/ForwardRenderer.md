# Минимальный Forward Renderer

Реализация в исходниках покрывает пункты 1, 2 и 4–7. Скелетная анимация и GPU skinning не добавлялись. Сборка и GPU-прогон этой версии ещё не выполнены; приведённые ниже возможности описывают код, а не подтверждённый результат запуска.

## Путь кадра

Engine создаёт один `RenderFrameData` со снимками всех активных поверхностей. Каждый `RenderViewFrame` содержит собственную сцену, камеру и настройки. Единственный Render Thread исполняет для каждой поверхности:

1. Отбор объектов по AABB и frustum камеры; отбор локальных источников по диапазону. Непрозрачные объекты сортируются от ближних к дальним.
2. Карты глубины теней в атласе. Объекты для теней проверяются относительно объёма источника, а не списка видимых камерой объектов.
3. Непрозрачный и alpha-mask Forward PBR в RGBA16F с D32 depth.
4. Прозрачные поверхности в отдельные accumulation/revealage-буферы с depth test без записи глубины.
5. Композиция прозрачности в линейном HDR, exposure, threshold bloom и ACES-приближение.
6. FXAA и вывод в sRGB swapchain. Qt UI рисуется отдельно.
7. Fence после работы всех поверхностей, единственный FinishFrame и освобождение отложенных ресурсов, чьи кадры завершены GPU. Все swapchain имеют IsPrimary=false: отдельный Present не завершает общий кадр.

## Свет и материалы

Используется GGX metallic/roughness BRDF с Fresnel и геометрическим затенением. Нормали преобразуются inverse-transpose матрицей. Если у меша нет нормалей, uploader рассчитывает их по треугольникам.

Поддерживаются directional, point и spot. На вид выделено 32 источника и 16 ячеек теней по 1024×1024 в атласе 4096×4096. Directional и spot занимают одну ячейку; point — шесть. Переполнение бюджета видно в статистике. Directional использует ограниченную область относительно камеры, без каскадов. Фильтрация теней — PCF 3×3 с bias.

IBL использует встроенное окружение неба. При инициализации создаются diffuse irradiance cubemap, GGX-prefiltered reflection cubemap с mip-уровнями и интегрированная BRDF LUT. Интенсивность задаётся отдельно. Импорт пользовательского HDR-окружения и локальные reflection probes в эту минимальную версию не входят.

Формат `.material` остаётся schemaVersion 1. Старые материалы сохраняют непрозрачный режим по умолчанию. Доступны:

- `baseColor`, `baseColorTexture`, `metallic`, `roughness`;
- `alphaMode`: `OPAQUE`, `MASK`, `BLEND`;
- `alphaCutoff`, `doubleSided`, `castShadows`;
- `emissive`: три неотрицательных линейных значения, допускающие HDR.

Неверные типы, неизвестный alphaMode и факторы вне допустимого диапазона возвращают диагностику загрузчика. Для MASK одинаковый alpha test используется в основном и теневом проходах.

BLEND реализован через weighted blended OIT. Результат не зависит от порядка объектов; пересекающаяся геометрия не требует сортировки. Это приближение многослойной прозрачности: нет физической рефракции, цветных transmission shadows и точного послойного композитинга. BLEND получает освещение и тени, но сам не отбрасывает тени. Очень большой overdraw и экстремальная яркость ограничены точностью FP16 accumulation.

## Поверхности и ресурсы

`Engine::RegisterRenderSurface`, `ConfigureRenderSurface`, `ResizeRenderSurface`, `UnregisterRenderSurface` управляют независимыми native surfaces. Surface 1 создаёт device; следующие поверхности используют тот же device/context и собственные swapchain, размер, камеру, HDR/depth/OIT-буферы, атлас и query ring. Для нескольких native surfaces нужен D3D12 или Vulkan. OpenGL остаётся резервным вариантом одной поверхности.

Редактор показывает Scene и Game одновременно. Scene использует EditWorld и редакторскую камеру; Game — активный мир и CameraComponent. API позволяет задавать отдельные настройки каждому виду. В редакторе есть общие controls для exposure, IBL, bloom и FXAA.

Скрытые/нулевые поверхности приостанавливаются. Qt сообщает об уничтожении native surface до её удаления; detach ждёт GPU idle. Resize и shutdown также используют ожидание idle: это сознательно простой вариант, который может кратковременно остановить все поверхности при resize. В обычном кадре такого ожидания нет.

Удаление ассетов устроено иначе: GPU-объекты остаются в менеджере до fence, покрывающего последний уже отправленный кадр. Число сигнала равно `FrameIndex + 1`; очередь кадров сохраняет порядок. Отмена загрузки после создания GPU-ресурса тоже ставит его на освобождение. Идентификаторы ресурсов не переиспользуются после перезапуска Renderer. Закрытие проекта очищает upload-cache, отменяет CPU-загрузки и инициирует освобождение GPU-ассетов; default mesh живёт до shutdown.

## Статистика

`Engine::GetRenderStatistics(RenderSurfaceId)` возвращает копию статистики, опубликованную через mutex. Метрики:

- CPU-время подготовки и отправки вида без Present;
- GPU duration отдельно для shadows, opaque, transparency и postprocess;
- frame index текущей CPU-статистики и отдельный `GpuFrameIndex` задержанного измерения;
- число объектов, отсеянных/видимых объектов, draw calls и треугольников, включая теневые проходы;
- источники света, теневые виды и переполнение бюджетов;
- resident meshes/textures, очередь освобождения и оценка памяти GPU-ассетов без внутренних render targets и памяти драйвера.

Каждая поверхность использует кольцо из четырёх наборов запросов. Результат считывается только при готовности. Если GPU ещё занят, измерение пропускается вместо ожидания. Если device не поддерживает duration queries, `bGpuTimingsAvailable` остаётся false. Occlusion culling, Hi-Z, spatial tree и автоматический LOD не добавлялись: минимальная оптимизация видимости здесь — frustum/range culling и front-to-back порядок.

## Проверка

`Samples/RenderValidation/RenderValidation.project` содержит 83 объекта: ряд roughness/metallic-сфер, пол, три типа света с тенями, пересекающиеся прозрачные поверхности, alpha-mask, emissive и 64 объекта вне камеры. Генератор `GenerateScene.py` воспроизводит GLB, материалы, PNG и `.meta` с устойчивыми GUID и актуальным FNV-1a.

Добавлены проверки:

- `SakuraRenderViewTest`: видимый объект, боковая/задняя/дальняя плоскости, пересечение near plane и объём, содержащий frustum;
- `SakuraAssetTest`: режимы BLEND/MASK, emissive, defaults и отклонение некорректных факторов;
- `SakuraForwardRendererTest` (`Engine.Render.Forward`): инициализация шейдеров и двух поверхностей, загрузка ресурсов, culling, восемь shadow views, suspend/resize/resume/reattach и освобождение ресурсов после закрытия проекта. Параметр `--vulkan` выбирает Vulkan для дополнительного прогона.

В этой сессии проверены структура CMake-списков, наличие новых shader entry points, баланс скобок, `git diff --check`, связи и контрольные суммы технического проекта, структура GLB, индексы и winding треугольников, воспроизводимость генератора и обработка Qt-заголовков через moc. Это не заменяет сборку, Diligent validation и визуальную проверку на GPU. Перечисленные C++/GPU-тесты ещё не запускались.
