# Встроенные примеры на общих механиках

Файлы `*.sacura-template.json` содержат `sacura-authoring-package`, formatVersion 2,
roots.kind `template`, gameplay.version 2. Расширение файла сохранено для знакомого
пути загрузки. Это тот же контейнер, что локальные пользовательские заготовки.
Старый `sacura-project-template` остаётся читаемым через адаптер.

Каталог доступен на главной странице и в «Файл → Новый проект → Основа проекта».
Загрузчик проверяет пакет; `instantiateAuthoringTemplate` добавляет его в пустой
проект через `planPackageImport`. Объекты, события, функции, сигналы, камеры,
виджеты, кнопки и их ссылки получают согласованные ID. После создания проекта
исходный файл шаблона не нужен; ID происхождения служит только сведениями об авторстве.

## Четыре примера

| Пример | Как проверить | Где изменить поведение |
| --- | --- | --- |
| Новелла · Отношение и ответы | «Поддержать» увеличивает отношение; после реплики доступен личный вопрос. Холодный ответ его не открывает | Механика «Награда за действие», Event ответа, условие доступности следующего ответа |
| Point & click · Квест | Подобрать ключ и записку, соединить в инвентаре, нажать дверь или использовать ключ с кодом; открывается диалог во дворе | Правило запертой двери, условия инвентаря, Event открытия и функции журнала |
| Шутер · FPS, HP и Game Over | После вступления WASD, ЛКМ, R, 1/2, H, E и Esc. Два попадания пистолета снимают 50 HP; побеждённая цель даёт 100 очков | Независимые движение, камера, оружие, здоровье; правила смерти, аптечки и механика задания |
| UI-кликер · Монеты | Нажать «Получить монету», затем «Улучшить скорость». Каждый игровой тик начисляет выбранное количество | Правила конкретных кнопок, общая функция награды, игровой таймер и переменная скорости |

В квесте нет здоровья и оружия. В кликере и новелле не нужен герой; кликер не
содержит пространственных объектов или физических тел. Их правила, функции и
операции исполняет тот же runtime, что шутер. Пустая логическая сцена остаётся
частью текущего формата проекта; это не требование подключать 3D-физику.

## Задание шутера

Механика «Задание по группе целей» содержит обычный граф состояний:
«Задание не начато → Активно → Завершено». Event входа в боевую сцену отправляет
сигнал начала. Правило смерти участников группы награды отключает их управление,
поведение и оружие, скрывает тело, записывает результат и отправляет награду. Отдельное правило любого сигнала смерти запрашивает проверку
выбранных целей задания, независимо от группы награды. Смерть героя отдельно отключает управление/оружие,
ожидает Event смерти и выбирает Game Over. Аптечка проверяет ранение и наличие
предмета, использует зарегистрированную операцию инвентаря; её количество и HP
показываются явными привязками.

Параметр «Цели задания» выбирает объекты или группу по тегу. Исходный пример
содержит пять целей в данных; условие завершения не содержит числа пять.
Пустая группа не завершается. Проверка выполняется после смерти цели или по
явному сигналу проверки, только в активном состоянии. Состав группы определяется
заново при каждой проверке: добавленная до завершения живая цель препятствует
победе. Отсутствие у цели состояния здоровья тоже препятствует завершению.
Поздно добавленное здоровье инициализируется один раз из возможностей объекта.

Тег выбирает активные объекты проекта. Скрытый объект остаётся участником;
`active: false` исключает его из группы. После завершения новые участники не
открывают задание снова; перезапуск проекта создаёт новый сеанс. Чтобы заменить
пять целей на три или восемь, измените данные объектов/их тегов и возможностей,
а не исходники runtime. Все реакции видны в обычном редакторе механик.

## Переносимая награда и применение к существующей сцене

`reward.sacura-package.json` содержит механику «Награда за действие», обычную
Blueprint-функцию «Начислить награду», сигнал и счётчик. Та же функция используется
для отношения в новелле, очков/числа целей в шутере и монет в кликере.

В действующем проекте: «Игровые механики → Импортировать» → выбрать этот файл →
выбрать свою сцену в обязательной привязке → «Проверить импорт» → изучить состав
и переименования → «Добавить в проект». Добавятся независимые определения,
функция, сигнал и счётчик. Камера, ввод и виджеты существующего проекта не
перезаписываются. Импорт отменяется одним Undo. Полный шаблон предназначен для
пустого проекта; для существующей сцены переносите отдельную механику.

Чтобы подключить награду к своему действию, отправьте импортированный сигнал
или вызовите её обычную функцию из правила/Event, выбрав владельца, счётчик и
величину из сигнатуры. Изменения общей логики доступны через «Изменить логику»
и графовый редактор. Локальная копия не обновляет исходный пакет автоматически.

## Миграция и самостоятельный player

Проекты gameplay.version 1 читаются в версии 2 без смены ID. Нормализованные
правила сохраняют связи и ожидания событий; старые обработчики повторно не
добавляются. Отчёт и исходник доступны в дополнительных свойствах проекта:
«Отчёт о преобразовании игровых механик → Скачать исходный проект».
Неизвестные настройки сохраняются с диагностикой. Резервная копия не входит в
авторский пакет, runtime-проект или экспортируемый HTML.

Обычный экспорт: «Файл → Экспортировать игру (HTML)…». Для воспроизведения всех
четырёх готовых HTML из репозитория:

```sh
npm test
npm run build:player
npm run build
node scripts/export-template-players.mjs
```

Результаты находятся в `dist/examples`: `novel.html`, `point-and-click.html`,
`shooter.html`, `ui-clicker.html`. Они содержат собранный player и проект, без
загрузчика шаблонов. Открыть можно как файлы или через `npm run preview`.
Следующая сборка очищает dist; скрипт создаёт HTML заново.

`node scripts/build-builtin-templates.mjs` — инструмент сопровождения примеров,
не установщик пакетов. Он пересобирает четыре JSON и рецепт через существующий
экспорт из зафиксированных исходных примеров и открытых возможностей. Он не
вызывается при импорте или запуске игры. Пользовательский вариант экспортируйте
под отдельным именем, сохраняя происхождение.
