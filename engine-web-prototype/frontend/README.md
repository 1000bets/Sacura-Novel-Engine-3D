# Sacura Novel Studio — UI prototype 04

Локальный макет редактора 3D-визуальных новелл и point-and-click. React, React Flow и Three.js здесь нужны для проверки интерфейса; это не реализация будущего C++-движка.

## Запуск

```powershell
cd engine-web-prototype/frontend
npm install
npm run dev -- --host 127.0.0.1 --port 5173
```

Открыть http://127.0.0.1:5173/. Если сервер уже работает, второй запуск не нужен.

## Рабочая область

- **В центре — сцена.** Разделитель между сценой и графом перетаскивается мышью. Боковые панели тоже меняют ширину. Двойной клик по разделителю возвращает размер. Кнопка разворота есть у сцены и графа.
- **Сцена / Игра.** В сцене ЛКМ выделяет объект, Alt+ЛКМ вращает камеру, СКМ сдвигает обзор, ПКМ+WASD/QE включает свободный полёт (Shift ускоряет); игра использует постановочную камеру. Диалог и ответы находятся внутри игрового кадра. Переключение режима, выделение и resize не перезапускают проигрывание.
- **Слева — Иерархия / История.** Объекты, поиск реплик, эпизоды и сабсцены. Поиск раскрывает эпизоды. Выбор реплики показывает её свойства и граф.
- **Под сценой — Сценарий / Постановка / Событие.** Три уровня одной истории: переходы между репликами; события до, во время и после текста; группы и Actions внутри события.
- **Справа — Инспектор.** Свойства выделенного объекта или узла. Основные параметры Action также редактируются прямо на графе. «Все параметры рядом» открывает большой редактор в центральной области.
- **Проект, Звук, Активные, Ошибки** доступны вкладками той же нижней панели.

## Виджеты интерфейса игры

Откройте **Виджеты UI** в рабочей области или кнопку редактора интерфейса над сценой. В одной библиотеке хранятся диалог, главное меню и меню паузы. Слева назначаются стандартные виджеты проекта и выбираются элементы; справа доступны положение, анкеры, pivot, содержимое, действия кнопок и оформление.

- Перетаскивайте элементы на холсте, меняйте размер за нижний правый угол. Стрелки перемещают выбранный элемент, Shift увеличивает шаг. Одно перетаскивание отменяется одним Ctrl+Z.
- Анкеры задаются пресетами или числами 0–1 относительно родительской панели. Растяжение по ширине/высоте сохраняет отступы; смена анкеров сохраняет положение. Проверьте результат на пяти разрешениях в списке над холстом.
- Добавляйте панели, текст, кнопки, изображения и ответы игрока. Привязки подставляют имя персонажа, реплику, ответы и название игры. Кнопки запускают игру, продолжают диалог, снимают паузу, начинают игру заново или открывают главное меню.
- У персонажа есть поле **Виджет диалога персонажа**. В самом низу инспектора реплики находится **Переопределить виджет этой реплики**. Приоритет: реплика → персонаж → стандарт проекта. **Свой вариант** создаёт отдельную копию, назначает её выбранному персонажу/реплике и открывает редактор.
- Цвета, шрифт, отступы, рамка, скругление и прозрачность меняются без CSS. Для CSS используйте `.widget-element`, `[data-role="dialogueText"]`, `[data-element="ID"]`; `:widget` обозначает холст. Поддерживаются обычные правила без вложенности, `@`-директив и `url()`. CSS изолирован внутри виджета и применяется после параметров инспектора.

**Проверить в игре** показывает выбранный виджет в игровом кадре. Главное меню доступно кнопкой **Меню**, пауза — кнопкой проигрывания или Escape. Виджеты сохраняются, экспортируются и импортируются вместе с проектом; старые проекты автоматически получают стандартные виджеты.


## Проводник проекта

В основной строке вкладок есть **Проводник**: слева дерево `Assets`, справа папки и файлы, снизу информация о выбранном ресурсе и объекты, которые его используют. Он показывает модели сцены и персонажей, встроенный звук и импортированные файлы. Поиск работает по текущей папке и всем её вложенным папкам.

«Импорт файлов» принимает несколько файлов, «Импорт папки» сохраняет вложенную структуру; можно перетаскивать файлы в область списка и создавать пустые папки. До 100 МБ на файл, с проверкой свободного места в автосохранении. Для GLB/OBJ доступно «Добавить в сцену». Библиотека и папки сохраняются в JSON проекта; модель остаётся в библиотеке после удаления последнего объекта или замены его меша. Пункт **Звук и окружение** перенесён в меню **Ещё**.

### Анимации Mixamo для персонажей

1. Во вкладке **Персонажи** загрузите GLB-модель со skinned mesh и humanoid-скелетом (до 100 МБ, ресурсы встроены).
2. В Mixamo скачайте движение: **FBX Binary → Without Skin**. FBX с мешем тоже принимается, но его меш и текстуры не добавляются в проект.
3. В **Пуле анимаций** нажмите **Добавить анимации из файла** и выберите `.fbx` до 100 МБ. Все непустые движения из файла станут отдельными карточками. Также поддерживается прежний импорт `.glb` до 100 МБ с тем же скелетом и именами костей.
4. Нажмите **Посмотреть**, затем назначьте движение для ожидания, ходьбы или действия в сценарии. Название, описание, скорость и повтор настраиваются в карточке.

Повороты переносятся с учётом bind pose и осей костей, перемещение таза — с учётом масштаба скелетов. По умолчанию включено **Движение на месте**: горизонтальное смещение удаляется, прыжки сохраняются, а перемещение персонажа задаёт сценарий. Снимите галочку **до импорта**, если требуется смещение из FBX; оно может складываться с перемещением в сценарии.

Автоматическое сопоставление поддерживает имена Mixamo (`mixamorig:Hips`, `mixamorigHips` и аналогичные), основные humanoid-имена (`Hips`, `Spine`, `LeftArm`, `LeftUpLeg` и т. д.) и ряд распространённых вариантов (`pelvis`, `upper_arm.L`, `thigh_r`). Требуются таз, позвоночник, голова, обе цепочки рук и ног. Для произвольных имён костей сначала переименуйте скелет в 3D-редакторе; ручного сопоставления костей пока нет. Мимика и scale-треки FBX не переносятся, позиции конечностей сохраняются из целевой модели. Проверьте результат на персонаже: при сильно отличающихся пропорциях возможны пересечения и скольжение ног.

Анимация сохраняется внутри JSON проекта уже для выбранного скелета; исходный FBX больше не нужен. При замене модели пул импортированных движений сбрасывается — импортируйте их для нового персонажа заново.

## Custom mesh и материалы

Добавьте куб, сферу, цилиндр или интерактивный предмет и выберите его. В инспекторе «Меш и материалы» нажмите «Загрузить меш» или перетащите файл на блок загрузки. Поддерживаются GLB со встроенными ресурсами и OBJ (геометрия без MTL), до 100 МБ. Масштаб и начало координат из файла сохраняются; положение, поворот и размер меняются обычными инструментами сцены.

Выберите весь объект или отдельный слот импортированной модели и назначьте матовый материал, металл, пластик или камень. Можно изменить цвет, шероховатость, металличность и включить двусторонний рендер. Назначение слота имеет приоритет над назначением всему объекту. «Исходные материалы» снимает общее назначение, «По умолчанию» снимает назначение слота. «Вернуть примитив» удаляет custom mesh и его назначения. Материалы также доступны для встроенных декораций.

Модель и назначения входят в JSON проекта, копируются вместе с объектом и поддерживают отмену изменений. Если для автосохранения не хватает места, импорт показывает ошибку и сохраняет предыдущую модель.

## Изменения 04

- **Сабсцены** — отдельная карта настоящих межсценовых связей, возвратов и концовок. Под картой видны источник, ответ, условие и точная реплика назначения. Нажатие на переход открывает его в сценарии.
- **Эффекты** — 30 примеров: дождь, гроза с молнией, туман, снег, ясное небо, время суток, свет, движение, позы, камера, дверь, предметы, светлячки и лепестки. «Проба» применяет событие в 3D, «Граф» открывает структуру, «В реплику» добавляет реальное размещение. «Проиграть постановку» соединяет четыре последовательные группы с параллельными действиями внутри.
- Игровые камеры находятся внутри гостиной, сада и станции. При ожидании предмета камера показывает его крупнее; записка/письмо имеют линии, печать и подпись осмотра. Декорации не перекрывают записку на скамье.
- Продолжить можно кликом по всей карточке диалога или свободной области сцены. Выбор ответа и ожидание предмета таким кликом не пропускаются.
- Погода и время переключаются прямо в правом верхнем углу сцены. В playtest это временное изменение; вне проигрывания — начальное состояние выбранной сабсцены.
- Звук использует общий Web Audio output, разблокируемый кликом запуска. Очень тихие записи усиливаются при воспроизведении с ограничением по пику; исходные файлы сохранены. Уровень выхода виден под сценой. Ошибки файлов видны в пульте.
- События показывают в сцене тип действия, цель, применение и прогресс движения. Повторная проба не разрешает незаметно запустить два Move одного персонажа. Пробы работают отдельно от сюжета; «Стоп» возвращает редактор.

## Что попробовать

1. На первой реплике открыть **До реплики**. Музыка и дождь стартуют вместе, результаты сходятся, затем меняется камера. В этой же реплике есть параллельные события во время текста и последовательные действия после него.
2. Переключить **Вместе / По очереди** на группе в графе. Кнопка `+` добавляет событие в эту группу; шестерёнка открывает порядок и состав. Соседние группы можно объединить для одновременного запуска.
3. Открыть действия события. Перемещение предлагает объект и точку; погода и время — состояния; звук — файл и громкость. У размещённого события параметры меняют только его экземпляр. Состав групп редактируется в исходном шаблоне.
4. Открыть «Письмо на столе» → «Что сказать Бобу?». **Обзор развилки** показывает ближайшие разные продолжения. Выходы ответов соединяются мышью; обычные связи тоже можно переназначать. В инспекторе ответа задаётся условие и конкретная реплика назначения.
5. Запустить с этой развилки и выбрать **Спрятать письмо**: `ls1 → ls2 → ls3 → station-entry`. Другая ветка ведёт в сад. На станции выбор возвращения домой недоступен без письма, а билет требует клика по объекту в 3D.
6. Запустить с начала: WAV и три MP3 используются как фоновая тема и голоса первых трёх реплик. Вкладка **Звук** позволяет прослушать файлы, менять громкость, loop, fade и привязывать звук к реплике. Волны извлекаются из самих файлов.
7. Открыть **Активные**. Эффекты и экземпляры показывают состояние, источник и границу жизни. Можно приостановить эффект или завершить событие целиком. Пауза экземпляра приостанавливает его конечные действия; остановка отменяет последующие группы.
8. Открыть **Ошибки**: в `l3` намеренно сталкиваются два Move Алисы; в `t1` два события ждут друг друга. Есть переход к проблеме и исправление. Лаборатория сбоев показывает частичный запуск, исчезновение объекта, устаревший экземпляр, ошибку cleanup и выход из сабсцены.

## Сохранение

Проект сохраняется в `localStorage/sacura-studio-v2`; раскладка и координаты узлов — отдельно в `sacura-workspace-v3`. Пользовательские шаблоны и данные прежней версии сохраняются. Перед миграцией v1 остаётся резервная копия `sacura-ui-project-v1-backup`.

Меню **Файл**: экспорт и импорт JSON. Перед импортом создаётся резервная копия текущего проекта `sacura-studio-v2-backup-v3`. **Правка / Ctrl+Z** отменяет до 20 последних изменений текущей сессии. `Ctrl+S` подтверждает локальное сохранение. При ошибке чтения сохранение не перезаписывается.

Изменения содержания во время проигрывания используются в следующем запуске. Текущий playtest работает со снимком проекта.

Основной вход — `src/Editor.jsx`. `Studio.jsx` и старые экраны оставлены в исходниках для сравнения.

## Проверки и пределы

`npm test`: автоматические проверки порядка фаз, параллельных запусков, ожидания аудио, ветвлений, миграции, локальных переопределений, конфликтов, паузы/отмены экземпляра и отмены поздних действий. `npm run build` проходит.

Проведена браузерная проверка: внешний вид в обычном окне и при 1440×900, resize мышью, сохранение диалога при выборе объекта и смене режима, первые три озвученные реплики, отдельная ветка до станции, условный ответ, клик по билету, смена порядка группы, открытие Action, вставка вложенного выбора с сохранением продолжения и переназначение связи с отменой. Для каждого из четырёх файлов проверены запуск и ненулевой сигнал Web Audio на выходе. Оценка звучания человеком не проводилась.

Это ограниченный планировщик предпросмотра. Перемещение плавно интерполирует позицию в течение указанной длительности, учитывает паузу и остановку. Погода и время меняют частицы, туман, цвет неба и освещение; сложной физической симуляции нет. Арбитр ресурсов, очереди, подтверждённый cleanup, AI/NPC и универсальное ожидание результатов других событий представлены диагностикой и настройками, а не производственным C++-runtime. Для ожидания действия игрока используется отдельный блок взаимодействия. Статическая проверка не доказывает корректность всех возможных графов и межрепличных пересечений.

## Создание действий, групп и событий

Кнопка **«Действия и события»** в верхнем меню открывает большую рабочую область. Тот же редактор доступен во вкладке **«Создание»**. Вверху всегда видны три кнопки: **+ Действие**, **+ Группа действий**, **+ Событие**.

1. Создайте действие, дайте название, выберите тип и настройте объект, звук или окружение. Нажмите **«Сохранить в библиотеку»**.
2. Из действия можно сразу **создать событие**. Внутри шага добавляйте параллельные действия из библиотеки или по типу; **«Добавить следующий шаг»** создаёт последовательность. Группы тоже сохраняются отдельно.
3. **«Проверить в сцене»** запускает отдельное превью текущего черновика. **«В реплику»** добавляет сохранённое событие в текущую реплику с явным выбором «до / во время / после».
4. Готовые события доступны и в графе. При повторном открытии чистый редактор получает актуальные изменения из графа. Несохранённые черновики доступны в списке библиотеки, пока приложение открыто.

Действия и группы вставляются как независимые копии с новыми ID. Изменение шаблона события применяется к его размещениям; локальные переопределения сохраняются. Пустые шаги, конфликтующие параллельные команды и незаданная роль замены показывают ошибку до сохранения.

## Редактирование 3D-сцены

Нажмите **«Редактор сцены»** над 3D-кадром. Воспроизведение остановится, чтобы редактировать исходную постановку. Выберите персонажа, мебель или предмет в сцене либо в иерархии.

- **W / Сдвиг**, **E / Поворот**, **R / Масштаб** — перетаскивание цветных осей. **Q** — выбор без манипулятора; **F** — приблизить объект. Клавиши работают, когда фокус находится в сцене.
- В инспекторе доступны XYZ, поворот в градусах, масштаб, сброс, дубликат и удаление. Изменение числового поля применяется по Enter или потере фокуса. Ctrl+Z отменяет редактирование.
- **«+ Объект»** добавляет персонажа, интерактивный предмет, куб, сферу или цилиндр. Форма простого меша и цвет меняются в инспекторе.
- Магнит включает привязку 0,25 м / 15° / 0,1×. Оси можно переключать между миром и объектом.
- Размещение хранится отдельно для каждой сабсцены и сохраняется в JSON/локальном проекте. Перенос записки учитывается камерой взаимодействия; события движения начинают путь из авторской позиции.

В макете редактируются объекты и собранная из примитивов мебель. Стены, пол, потолок, окно, лампа, деревья, дорожка, платформа, рельсы и навес также доступны в иерархии и редактируются как объекты. Составные предметы перемещаются целиком; это не редактор полигональной геометрии.


## Камеры и слежение

Над 3D-сценой появилась кнопка **«Камеры»**. Камеры также видны в иерархии сабсцены.

- **Камера из вида** сохраняет тот ракурс, который сейчас виден в 3D. Поверните свободный обзор мышью, сдвиньте его правой кнопкой, приблизьте колесом — затем создайте камеру.
- **Настроить ракурс мышью** открывает кадр выбранной камеры. Найдите композицию и нажмите **«Сохранить ракурс»** над сценой. Крестик вернёт свободный обзор без сохранения. Угол обзора задаётся ползунком.
- В свободном редакторе камеры обозначены розовыми 3D-маркерами. Выбранную камеру можно перемещать и поворачивать стандартными манипуляторами. Контур показывает направление и границы кадра.
- **Следить за персонажем** создаёт основную следящую камеру. В настройках выберите героя, расстояние, высоту, ракурс вокруг него и плавность. Камера сопровождает интерполированное движение; при переносе камеры манипулятором сохраняет взгляд на герое. Режим можно переключить и у существующей камеры.
- **Посмотреть** показывает выбранную камеру, **По сценарию** возвращает автоматическое управление. Основная камера используется для «Общего плана». В действии **«Сменить план»** можно выбрать конкретную сохранённую камеру, включая следящую.

При обязательном осмотре предмета сценарий временно показывает предмет, затем возвращает следящую камеру. Явное действие переключения на другой план меняет камеру. Если персонаж скрыт или удалён, сохраняется запасной неподвижный кадр и появляется сообщение в настройках камеры. Камеры сохраняются отдельно по сабсценам, поддерживают Undo и экспорт проекта.

## Добавление и редактирование сабсцен

Откройте вкладку **«Сабсцены»** под 3D-кадром. Здесь три представления: **Редактор**, **Переходы**, **Карта**. Сабсцену также можно выбрать в левом списке или открыть кнопкой «Сабсцена» над инспектором.

- **«Добавить сабсцену»** (либо «+» в списке / «Создать → Сабсцена») открывает большую форму. Укажите название, выберите гостиную, сад или станцию, персонажей, окружение и первую реплику. Камера и предметы локации создаются автоматически.
- Новую сабсцену можно оставить отдельной или вставить после текущей реплики / конкретного ответа. При вставке прежнее продолжение сохраняется после новой сабсцены.
- В редакторе меняются название, заметка, локация, время, погода, состав персонажей и начальная реплика. Есть прямые кнопки сценария, редактирования 3D и камер. Изменения сохраняются автоматически, Ctrl+Z отменяет их.
- **«Переходы»** показывает входящие и исходящие связи и позволяет выбрать исходную реплику или ответ, найти его по тексту и назначить сабсцену назначения. Условия ответов сохраняются. При изменении начальной реплики можно перенаправить входы со старого начала; прямые переходы на другие реплики сохраняются.
- **«Дублировать»** копирует сценарий, локальные объекты и камеры с новыми ID. Внутренние связи переводятся на копию; внешние выходы и библиотечные шаблоны событий остаются общими. Размещения персонажей независимы, определения общих персонажей сохраняются.

Смена шаблона локации сохраняет сценарий и авторские объекты. Если событие или ожидание осталось привязано к недоступному предмету, вкладка «Ошибки» показывает проблему. Геометрия ограничена тремя шаблонами этого макета.


## Иерархия, навигация и общий таймлайн

- Стрелки у сабсцены, камер, объектов и точек сворачивают и разворачивают группы. Кнопки над деревом открывают или закрывают все группы; состояние сохраняется отдельно для каждой сабсцены. Двойной щелчок по объекту показывает его в кадре.
- У иерархии и инспектора есть кнопки сворачивания и разворота. Свёрнутая панель восстанавливается боковой кнопкой; меню **Окно** также открывает панели. Разворот сцены или рабочей области занимает всё доступное место. **Escape** возвращает обычную раскладку.
- Управление 3D по образцу Unity: **ЛКМ** — выбор, **Alt+ЛКМ** — орбита, **СКМ** — панорама, **ПКМ + WASD** — полёт, **Q/E при зажатой ПКМ** — вниз/вверх, **Shift** — ускорение, **колесо** — приближение. Вне полёта **W/E/R** выбирают перемещение/поворот/масштаб, **F** показывает выделенное в кадре.
- **Точки постановки** принадлежат своей сабсцене: у гостиной, сада и станции разные названия и привязки. Щелчок показывает связанный предмет; точки следуют за его перемещением. В инспекторе команда **Опорная точка** переносит выбранный объект к точке. Копии сабсцен получают независимые точки.
- Вкладка **Таймлайн** и **Окно → Общий таймлайн** открывают всю историю отдельно от редактора реплик. На графе показаны сабсцены, реальные выборы и условия, возвраты и концовки. Линейные реплики объединены во фрагменты; дополнительные входы в сабсцену сохраняются. Кнопки **Текущий узел** и **Вся история** управляют обзором. Щелчок по глобальной переменной показывает её зависимости; значения отражают текущий playtest.
- Список выбора сабсцены использует палитру редактора и поддерживает стрелки клавиатуры, Enter и Escape.

## Множественное выделение и расположение узлов

**Shift + щелчок** в сцене или иерархии добавляет объект к выделению; повторный щелчок с Shift убирает его. Выделение общее для обеих панелей. Манипулятор перемещает, вращает и масштабирует всю группу; **F** показывает все выбранные объекты. В групповом инспекторе можно применить относительную трансформацию, сбросить положение, создать дубликаты или удалить выделенное. Одна групповая операция отменяется одним **Ctrl+Z**.

Карточки во вкладке **Таймлайн**, включая глобальные переменные, можно перетаскивать за заголовок или текст. Соединения следуют за карточками, маршруты истории не меняются. Координаты сохраняются в проекте; **Ctrl+Z** отменяет перенос, **Автораскладка** возвращает автоматическое расположение. Двойной щелчок или кнопка **Сценарий** открывает исходную реплику.

## Настройки сайдчейна

Во вкладке **Звук → Сайдчейн проекта** доступны атака, восстановление (release) и снижение громкости в dB. Диапазоны: 0,05–10 секунд и 0–24 dB; 0 dB отключает приглушение. Значения по умолчанию — 0,6 с / 0,9 с / 4 dB. Изменения сразу применяются к прослушиванию и Playtest с плавным переходом и сохраняются вместе с проектом.

## Сохранение, новые проекты и шаблоны

- **Файл → Сохранить проект** (**Ctrl+S**) записывает JSON проекта. Если файл ещё не выбран, открывается системное окно сохранения. Последующие сохранения в этой сессии используют тот же файл. В браузерах без доступа к выбору файла проект передаётся в загрузки. Автосохранение рабочего проекта в браузере продолжает работать отдельно.
- **Сохранить проект как…** (**Ctrl+Shift+S**) создаёт копию под новым названием и делает её текущей после успешной записи. Отмена выбора файла оставляет текущий проект без изменений.
- **Новый пустой проект…** создаёт одну пустую сцену с камерой и начальной строкой сценария, без моделей и демонстрационных событий. В этом же окне можно выбрать сохранённый шаблон.
- **Записать проект как шаблон…** сохраняет независимый снимок в библиотеке этого браузера. **Экспортировать шаблон…** выгружает переносимый `.sacura-template.json`; его можно открыть через **Открыть проект…**, чтобы создать отдельный проект.
- **Восстановить предыдущий проект** возвращает резервную копию, сделанную перед созданием, открытием или сохранением копии проекта. Хранится один предыдущий проект.

Файлы проекта и шаблоны сохраняют сцены, объекты, события, параметры звука и ручное расположение узлов таймлайна. Доступ к выбранному файлу действует до перезагрузки страницы; после неё файл нужно выбрать снова.

## Ответы, переменные и логика на графе

ПКМ в потоке истории открывает добавление нод. В поиске введите имя существующей переменной: появятся «Получить» и «Задать». Раздел «Переменные проекта» также доступен без поиска; «Последний ответ игрока» предлагается только для чтения. Слева находится «Мой Blueprint»: список переменных с типами Boolean, Integer, Float и String. Кнопка «+» создаёт переменную; выбор строки открывает имя, тип и значение по умолчанию. Переименование обновляет ссылки во всём проекте. Get и Set компактны и используют общую настройку переменной; двойной щелчок по ноде открывает её свойства в списке. Перетащите строку на граф и выберите Get/Set; Ctrl (Cmd) создаёт Get сразу, Alt — Set. «Переменная · задать» меняет значение по ходу истории. Круглые пины передают данные, стрелки — выполнение.

Соедините выход переменной с входом A ноды `>=`, `<=` или `==`, задайте B, а результат подключите к условию `If · Если`. Вход со стрелкой запускает If; выходы «Да» и «Нет» ведут к продолжениям. Результат сравнения можно также подключить к круглому входу доступности конкретного ответа. Ноды «И» и «ИЛИ» объединяют условия.

Текст и результат ответа редактируются в ноде выбора. По умолчанию ответ ничего не возвращает. Можно выбрать текст, число или «Да / нет»; результат читает нода переменной «Последний ответ игрока». Старые условия при открытии превращаются в видимые ноды и провода.

Новые ноды создаются без соединений. В меню добавления операторы находятся в подменю «Сравнения». В ноде выбора каждый ответ содержит текст для игрока, вход доступности (Да / Нет) и выход продолжения; возвращаемое значение настраивается в раскрываемой строке. Оборванный переход можно убрать кнопкой, Alt-кликом по пину либо выделением карточки и Delete.

Переходы показывают иконку и первые слова целевой ноды вместо технического ID. Наведение или фокус на метке подсвечивает провод и обе ноды; нажатие открывает целевую ноду на графе. Такая же подсветка доступна при наведении на сам провод.

Провода Blueprint используют плавные кривые (для обратных переходов — скруглённый обход). Сплошная линия со стрелкой передаёт выполнение, пунктир с круглыми концами — значение; цвет значения соответствует типу. Подписи переходов в потоке истории появляются при подсветке, а контрастная подложка отделяет пересекающиеся провода.

## Загрузка своих звуков

Откройте **Ещё → Звук → Выбрать звуки** или перетащите аудиофайлы в блок загрузки. Поддерживаются WAV, MP3, OGG, M4A, AAC, FLAC и WebM, если формат декодируется браузером; до 100 МБ на файл. Выберите тип: музыка, озвучка или звуковой эффект. Перед сохранением файл проверяется декодером.

Загруженные звуки доступны для прослушивания, назначения реплике и выбора в звуковых действиях сценария. Они видны в проводнике и сохраняются внутри проекта; тип можно изменить в карточке звука. Аудио, импортированное через проводник, также попадает в медиатеку.

## Плоский nav mesh и простые коллизии

Откройте **Сабсцены → Редактор → Nav mesh и коллизии** и включите плоский nav mesh. Настройте центр X/Y/Z, ширину X, глубину Z и размер ячейки. Область принадлежит сабсцене, отображается зелёной плоскостью в редакторе и сохраняется в проекте.

Выберите объект в иерархии: **Инспектор → Простая коллизия · Box → Коллизия объекта**. Включите её у движущегося персонажа и нужных препятствий. По умолчанию все коллизии выключены, поэтому существующие проекты продолжают работать как раньше. Отключение коллизии позволяет проходить сквозь этот объект. Коллайдер автоматически охватывает видимую геометрию, включая загруженную модель; можно задать локальные размер и смещение вручную. Поворот и масштаб учитываются через мировой AABB, поэтому повёрнутые объекты могут иметь увеличенную область блокировки.

Действия **Движение** персонажей строят путь по горизонтальной плоскости с обходом включённых коллизий (A* и упрощение маршрута). Для других объектов проверяется прямое движение; при выключенном nav mesh персонажи также движутся прямо. Проверяется весь отрезок движения, чтобы объект не перескочил тонкую стену. Недоступная цель, отсутствие прохода или новое препятствие на пути останавливают действие с сообщением. Гравитация, лестницы, наклонные поверхности и физические импульсы не входят в эту простую модель.

**Показывать коллизии в редакторе** включает жёлтые контуры; в игре вспомогательные поверхности и контуры скрыты. Редакторские трансформации и свободная камера остаются свободными. Nav mesh и коллизии копируются вместе с объектами/сабсценой и сохраняются в JSON проекта.

## Интерактивные эпизоды и звук

В потоке истории создайте ноду «Взаимодействие» и откройте её инспектор. Отметьте обязательные интерактивные предметы: игрок может осматривать их в любом порядке, а выход «Дальше» сработает только после всех предметов. Для каждого предмета можно выбрать событие — например, изменить переменную, показать объект или открыть дверь. Повторный осмотр уже выполненного предмета не запускает это событие снова.

В том же инспекторе выберите персонажа и управление: WASD / стрелки, point & click или оба режима. Задайте скорость и дальность взаимодействия (0 — клик с любой дистанции). В игровом кадре нажмите на сцену, чтобы передать ей фокус; WASD двигает персонажа относительно камеры, E взаимодействует с ближайшим обязательным предметом. В point & click щелчок по полу задаёт путь, а щелчок по предмету подводит персонажа к нему и выполняет осмотр. Ручная ходьба отменяет текущий путь. Для ограничения ходьбы включите nav mesh в настройках сабсцены; препятствия учитываются при включённых коллизиях персонажа и декораций.

В новом стандартном шаблоне «Письма после дождя» после реплики «Здесь ничего не изменилось» находится эпизод `rain-explore`: Алиса ходит по гостиной и должна осмотреть письмо и шкатулку. Событие шкатулки выставляет `keepsakeFound`, осмотр письма — `letter`. Только после обоих осмотров продолжается диалог. Ранее сохранённые проекты сохраняют свой сценарий; для нового примера загрузите стандартный шаблон с главного экрана.

В инспекторе действия «Проиграть звук» или «Включить музыку» выберите аудиофайл. Над волновой формой показана огибающая громкости. Перетащите маркеры или задайте Fade in и Fade out в секундах; вход начинается с тишины, выход затихает к концу файла. Пауза и перемотка сохраняют соответствующую громкость; у зацикленной музыки выход применяется при её остановке.

В иерархии есть отдельные кнопки создания объекта, группы, точки постановки и звукового события. Кнопка «+» у группы создаёт объект сразу внутри неё. Перенос между группами доступен перетаскиванием и полем «Группа в иерархии» в инспекторе объекта; сбросьте группу для возврата в корень. Точка постановки имеет название и координаты и доступна в действии «Переместить». Через контекстное меню сцены объект или точку можно создать в месте щелчка. Звук создаётся как событие: назначьте файл и добавьте событие к нужной реплике.

«Положение, поворот, масштаб» открывает числовые параметры выбранного объекта. Для изменения мышью выберите один инструмент над сценой: W — сдвиг, E — поворот, R — масштаб; Q — выбор.


### Маркеры и завершение звука

Во вкладке «Ещё → Звук» маркеры конца задаются для файла нажатием на волну или точным временем в секундах. Для музыки доступны BPM, музыкальный размер и частота квантизации: от 1/16 ноты до 8 тактов. Сетка начинается с начала трека и продолжает музыкальный отсчёт при повторе, как сетка переходов в [FMOD Studio](https://fmod.com/docs/2.04/studio/glossary.html#quantization). BPM задаёт сетку и не изменяет скорость записи.

В действиях запуска есть Fade In и Fade Out с отдельными длительностями; пауза и остановка используют Fade Out, продолжение — Fade In. «Когда конец» управляет завершением при остановке, замене или закрытии события: конец текущего прохода файла, ближайший маркер/точка сетки, конец события или немедленное начало завершения. Если выбрано окончание вместе с событием, звук запускается без ожидания всего файла и закрывается после следующих групп; удерживаемое событие сохраняет его до остановки. Fade Out заканчивается на выбранной границе и сокращается, если времени осталось меньше. Без маркеров и включённой сетки завершение начинается сразу; после последнего маркера неповторяемый файл доигрывает до конца. Общая пауза сохраняет ожидающий переход, а «Остановить всё» и завершение предпросмотра немедленно очищают воспроизведение. Старые поля `fade` и длительности остановки читаются для совместимости, но не дублируются в интерфейсе.

### Язык интерфейса

В верхней панели редактора, на стартовом экране проектов и на экране входа
доступен список **Русский / English**. Переключение применяется сразу, включая
инспекторы, меню, подсказки, графы, аудиотеку и диагностику. Выбор сохраняется
на устройстве в `localStorage` (`sacura-language-v1`); по умолчанию используется русский.

Язык интерфейса не изменяет текст истории, названия проектов, объектов и ответов,
значения переменных или формат сохранения. Предпросмотр продолжает работать.
Общие функции локализации находятся в `src/i18n.js`, React-подписка — в
`src/i18n.jsx`, английский словарь — в `src/translations.en.json`.
Новый текст интерфейса оборачивается в `t()`; авторские подписи в списках
передаются через `literalLabel()`. Значения `<option>` остаются исходными.

## Общая обработка ввода

Откройте **Ещё → Ввод**. Устройство связывается с действием игрока через контекст, по схеме [Enhanced Input](https://dev.epicgames.com/documentation/unreal-engine/enhanced-input-in-unreal-engine): действие, контекст привязок, модификаторы и триггер. Проект хранит эти настройки в `input` и сохраняет их в JSON. Старые проекты получают стандартные привязки при открытии.

1. Создайте действие: кнопка, ось 1D или оси 2D. Выберите обработчик движка либо своё событие и триггер: нажатие, отпускание, удержание или каждый активный кадр.
2. В контексте добавьте привязки клавиатуры, указателя, геймпада, экранного элемента или внешнего источника. У клавиатуры используются физические коды (`KeyW`, `Space`), у геймпада — номера кнопок и осей с нуля. Кнопка «Записать клавишу» помогает назначить клавиатуру. Масштаб, инверсия и мёртвая зона применяются до объединения значений действия.
3. В инспекторе момента истории откройте **Контексты ввода** и включите нужные контексты. Автоматически диалог использует «Диалог», взаимодействие — «Ходьба и взаимодействие», системный контекст активен в обоих случаях. Контекст с большим приоритетом первым получает физический канал. «Перехватывать ввод» блокирует этот канал в нижних контекстах.
4. Для собственной механики назначьте событие и при необходимости переменную значения. Кнопка пишет Boolean, оси — числовые переменные (2D отдельно X и Y). Событие запускается на Triggered и может читать эти значения обычными средствами Blueprint. Повторный запуск того же действия ждёт окончания предыдущего экземпляра. Отпускание, отмена, переход истории, пауза и остановка очищают значения активного ввода.

В «Письмах после дождя» ходьба и осмотр используют общий слой: WASD / стрелки, левый стик / крестовина или экранный джойстик; E / A (Cross) / экранная кнопка осматривает предмет. Клик или касание сцены задаёт путь. В диалоге Enter, пробел, A (Cross) или экранная кнопка подтверждают выделенный ответ; стрелки / крестовина меняют ответ, пропуская недоступные. Start или Esc переключает паузу. Клавиатура и геймпад управляют кадром, когда он имеет фокус; нажмите на сцену. Удерживаемые кнопки не переносятся в новый контекст, а после потери фокуса геймпад должен вернуться в нейтральное положение.

Экранные кнопки и джойстик появляются автоматически при `(pointer: coarse)`. Режим **Всегда показывать · для проверки** позволяет проверить их на компьютере; одновременно поддерживаются ходьба и действие разными пальцами. Стандартный геймпад использует браузерный [Gamepad API](https://developer.mozilla.org/en-US/docs/Web/API/Gamepad_API/Using_the_Gamepad_API); браузер может обнаружить его только после нажатия кнопки. Нестандартным раскладкам назначьте собственные индексы. Монитор в рабочей области показывает обнаруженные геймпады и последнее действие.

### Подключение других устройств

`InputSystem` не зависит от DOM или вида устройства. `feed(device, control, value, {sourceId, payload})` принимает кнопку (0/1), ось (−1…1) или вектор `[x,y]`; `pulse` отправляет одно нажатие с полезными данными. `registerAdapter({id, start(emit), poll(emit, dt), stop})` подключает источник с событиями либо опросом и возвращает функцию отключения. Ошибка опроса отменяет удерживаемые значения этого источника; `adapterErrors` содержит ошибки. `dispose()` снимает подписки. Фазы доступны через `onAction`: `started`, `ongoing`, `triggered`, `completed`, `canceled`.

```js
const disconnect = controls.input.registerAdapter({
  id: 'custom-controller',
  start(emit) {
    return controller.subscribe(value => emit('external', 'aim', value));
  },
});
// Для контекста добавьте привязку external / aim к действию axis2d.
// Когда устройство отключается:
disconnect();
```

В браузере адаптер также может отправить `CustomEvent('sacura-input')` в `.scene-viewport` с `detail: {device:'external', control:'aim', value:[x,y], sourceId:'my-device'}`. Доступны `pulse:true` и `payload`. Передача по сети, WebHID, датчики телефона и другие транспортные протоколы подключаются отдельными адаптерами; готовые клавиатура, указатель, touch и gamepad встроены в `GameControls`. Адаптер принадлежит текущему запуску; при смене проекта или настроек его нужно подключить к новому экземпляру. Реальные аппаратные устройства следует дополнительно проверить на целевых браузерах: автоматические тесты используют симуляцию геймпада и источников ввода.
