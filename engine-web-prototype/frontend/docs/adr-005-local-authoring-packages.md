# ADR-005: локальный обмен авторскими заготовками, этап 5А

Статус: реализовано в рабочей ветке `feature/new-ui-fix`, 13 октября 2026.
Основание: [продуктовые требования](../../../docs/PRODUCT-REQUIREMENTS.md),
[ADR-004](adr-004-authored-mechanics.md),
[контракт пакета](../../../docs/AUTHORING-PACKAGE-V1.md).
Изменения до начала этапа сохранены. Commit, push, reset и смена ветки не выполнялись.

## Решение и совместимость

Продолжаем существующий UTF-8 контейнер `*.sacura-package.json`:
`format: sacura-authoring-package`, **formatVersion: 2**. Читатель поддерживает
также v1; версия авторского содержания `metadata.version` независима от версии
контейнера. Форматы целого проекта, `sacura-project-template`, location и игровой
HTML не меняют значения. ZIP, пакетный менеджер, магазин и облако не добавлены.

Оболочка содержит `metadata`, `compatibility`, `roots`, `inputs`, `content`,
`references`, `assets`. Корень — отдельный native Event, функция, авторская или
встроенная механика, либо полный стартовый шаблон. `roots.entries` перечисляет
публичные точки входа; `roots.parameters` сохраняет схемы публичных параметров.
Для механики можно включить несколько экземпляров одного определения/версии.
Определение переносится один раз; параметры экземпляров остаются раздельными.
Разные версии одного definition ID сохраняются как `id@version`.

Пакет хранит native Events, Action Groups, blueprintFunctions, правила и FSM,
схемы, начальные значения, descriptions, comments, node positions, links и
отдельные graph/timeline layouts. Импорт не компилирует их в закрытый результат.
Редактирование, Play и standalone используют прежние модели и исполнители.
Схемы проверяются через `valueSchemas`, `validateFunctions`, `validateRules`,
`validateAuthoredDefinition` и общий registry операций. Нового интерпретатора нет.

## Сбор зависимостей и внешние связи

`exportAuthoringPackage` строит замыкание вызовов Events/функций, библиотечных
действий и групп, widgets, custom signals, Input Actions, items/resources и
ссылок в аргументах, defaults, коллекциях, initialState и values. Очередь сбора
и visited set обрабатывают повторные и циклические вызовы. Цикл графа остаётся
редактируемыми данными; штатные лимиты выполнения функций не снимаются.

Отдельная механика не копирует сцены/объекты A. Прямые внешние связи превращаются
в автоматически найденные именованные типизированные inputs. Незаданный обязательный
объектный параметр определения также предлагается экспортером. В предпросмотре
автор может изменить имя и подсказку; принимающий автор выбирает свои объекты,
сцены, переменные и другие доступные записи. Совпадение имён не связывает записи;
одноимённые объекты в выборе различаются номером и сценой. Native и typed ссылка
на одну переменную используют один вход и правильный адаптер ключа/ID.

V1 сохраняет известные native ссылочные поля с `null` и JSON Pointer в
`references`. V2 дополнительно хранит типизированный транспортный маркер
`{kind: reference, type, mode: external, parameter: inputId}` с `typed: true`
в соответствующей записи `references`. Это транспортный вход пакета; аргументы
авторской функции, contextual self/source/target и tag selectors сохраняют свою
native семантику. ID проекта переводится на принимающий project.id.

Для известного старого signal callback `args.objectId` сравнение eq/ne с ID
существующего объекта адаптируется в экспортной копии: появляется обычный
именованный reference-параметр функции, а сравнение читает этот аргумент.
Это исправляет D1 у shipped `award-kill`, сохраняя source template без изменений.
Основание для адаптации — реальный legacy rule callback; массовой замены строк нет.
Произвольный текст, похожий на ID, по-прежнему не объявляется ссылкой.

Встроенные операции/доверенные возможности движка указываются версиями в
requirements; код ядра не попадает в пакет. Транзитивные ресурсы встраиваются
как base64 с SHA-256. glTF buffers/images собираются при экспорте; GLB должен
содержать свои ресурсы. Import восстанавливает native data URLs без fetch.
Посторонние сцены отдельной заготовки, server/auth данные и runtime world,
живые mechanicStates/таймеры/задачи не экспортируются. InitialState остаётся
авторским начальным значением, а не снимком текущего прохождения.

## Проверка, применение, отмена и происхождение

`readAuthoringPackage` проверяет оболочку, версии, схемы, требования к установленным
возможностям, public roots, уникальность записей, ссылки, native логические
определения, ресурсы и контрольные суммы до изменения проекта. Неизвестная
операция/версия даёт ошибку; исходный пакет остаётся доступным и неизменённым.
Не выполняются Actions, функции, JS, eval, Function, install hooks или dynamic
import из пакета. Отсутствующая возможность не скачивается автоматически.

Лимиты: 150 000 000 UTF-8 байтов контейнера, 128 файлов, суммарно 100 MiB
декодированных ресурсов, 4096 записей с ID, глубина 64 и бюджет 100 000 значений.
Недопустимые prototype keys и кодовые разделы отвергаются. Ресурсы ограничены
поддерживаемыми audio/image/glTF форматами; внешние ссылки ресурсов и URL в
inline styles запрещены. Для glTF/GLB проверяются структура/версия и внешние URI.
Архив не извлекается и пути назначения не используются. SHA-256 выявляет
повреждение, но не подписывает автора. JSON не является sandbox: полноценный
анализ декодируемых картинок/аудио не реализован, их читают браузерные декодеры.

`planPackageImport` работает с копиями пакета и проекта. Обязательные inputs
проверяются до создания плана. Native IDs, namespaced definition/signal IDs,
FSM states, links, references, override/layout keys переназначаются согласованно.
Публичные неизменённые engine Input Actions/contexts могут использоваться повторно;
пользовательское содержание всегда импортируется копией. Конфликт имени получает
суффикс и показывается в preview. Существующие записи не перезаписываются.
Конфликт уже подключённой камеры/инвентаря/HUD объясняется до применения.

План привязан к точному содержимому target: изменение проекта после preview
требует повторной проверки. `apply` возвращает целую копию; `undo` восстанавливает
исходный проект, если после применения он не изменён. В Editor используется
существующая атомарная `changeAssetLibrary` с проверкой места автосохранения
и одним элементом общей Undo history. Cancel/ошибка/позднее завершение чтения
закрытого окна не меняют проект. Import не запускает заготовку.

Повторный импорт узнаётся по `packageSource.id`, показывает отмену или новую
независимую копию. Обновлений/слияний нет. Каждый экспорт локального варианта
получает новый origin package ID; project IDs имеют отдельное назначение.
Источник, автор/лицензия/версия сохраняются в `metadata.sources` и `packageSource`,
включая происхождение импортированных зависимостей новой локальной механики.
Автор варианта указывается отдельно; редактирование не выдаётся за официальное
обновление исходника. Всё содержание локально и редактируемо офлайн.

Полный template настраивает пустой проект: startup scene, story policy, activation,
camera/controller/HUD и подготовленные compatibility reactions/bindings. Пустая
служебная сцена mechanics-only проекта используется для первой сцены story template,
без добавления фиктивной реплики. Повторное чтение не дублирует мигрированные реакции.
Если в target уже есть сюжет, механики или переменные, полный шаблон отклоняется
с предложением перенести отдельную механику/Event/функцию. Произвольное слияние
глобальной конфигурации двух полных игр не входит в этот этап.

## Проверки и воспроизведение

Исходный `npm test`: **489/489**, исходных падающих тестов не было.
Новые проверки: 16 headless и 3 DOM-теста; D1 characterization переведён в
regression. Весь набор после изменений: **508/508** (0 ошибок/пропусков/отмен).
`npm run build:player`, `npm run build`, `git diff --check` выполнены отдельно.
Предупреждения сборки о директивах React Flow и размере чанка остаются.

Проверены A → B → C с изменением условия и новым native действием в B;
раздельные экземпляры/версии; повторный import, одинаковые имена, Undo/Cancel;
циклические функции, ресурс, typed defaults/initial links, обязательный пустой
слот, unknown schema/op, повреждённый hash, код, excessive structures и stale plan;
каждый node/link/comment после законного remap; trusted turns как requirement;
реальные point-and-click/shooter templates и отсутствие двойного начисления kills.

В браузере запущены Play-стенд с реальным GamePlayer/исходным runtime и экспортированный
HTML со встроенным собранным player-runtime: попытка открытия без ключа оставляет
false; получить ключ → открыть меняет результат на true. Импортированные HUD и
PNG отображаются, standalone не требует A. Подготовка HTML использует штатный
`preparePlayableGame`, а не макет. Полный проход A/B/C через окна основного Editor
и браузерное редактирование графа в этом этапе не повторялись: модельные правки
проверены headless, preview/bindings/copy/Undo — DOM-тестами настоящего PackageExchange.

Ручной путь: «Игровые механики» → «Обмен заготовками» → выбрать export или import;
export: заполнить автора/лицензию → подготовить → проверить найденные связи → скачать;
import: файл → выбрать обязательные привязки → проверить → добавить → обычный редактор/Play.
Отдельный Event — «Передать отдельное событие»; функция — «Функции и графы» →
«Передать функцию». Для template создайте пустой проект.

Из frontend выполните:

```sh
npm test
npm run build:player
npm run build
node scripts/check-package-player.mjs --serve
```

Последний скрипт создаёт A/B пакеты, project C и фактический `player.html` в
системном temp-каталоге `sacura-package-check`. Откройте
`http://127.0.0.1:4179/play.html` и `http://127.0.0.1:4179/player.html`, нажмите
«Начать игру», «Открыть дверь», «Получить ключ», «Открыть дверь».
Браузерная проверка выполнялась через localhost; открытие file:// отклонено
политикой браузерного инструмента (разрешены HTTP/HTTPS), поэтому запуск этим
протоколом не подтверждён. Режим запрета сети не проверялся. Код и ресурсы
standalone встроены в один HTML.

## Изменённые файлы этапа и границы

- `src/mechanicPackages.js`: совместимое замыкание, v2, проверка, remap, origins,
  атомарный plan/undo, template configuration.
- `src/packageReferences.js` (новый): адаптеры native/typed transport, лимиты,
  совместные схемы/валидация и узкий legacy callback adapter.
- `src/PackageExchange.jsx`: export preview, имена/подсказки inputs, bindings,
  repeat/cancel, поздние async результаты, объяснение полного template.
- `src/valueSchemas.js`: deferred зависимая схема для существующего выражения
  аргумента; после вычисления runtime по-прежнему проверяет фактический тип.
- `src/gameExport.js`: выделен штатный `preparePlayableGame` для проверки
  того же HTML, который скачивает existing export.
- `tests/package-exchange.test.js`, `tests/package-ui.test.js` (новые);
  `tests/gameplay-characterization.test.js`: regression D1 вместо known defect.
- `tests/fixtures/packageDoor.js`, `tests/fixtures/packagePlayer.js`,
  `scripts/check-package-player.mjs` (новые): native A/B/C и browser стенд.
- Этот ADR, `docs/gameplay-unification.md`, `docs/adr-004-authored-mechanics.md`,
  корневые `docs/AUTHORING-PACKAGE-V1.md`, `docs/MECHANICS-IMPLEMENTATION.md`:
  actual format/границы/проверки вместо обещания переноса после UI.

Простота: найденные входы предлагаются автоматически, выбираются по именам;
ID, JSON и установка кода не нужны. Переносимость: logic/resource/graph/origin
round trip, изоляция копий и отказы проверены. Универсальность: UI-only/no hero,
turns и native story templates идут через те же definitions/functions/rules.
Физика, рендер, планировщик и identity объектов не заменены. Формат ограничен
установленными native возможностями; arbitrary code packages, магазин,
официальные обновления и merge содержимого не реализованы.
