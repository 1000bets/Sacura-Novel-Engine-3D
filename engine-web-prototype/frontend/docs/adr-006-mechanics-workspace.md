# ADR-006: рабочая область универсальных механик

Дата: 13 октября 2026 года. Статус: реализовано в текущей рабочей копии
`feature/new-ui-fix`. Область — этап интерфейса после [5А](adr-005-local-authoring-packages.md).
Основание: [продуктовые требования](../../../docs/PRODUCT-REQUIREMENTS.md).

## Решение и реальные связи

`GameplayWorkspace` выбирает владельца, показывает установленные механики и
редактирует одну выбранную запись. Библиотека строится из `mechanicDefinitions`,
реестра доверенных возможностей и определений проекта. Импортированные native
заготовки представлены проекцией существующих `gameplay.mechanics` с происхождением:
повторное применение проходит через тот же пакетный планировщик, без второго
каталога, хранилища объектов или исполнителя. Поиск понимает русские названия,
описания и ключевые слова; «счетчик» и «счётчик» совпадают.

| Задача | Потребитель и существующий контракт |
| --- | --- |
| Добавление | `addMechanic` / `addMechanicInstance`, обычные `project.objects`, object/scene/project scope |
| Параметры | `MechanicFields`, `SchemaFields`, схемы общего реестра; у авторской механики только `exposed` |
| Правило | `RuleFields`, `RuleActions`, versioned rule model, безопасные выражения, существующие Events и функции |
| Выполнение | прежние `PreviewRuntime`, `GameSession`, `RuleRuntime`, Event/Action Groups; планирование не менялось |
| Общая логика | `AuthoredMechanicEditor`, `BlueprintFunctionWorkspace`, исходные графы сохраняются |
| Локальный обмен | `PackageExchange` → `exportAuthoringPackage` / `readAuthoringPackage` / `planPackageImport` |
| Применение и отмена | `Editor.changeAssetLibrary` → один `mutate`; история и новая ветвь redo, до 20 снимков |
| Представление | `mechanicsPresentation`, `referencePresentation`; эти помощники не импортируются runtime |

Обычная форма и раскрытая логика изменяют те же записи. Панель общего определения
показывает число затронутых экземпляров; основная форма обозначена «Настройки
экземпляра». «Создать копию» авторской механики копирует определение и зависимости;
«Копия с общим определением» доступна в дополнительных свойствах. У native механики
копирование использует реальный экспорт/проверку/переназначение ID/импорт 5А.
Сведения об источнике сохраняются в обеих ветвях.

Объекты выбираются по названиям, одинаковые названия различаются сценой и номером.
Переменные показывают владельца и тип. Аргументы функции получаются из сигнатуры;
операции — из общих схем. Выбор значений контекста фильтруется по типу, счётчиков —
по владельцу. Удалённая ссылка остаётся в данных и отображается как ошибка.
Сложное выражение не стирается при открытии простой формы: его можно открыть
через существующую функцию. Отсутствующее определение также сохраняется.

Контекстная кнопка «Добавить механику» добавлена в инспектор объекта. Она выбирает
этот объект и открывает библиотеку. Глобальная кнопка механик открывает рабочую
область целиком; рядом со сценой она тоже работает. Стрелки / Home / End перемещают
фокус по установленным механикам, Escape закрывает обмен или возвращает из
библиотеки к форме и кнопке добавления. Undo/redo доступны кнопками и Ctrl/⌘ Z,
Ctrl/⌘ Shift Z, Ctrl Y; ввод текста сохраняет обычную отмену поля.

Обучение шутеру находится у карточки соответствующего шаблона на `ProjectHome`.
В общей навигации механик раздела «Как собрать FPS» нет. Новые поля и оформление
используют существующие темы и токены; магазина и новой авторизации нет.

## Исправления, необходимые для настоящего обмена

На старте 508/508 тестов проходили. При проверке нового пути обнаружились ошибки,
которые исходный набор не покрывал:

1. Внешний native переход к диалогу ошибочно считался удалённым при экспортной
   проверке. `packageReferences` проверяет его на приватном представлении с
   временной репликой для слота. Она не попадает в пакет, проект или выполнение.
2. Экспорт native предмета не собирал его инвентарь. Сборщик теперь включает
   настройки владельца и начальные значения **только включённых предметов**;
   посторонние предметы и их начальные значения не копируются. Инвентарь объявлен
   требуемой возможностью движка.
3. Повторное применение требует явного выбора «Использовать инвентарь принимающего
   проекта». Четвёртый аргумент `planPackageImport` содержит выбранную пользователем
   опцию; сам пакет её не навязывает. Вместимость и настройки получателя сохраняются,
   начальные количества новых предметов добавляются. Конфликт экипировки или нехватка
   вместимости отменяет весь план. По умолчанию конфликт остаётся ошибкой.
4. Play без истории показывал текст выбранной реплики и вечный индикатор подготовки.
   `Editor` теперь показывает подготовку только пока runtime не готов (или сообщает
   ошибку), передаёт HUD текст действительной реплики и отображает имя сцены при
   отсутствии реплики. `GameHUD` не рисует пустую плашку задачи.

Это адаптация существующего формата и потребителей, без нового формата, произвольного
кода при импорте, изменения семантики событий или жанровых веток runtime.

## Воспроизведение из пустого проекта

1. Создать пустой проект. Через «Создать → Объект → Интерактивный предмет» добавить
   объект. Его инспектор содержит «Добавить механику».
2. В «Игровые механики» выбрать «Весь проект», нажать «Добавить механику», найти
   «счётчик», добавить и назвать «Получено писем». Начальное значение — 0.
3. Выбрать созданный объект в «Добавить к», добавить «Предмет для подбора».
   Получатель — проект. Инвентарь подключается как зависимость подбора.
4. У предмета нажать «Изменить логику → Добавить реакцию». Получится
   «Когда: Получен предмет», «У источника: Этот объект», «Если: Всегда».
5. В «Сделать» добавить операцию «Изменить счётчик». Выбрать тип владельца «Проект»,
   свой проект и «Получено писем»; «Добавить» — 1.
6. Добавить второе действие «Продолжить историю». В «Создать диалог» ввести
   «Письмо получено. Спасибо!» и нажать «Добавить диалог». Реплика и её связь с
   действием создаются одной отменяемой правкой.
7. В «Свойства проекта → Запуск проекта» выбрать «Сразу механики, без реплик».
   Вернуться к предмету через установленный список. Нажать «Проверить», затем
   «Запустить». Щелчок по предмету увеличивает счётчик и открывает диалог.
8. Остановить Play, у предмета нажать «Экспортировать», указать название, автора
   и лицензию, подготовить экспорт. Внешние связи предложены автоматически;
   файл `*.sacura-package.json` скачивается обычной кнопкой.
9. В другом проекте создать свой предмет и диалог. «Импортировать» → выбрать файл,
   свой объект и свою реплику → «Проверить импорт» → «Добавить в проект».
   Если инвентарь уже подключён, выбрать его использование. Настроить запуск
   без истории; щелчок запускает **диалог принимающего проекта**. Undo убирает
   весь импорт, Redo восстанавливает его. Повторный импорт показывает происхождение
   и предлагает отдельную копию, не обновляя существующее содержимое.

Ни один из этих шагов не требует JSON, кода, ID или строкового пути свойства.
Для нескольких подбираемых предметов выбираются разные объекты-владельцы.

## Три продуктовых принципа и ограничения

Простота: основной путь проходит через библиотеку и короткую форму; раскрытая
логика использует те же данные, что готовая механика. Переносимость: проверены
экспорт/preview/собственные привязки/локальная копия/Undo, а A → B → C и сохранность
графа остаются регрессионными тестами. Универсальность: цепочка работает без героя,
HP и оружия, вызывает native историю через общий runtime и операции.

Большое правило требует вертикальной прокрутки; разворот рабочей области доступен
одной кнопкой. Произвольный сложный граф не преобразуется в простую форму, его узлы
сохраняются и редактируются существующим графовым редактором. Совместное использование
инвентаря сейчас поддержано для проекта; конфликт инвентарей конкретного объекта
или сцены требует другого владельца и диагностируется до применения.

Этот этап проверен автоматикой и авторским прогоном в одном браузере, а не
исследованием с пользователями. Все темы, мобильные размеры, screen reader,
несколько браузеров, звук и отказ браузерного хранилища не проверялись в этом
прогоне. Standalone здесь проверен сборкой и headless regression из 5А; новый
ручной прогон браузерного standalone не проводился. Магазин и слияние обновлений
не входят в этап.
