# Sacura Novel Engine 3D

## Обязательные требования продукта

[Требования Sacura](../docs/PRODUCT-REQUIREMENTS.md) имеют приоритет над прежними архитектурными предложениями и жанровыми примерами в этом руководстве. Каждое изменение проверяется по [трём принципам](../docs/CHANGE-CHECKLIST.md): простота, переносимость и редактируемость, универсальность. Герой, HP и оружие не обязательны для любой игры.

Перенос отдельных Events, функций, механик и шаблонов описан в [контракте пакета v1](../docs/AUTHORING-PACKAGE-V1.md). Локальный обмен реализован: исходники компонентов переносятся в [пакете v3](../docs/AUTHORING-PACKAGE-V3.md), v1/v2 остаются совместимыми. Текущий путь автора и фактические проверки — в [COMPONENT-ACCEPTANCE.md](../docs/COMPONENT-ACCEPTANCE.md).

## О прототипе

Движок для визуальных новелл в 3D и историй с point-and-click. Здесь реплика может запускать целую сцену: персонаж подходит к окну, камера меняет план, начинается дождь, а музыка уходит тише под голос.

Сейчас в репозитории — рабочий прототип редактора на React и Three.js. В нём уже можно редактировать историю, расставлять объекты, собирать события и проходить получившиеся сцены. Будущий C++-движок пока не реализован.

## Что в нём интересного

**Сценарий связан с постановкой.** У каждой реплики есть события до текста, во время него и после. Например, сначала открыть дверь и подвести персонажа, затем показать диалог, а после ответа переключить камеру. Всё это редактируется в одном рабочем пространстве рядом с 3D-сценой.

**Действия можно запускать вместе или по очереди.** Дождь и музыка начинаются одновременно, затем меняется камера и появляется реплика. Из действий собираются группы и события, которые можно сохранить в библиотеку и использовать повторно. У отдельного размещения события можно менять параметры, сохраняя общий шаблон.

**Развилки видны на графе.** Реплики и ответы соединяются мышью. У ответов есть условия и конкретная точка назначения. Общий таймлайн показывает переходы между сценами, возвраты и концовки — удобно, когда история уже не помещается в голове. Там же можно посмотреть, где используются глобальные переменные.

**Камера участвует в диалоге.** Автоматическая постановка чередует средние и крупные планы говорящего с общими планами и добавляет небольшой плавный проезд. Можно поставить свои камеры и выбрать нужный ракурс вручную: авторская камера имеет приоритет.

**Предметы могут двигать сюжет.** История умеет ждать клика по объекту в 3D. В демо есть письмо и билет: предметы связаны с прохождением и доступностью ответов. Так можно смешивать разговоры с осмотром локации.

**Сцену можно править прямо в редакторе.** Объекты перемещаются, вращаются и масштабируются манипулятором. Есть множественное выделение, дублирование, точки постановки и отмена изменений. Сцену можно скопировать вместе с её сценарием, объектами и камерами.

**Звук и окружение тоже входят в события.** Музыка, озвучка, плавные изменения громкости, дождь, снег, туман, свет и время суток настраиваются рядом с действиями персонажей. Под голос музыка плавно приглушается; силу приглушения и скорость перехода можно менять для проекта.

**Результат можно сразу проиграть.** Запуск работает с начала истории или с выбранной реплики. Отдельное событие можно опробовать без прохождения сюжета. Во вкладке «Активные» видно, что выполняется, а в «Ошибках» — найденные конфликты и проблемные связи с переходом к ним.

## Структура

- `frontend/` — редактор React и Three.js, браузерные тесты и сборка.
- `server/` — API, SQLite, S3 и серверные тесты.
- `deploy/` — Caddy, MinIO, инструкции размещения и проверка контейнеров.
- `ci/` — проверки GitHub Actions.
- `compose*.yaml`, `.env.example` — конфигурация контейнерного запуска.

Все команды ниже выполняются из этой папки.

## Запуск

Понадобятся Node.js и npm. Из папки `engine-web-prototype`:

```sh
cd frontend
npm install
npm run dev
```

Откройте адрес, который напечатает Vite в терминале — обычно это http://127.0.0.1:5173/.

## Что попробовать первым

В демо есть гостиная, сад и станция, диалоги с озвучкой, развилки и несколько концовок.

1. Запустите историю с начала: посмотрите, как реплики связаны с камерой, дождём и звуком.
2. Остановите проигрывание и откройте «До реплики» у первой строки. Переключите группу между «Вместе» и «По очереди», затем сравните результат.
3. Найдите развилку «Что сказать Бобу?» и выберите «Спрятать письмо». Пройдите до станции и попробуйте взаимодействие с билетом.
4. Выберите объект «Письмо» → компонент «Запомнить осмотр» → «Открыть общую реализацию». Измените правило StoryFlag и сравните доступность чтения в следующем запуске. Для своих типов используйте «Создать → Компонент → Код / Граф».
5. Посмотрите общий таймлайн: на нём видны маршруты истории, условия переходов и концовки.

## Свой проект

Через меню «Файл» можно создать пустой проект, открыть существующий или начать с сохранённого шаблона. Проект сохраняется в JSON; шаблоны тоже можно экспортировать и передавать отдельно.

Автосохранение хранит рабочую копию в браузере. Чтобы оставить проект отдельным файлом, используйте **Ctrl+S**, а для новой копии — **Ctrl+Shift+S**. **Ctrl+Z** отменяет изменения.

## Текущее состояние

Доступны пять редактируемых учебных проектов: шутер, две двери, новелла, UI-кликер и «Письма после дождя». Кодовые/графовые компоненты, Behavior Tree и Events выполняются общим JavaScript runtime в Play и автономном HTML. Движение, физика, raycast, рендер и звук остаются системными примитивами. Проверка графа находит ошибки данных, но не доказывает поведение любой истории; ограничения сохранений и авторского SDK перечислены в COMPONENT-ACCEPTANCE.md.

Редактор использует React, Three.js, React Flow и Vite. Код находится в `frontend`, основной экран — `src/Editor.jsx`. Команды из этой папки:

```sh
npm test        # проверки сценария, событий, камер, звука и сохранений
npm run build  # сборка браузерного прототипа
```

Подробности управления — в [руководстве редактора](frontend/README.md). Устройство прототипа и его ограничения — в [заметках по дизайну](frontend/DESIGN-NOTES.md).

## Серверное хранилище и публикация

Добавлен контейнерный стек: Nginx, Node.js API, SQLite для JSON проектов и S3/MinIO для GLB/OBJ. В контейнерной версии доступны серверное автосохранение, список проектов, защита паролем и переносимый экспорт JSON. Для сайта предусмотрен Caddy с автоматическим HTTPS.

Запуск, подключение внешнего S3, резервирование и размещение на VPS описаны в [руководстве размещения](deploy/README.md). Скопируйте `.env.example` в `.env`, заполните случайный S3-пароль и выполните `docker compose up -d --build`.

### Компоненты объектов

Выберите объект в иерархии. В инспекторе показаны его именованные подключения,
параметры и ссылки. **Открыть общую реализацию** переводит к настоящему коду
или графу в центре. **Создать → Компонент** создаёт собственный тип без пресета.
Раздел «Игровые механики» содержит библиотеку общих определений и открытые
реализации. Для отдельной копии исходника используйте **Создать независимый вариант**.
[Пять учебных проектов и упражнения](../docs/COMPONENT-TEMPLATES.md).

Приведённые ниже результаты прежних этапов относятся к старому интерфейсу и
его совместимости, а не заменяют текущий путь создания компонента.

Проверка редизайна от 18 октября 2026 года:

- Простота: в браузере добавлен таймер, время изменено с 2 до 5 секунд;
  оба изменения отменены. UI-тест проверяет выбор карточки счётчика,
  добавление к сцене и настройку названия и начального значения без JSON и ID.
  Проверены поиск без результатов, выбор владельца и свёрнутые дополнительные настройки.
- Переносимость и редактируемость: прошли тесты предпросмотра импорта,
  обязательных привязок, отмены без изменения проекта и независимого редактирования копии.
  Автотест «Дверь с ключом» A → B → C проверяет перенос, изменение и выполнение
  логики без исходного проекта. Формат пакета и модель данных не менялись.
- Универсальность: счётчик добавляется и редактируется в проекте без героя,
  здоровья и оружия; существующие тесты общей модели механик проходят.
  Runtime, физика и рендер не менялись.
- Проверки: 80 тестов механик, авторских определений, пакетов, UI и локализации;
  production-сборка. В браузере проверены русский и английский поиск, перенос
  окна в инспектор шириной 280 px без горизонтального переполнения.
- Ограничения: ручная приёмка полного A → B → C в браузере в рамках редизайна
  не повторялась. Отдельная проверка редактора функций приведена ниже.


### Редактор «Функции и графы»

При открытии графа каталог механик скрывается. Выбор функции, создание и экспорт
выбранной функции находятся сверху. «Добавить узел» открывает поиск с короткими
описаниями. Настройки справа разделены на вкладки «Узел» и «Функция»;
панель можно скрыть. Выбор узла и переходы между узлами доступны через списки,
поэтому протягивать связи мышью не обязательно. «Упорядочить» меняет только
координаты; авторские координаты сохраняются при обычном редактировании.
При переносе окна граф автоматически вписывается в новую область.

Проверка изменения от 18 октября 2026 года:

- Простота: в браузере проверены создание функции, поиск и добавление развилки,
  перетаскивание узла и отмена. Все проверочные изменения отменены. Автотест
  собирает ветку «да / нет» через списки и проверяет оба результата исполнения;
  проверены клавиатура, возврат фокуса и защита используемой функции от удаления.
- Переносимость и редактируемость: UI-тест импортирует функцию из A в B,
  меняет значение через редактор, сохраняет координаты и комментарий,
  экспортирует вариант в C и проверяет его исполнение, авторство источника
  и независимость от A. Существующие проверки авторских пакетов и двери
  A → B → C проходят. Формат пакета и исполнение не менялись.
- Универсальность: ветвление выполняется в пустом проекте без героя, здоровья
  и оружия, через общую модель функций. Новые жанровые сущности не добавлялись;
  runtime, физика и рендер не менялись.
- Проверки: 85 тестов функций, механик, авторских пакетов, UI и локализации;
  production-сборка. В браузере проверены перенос в инспектор 280 px,
  автоматический масштаб, отсутствие горизонтального переполнения,
  скрытие настроек, темы Classic Dark и Sakura Night.
- Ограничения: полный ручной цикл A → B → C в браузере не повторялся.
  Сложные выражения, массивы и структуры сохраняют прежние расширенные формы;
  их отдельный редизайн не входит в это изменение.
