# JavaScript игровых механик

19 октября 2026. Реализовано по указанию пользователя: заменить Blueprint
редактором JavaScript **только в игровых механиках**.

## Работа в редакторе

Открытие составной механики показывает её JavaScript в CodeMirror 6.
«Добавить скрипт» создаёт локальную функцию и механику с реакцией на старт игры.
В настройках доступны параметры функции, состояние экземпляра, входной сигнал,
фильтры и политика повторного запуска. Значения экземпляра открываются отдельно.

«Скомпилировать» или Ctrl+S / ⌘S проверяет синтаксис JavaScript, зависимости
игрового API и совместимость с исполняющей VM. Проверка не запускает код.
При успехе новая версия становится исполняемой; при ошибке показываются строка
и столбец, а предыдущая рабочая версия сохраняется. Черновик сохраняется
автоматически. Применение — при следующем запуске игры; редактирование во время
игры отключено. Горячая замена выполняющегося скрипта не реализована.

Существующие программы преобразуются в JavaScript при открытии без изменения
проекта. После первой успешной компиляции для игровых вызовов используется
скрипт. Обратного преобразования JavaScript в Blueprint нет. Сохранённый граф
остаётся совместимой реализацией для других редакторов; изменение скрипта
не меняет исполнение того же ID вне контекста игровой механики.

## Вход и игровой API

```js
async function main({ args, global, state, engine }) {
  const reward = args.amount * 3;
  await engine.operation("sacura.resource.add", {
    owner: args.owner,
    resource: args.counter,
    amount: reward,
  });
  console.log("Начислено:", reward);
}
```

`main(ctx)` — обязательное объявление функции. Поддерживаются обычный JavaScript,
функции, замыкания, циклы, массивы, объекты, Promise и async/await.

- `args` — параметры с текущими значениями экземпляра/вызова.
- `global` — переменные проекта; чтение и запись используют действующие данные
  сеанса и проверку типов. Вложенные поля и массивы также записываются через API.
- `state` — состояние экземпляра с объявленной схемой, отдельное от локальных
  переменных JavaScript. Обычный `let` существует только в текущем вызове.
- `engine.operation(id, parameters, version = 1)` — установленная операция.
- `engine.call("Имя функции", args)` — вызов другой функции.
- `engine.event("Имя Event", options)` — существующий Event.
- `engine.ref("Имя объекта / ресурса")` — типизированная переносимая ссылка.
- `engine.wait(seconds, timeSource = "game")`, `engine.signal(id, payload)`,
  `engine.waitSignal(id, timeout)` — время и сигналы существующего runtime.
- `engine.start`, `engine.join`, `engine.cancel` — управляемые фоновые работы;
  `engine.timeout`, `engine.sequence/selector` — таймаут и задачи поведения.
- `console.log/warn/error` — диагностические записи выполнения функции.

У обработчика сигнала необязательная `condition(ctx)` проверяется на снимке
сигнала в режиме чтения. `main` запускается при истинном результате;
`otherwise(ctx)`, если объявлена, — при ложном. Сгенерированная реализация
сохраняет локальные вычисления и результаты условия для тела реакции.

Имена зависимостей в `engine.operation/call/start/event/ref/signal/waitSignal`
задаются строковыми литералами, чтобы экспорт мог собрать и переназначить связи.
Значения аргументов вычисляются обычным JavaScript. Импорты npm/JS-модулей,
доступ к DOM, Node API и сети не предоставляются.

## Исполнение и перенос

Код исполняется в QuickJS WebAssembly, отдельно от JavaScript редактора.
Вызов имеет отдельную VM, ограничение памяти 16 MiB, стека 256 KiB,
прерывание длительных вычислений (100 мс между ожиданиями игрового API)
и ограничение продолжений Promise. Остановка игры/экземпляра отменяет
ожидающий скрипт. Низкоуровневые движение, физика и рендер не перенесены в JS.

В `functions[].mechanicScript` сохраняются черновик, скомпилированный текст,
версия и явные зависимости. Пакет объявляет `mechanic.javascript@1`.
Ссылки на функции, Events, сигналы, ресурсы и переменные переносятся через
таблицу привязок; строки исходника не переписываются по совпадению ID.
Предпросмотр показывает наличие JavaScript. Импорт не выполняет код и всегда
снимает `approved`; включение происходит после просмотра и успешной компиляции
в редакторе принимающего проекта. Копии и повторный экспорт сохраняют исходник.

## Фактическая проверка

- **Простота:** через браузер открыт существующий скрипт награды, изменён множитель,
  выполнена компиляция через ⌘S. Игра начислила 3 монеты по новой формуле.
  Через интерфейс создан новый скрипт; синтаксическая ошибка показала строку 2.
  CodeMirror проверен с номерами строк и контрастной подсветкой.
- **Переносимость и редактируемость:** автоматический A → B → C с вложенной
  функцией и переназначением переменной. После импорта код отключён; после
  компиляции выполняется. Изменение B не меняет A, изменение C не меняет B.
  Подтверждены сохранение/загрузка проекта и сохранение рабочей версии при ошибке.
- **Универсальность:** проверки проходят на проекте без героя, HP, оружия
  и физики; JS вызывает существующие общие операции, Events и функции.
  Отдельная проверка подтверждает прежнее исполнение функции вне механик.
- **Игра:** экспортированный HTML содержит VM и исполняет скрипт без редактора;
  в браузере проверено приращение счётчика с 18 до 23 по формуле ×5.
- **Проверки:** 672 теста; production/editor и player собираются.
  Новый сценарий «Дверь с ключом» A → B → C вручную в этом изменении не проходился;
  его полная приёмка не объявляется выполненной.

Ограничения: применение при следующем запуске, без горячей замены; нет внешних
модулей и отладчика с точками останова. Переносится объявленная через игровой API
таблица зависимостей, а не произвольные ID, записанные вручную в строках кода.
Эти ограничения не относятся к редакторам истории, Events, UI или ввода.

## Поля инспектора прямо в коде — SerializeField

Добавлено 20 октября 2026. Объявите обычную переменную на верхнем уровне
скрипта и скомпилируйте его:

```js
const amount = SerializeField(5, { label: "Награда", min: 0 });
const allowed = SerializeField(true, { label: "Начислять" });

async function main({ args, global, engine }) {
  if (allowed) global.result += amount * 3;
  // amount и args.amount — одно значение данного вызова.
  await engine.operation("sacura.game.message", {
    message: "Результат: " + global.result
  });
}
```

В этом примере сюжетная числовая переменная `result` заранее создана в проекте.
Само объявление полей не требует переменных истории, героя или боевых систем.

- Имя поля берётся из имени JS-переменной; в инспекторе показывается `label`.
  После успешной компиляции поле доступно у подключённых экземпляров, включая
  уже существующие. Новый тип не добавляется в движковый enum/каталог.
- Тип выводится из default: число, boolean, строка, структура или коллекция.
  Второй необязательный аргумент — существующая schema: `type`, `label`,
  `min/max`, `enum/options`, `items`, `properties` и другие поддержанные свойства.
  Default задаётся первым аргументом, повторный `default` во втором запрещён.
- Для целого числа: `const count = SerializeField(2, {type: "integer"});`.
  Для вектора: `const offset = SerializeField([0, 1, 0], {type: "vector", size: 3});`.
  Для ссылки: `const target = SerializeField(undefined, {type: "reference",
  referenceType: "object", label: "Цель"});`. Объект выбирается у экземпляра;
  обязательную ссылку нужно заполнить перед Play. Конкретные ID мира внутри
  объявления запрещены; экспорт переносит настроенные ссылки через входы пакета.
- Значение переменной — снимок аргумента при входе в вызов. `false`, `0` и пустая
  строка сохраняются как явные значения. Вызовы разных экземпляров независимы.
  `let` допустим, но присваивание такой локальной переменной не меняет настройки
  проекта и не является сохраняемым прогрессом. Для прогресса используйте
  объявленное состояние `ctx.state`, как и раньше.
- Тип/default объявленного поля редактируются в коде. «Настройки скрипта»
  показывают эти поля только для чтения; значения экземпляра редактируются в
  его инспекторе. Старые ручные параметры остаются доступны и не удаляются при
  добавлении SerializeField. Переименование переменной означает удаление поля
  и создание нового; автоматического переноса его прежних значений нет.
- При компиляции обновляются прежние `functions[].parameters`, схемы определения
  и открытые поля экземпляра. Обработчики этого определения передают новые поля
  в корневую функцию; явные настройки аргументов сохраняются. Другие вызывающие
  скрипты используют обычные аргументы `engine.call("Имя", { amount: 7 })`.

Поддерживается только прямой инициализатор `const/let name = SerializeField(...)`
на верхнем уровне. C#-атрибуты `[SerializeField]`, декораторы `@SerializeField`,
объявления внутри методов/классов, вычисляемые defaults и схемы не поддержаны.
Вычисления пишутся в `main`. Разбор метаданных статический: компиляция и импорт
не выполняют gameplay-код. Ошибка показывает исходную строку/столбец и сохраняет
предыдущую рабочую версию по контракту обычных JS-механик.

Авторский текст хранится без замены в `source` и `compiledSource`; схемы —
производный индекс. Перед исполнением SDK раскрывает только инициализаторы
SerializeField в чтение нормализованных аргументов данного вызова. Номера строк
сохраняются; столбец runtime-ошибки на строке с раскрытым объявлением может
отличаться. Разбор кэшируется, отдельного хранилища параметров или нового
native API нет. Применение исходника — при следующем запуске, без hot reload.

Пакет остаётся **v3** с `mechanic.javascript@1` и дополнительно объявляет
**`mechanic.serialized-fields@1`**. Требование учитывает также черновики;
импорт не включает код автоматически. V1/V2 и их запреты не ослаблены.

проекта и запуск HTML-игры. Значение экземпляра 7 при default=5 дало 14;
