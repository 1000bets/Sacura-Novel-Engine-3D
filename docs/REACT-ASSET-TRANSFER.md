# Native React asset integration

The React Inspector keeps its existing expandable reflected-component presentation. NativeAssetsContext supplies registered asset identities, navigation and previews to shared AssetReferenceField/AssetThumbnail components. Fields expose Open, Reveal and Clear without coupling type validation to captions. Typed AssetKey and paired string properties use component.setAsset.

EditorCore GenerateAssetPreview contains the CPU thumbnail generator previously embedded in Qt AssetThumbnails. Qt bindings remain in Editor; Electron assets.thumbnail schedules owned registry snapshots on JobSystem. The native-thumbnail protocol serves only session-scoped registered identities. Preview misses use type cards; no source-side files are generated.

Content Browser cards use the same images and support external reveal requests. Static mesh placement, instance materials and physics delegate to the existing EditorCore commands. Asset document editing delegates to StaticMeshDocument/MaterialEditingSession. Explicit save and revision checks protect drafts. Closing/switching projects includes dirty asset documents.

The separate placement palette reads published EditorAction descriptors. Its Point/Spot/Directional light presets use the same C++ action implementations as Qt. Third-party registered actions appear without adding React mutation code. Primitive meshes are discovered from Engine BasicShapes.

Viewport diagnostic selection is forwarded to the native controller and retained across frames.

Static mesh and material activation opens a resizable native Electron window, reused by project/asset/subasset identity. File/Edit/View actions and keyboard shortcuts use the same document commands as the toolbar. Each asset window owns a separate native host, isolated Scene and GPU frame stream; it shares Content on disk with the main project without replacing or mutating the main edit world. This intentionally favors isolation over the lower memory cost of a shared multi-surface renderer. Main close/project switching checks child drafts and supports Save/Discard/Cancel. Main retains a bounded pool of Electron imports keyed by native resource/extent. The prototype waits for the consumer GL blit to finish before its consumed-frame ACK releases a producer slot, complementing the existing producer fence; resizing/minimizing must not recycle a resource still consumed by Chromium. Visibility/focus restoration republishes viewport bounds. Renderer IPC is scoped to the owning window, allowed commands and asset identity; thumbnail protocol access is scoped to the owning native session.

Preview camera orbit, pan, flight and focus use the native controller. Mesh material assignments and compiled material drafts update the GPU preview. Surface and PostProcess previews support sphere, cube and plane; PostProcess drafts are bound to the preview camera rather than to a mesh. UserInterface materials use the existing GPU MaterialImageRequest renderer through an Engine/RenderThread command API, with bounded 512px image snapshots. Animated UI materials refresh through the same draft-preview path. No native graphics types cross the bridge. Collision elements can be selected from the panel or viewport, shown as wireframes and edited with translation/rotation/scale gizmos. A completed drag invokes the same validated assetDocument.execute edit operation with its starting document revision, so Undo restores the entire gesture atomically. Escape/lost capture cancels an uncommitted gesture. Triangle-mesh collision displays source triangle edges and supports position/rotation; its document schema has no independent scale.

Material Instance displays the complete resolved parameter catalog, including inherited scalar, integer, boolean, vector, color, texture and static-switch values. Overrides retain their native {type,value} representation and can be reset to inheritance. Base materials expose shading/blending, render flags, alpha cutoff, bounds expansion, postprocess stage, shader source, parameter definitions and texture sampler metadata. Native validation remains authoritative for parent cycles, types, read-only resources and unsupported source/domain changes. Failed compilation keeps the last successful preview and reports its diagnostic. Source edits, material assignments and instance overrides remain drafts until explicit Save.

Saved metadata changes invalidate CPU asset caches during registry refresh; material/texture changes retain the existing SceneAssetResolver file-watch path. Thumbnails include metadata modification time in their browser version. No generated previews are authored beside Content.
