# Пользовательские JavaScript-функции

20 октября 2026. Дополнение к скриптам механик по запросу пользователя.

В графе истории: «Добавить ноду» → «Скриптинг» → «Создать JavaScript-функцию…».
Создаются локальная функция и её вызов на графе; открывается вкладка «Скриптинг».
В меню, открытом с круглого пина, тип новой функции соответствует пину,
а новая связь добавляется автоматически. Существующие функции выбираются
в том же разделе, с проверкой совместимости типов.

```js
function main({ args, global, engine }) {
  return args.value * 3;
}
```

Параметры, названия для автора, defaults и тип результата доступны рядом с кодом.
Параметры вызова задаются прямо на ноде или через провода. «Открыть скрипт»
и двойной щелчок возвращают к реализации. Скомпилировать — кнопка или Ctrl+S / ⌘S.
Черновик сохраняется локально. Ошибка показывает строку и сохраняет предыдущий
исполняемый текст. Изменения применяются в следующем запуске игры.

Функция вычисляет значение синхронно и не меняет игровое состояние. `global`
содержит снимок используемых переменных для чтения. `engine.call("Имя", args)`
вызывает другую такую функцию. Имена зависимостей — строковые литералы;
экспорт переносит их через явные таблицы привязок, не заменяя строки исходника.
Обычные вызовы функций в Events/графах используют тот же исходник и результат.

Исполнение использует существующий QuickJS, отдельную VM, 16 MiB памяти,
256 KiB стека и общий лимит 100 мс для цепочки вложенных вызовов. Цикл вызовов
диагностируется. DOM, сеть, Node API и изменение переменных из функции отсутствуют.
Для действий с эффектами и ожиданиями остаётся редактор JavaScript механик.
Низкоуровневые движение, физика и рендер не изменены.

`functions[].functionScript` хранит исходник, последнюю скомпилированную версию,
зависимости и разрешение исполнения. Остальная сигнатура функции сохраняет
общую модель. Вызов в истории — `kind: "script-function"`, `functionId`,
локальные `args` и провода `inputs["arg:имя"]`. Данные вызовов независимы.
Кнопка копирования создаёт независимый редактируемый исходник.

Отдельный экспорт/импорт доступен во вкладке «Скриптинг». Это существующий
пакет v3 с новым контрактом SDK v2 (`execution: "gameplay-and-functions"`)
и обязательным `function.javascript@1`; прежний контракт SDK v1
`gameplay-only` сохраняет прежнее значение. Старый редактор отклонит новый
контракт, вместо запуска его с иной семантикой. Пакеты v1/v2 не разрешают код.
Предпросмотр объявляет наличие JavaScript; импорт не исполняет исходник
и сбрасывает разрешение. Для включения нужна успешная компиляция локальной копии.

Проверено автоматически: исполнение аргументов и проводов, ветвление истории
без героя и механик, чтение текущих переменных, запрет записи в исходные данные,
контроль типа результата, предел вычислений, рекурсия, Promise и runtime-ошибки,
переименование портов и сохранение проекта. A → B → C проверяет вложенную функцию,
привязку переменной, происхождение и независимые изменения; после импорта
исполнение отключено. UI-тесты проверяют создание, правку, компиляцию, копию,
добавление вызова и сохранение рабочей версии при ошибке. Через браузер проверены
создание из меню графа, редактор и успешная компиляция.

Ограничения: функции значений синхронны; async/await, эффекты, ожидания и запись
игрового состояния выполняются в механиках. Горячей замены, внешних модулей
и отладчика с точками останова нет. Переименование параметра сохраняет аргументы
и провода, но обращения `args.имя` внутри авторского JS меняет сам автор.
Ручная приёмка «Дверь с ключом» A → B → C этим изменением не объявляется выполненной.
