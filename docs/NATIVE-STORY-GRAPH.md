# Нативный редактор графа истории

Реализован профиль `sakura.story` v1: **Реплика**, **Выбор**, **Действие** и
**Концовка**. Это редактируемые документы C++ runtime. Дополнительные типы
JS-графа, Events, функции, провода значений и переменные этим этапом не перенесены.

## Работа в редакторе

1. Откройте Story двойным щелчком в Content Browser или кнопкой «Открыть».
   Новая история создаётся через «Создать → Историю…» внутри Content проекта.
   В пустой рабочей области «+ Нода» предложит создать документ.
2. Добавляйте узлы через «+ Нода» или контекстное меню холста. Перетаскивайте
   карточки за свободную область. Ctrl позволяет выбрать несколько узлов.
3. Тяните выход справа на вход слева. У выбора свой выход для каждого ответа.
   Повторное соединение того же выхода заменяет переход. Выделенная связь
   удаляется Delete или через контекстное меню.
4. Выбранный узел настраивается в инспекторе. Для реплики доступны говорящий,
   текст и продолжение; для выбора — вопрос, ответы и их переходы; для действий —
   последовательность Wait/MoveTo/CameraCut/NavigateTo, время, объекты сцены,
   положение и поворот, где они применимы. Ссылки выбираются по названиям,
   а не вводом ID. Начало истории задаётся инспектором или контекстным меню.
5. Ctrl+S сохраняет активный документ. Undo/Redo доступны в меню «Правка», на
   панели графа и стандартными сочетаниями Qt. Незавершённый ввод текста/чисел
   попадает в команду перед сохранением или отменой.
6. «Запуск» проверяет текущий черновик в PlayWorld без неявного сохранения.
   На время Play редактирование и история команд заблокированы. Колесо
   прокручивает граф, Ctrl+колесо меняет масштаб; «Вся история» показывает узлы.

## Ответственность слоёв

- **Engine** владеет StoryDocumentIO и StoryRuntime. Qt-граф ему неизвестен.
- **EditorCore / StoryGraphDocument** владеет документом, атомарными именованными
  правками, снимками для undo/redo, dirty state, сохранением и проверкой внешних
  изменений. Для работы не нужны QApplication и конкретный игровой мир.
- **EditorCore / StoryAssetCreation** создаёт файл и `.meta` в Game Content,
  проверяет конфликты и откатывает созданные файлы при неудаче регистрации.
- **UI / Adapters / StoryGraphController** связывает команды и независимые
  представления данных с графом и инспектором. Изменения сцен остаются в
  SceneWorkspace; история графа не может отменить команду сцены.
- **UI / Views** владеет виджетами, портами, жестами и формами. Перестроение
  графических объектов откладывается до завершения текущего UI-события.
- **UI / Styles** и `resources/ui/styles` содержат отрисовку, шрифты, геометрию,
  иконки и QSS. Цвета Classic/Sakura сверяются с `themes.js`.

## Данные и сохранение

Основной формат остаётся `sakura.story` v1. Совместимые дополнения:

- `editor.version = 1`, `editor.positions[nodeId] = {x, y}` — координаты графа
  в логических единицах, не зависящих от DPI и масштаба просмотра;
- необязательный строковый `id` у ответа и действия — идентичность записи
  при удалении/изменении строк и восстановлении истории;
- пустая история — `nodes: []`, `startNodeId: ""`; при запуске она завершена.

Старые документы читаются без перезаписи. Идентичность старых вложенных записей
восстанавливается детерминированно, новые записи получают GUID. Runtime не
использует координаты редактора. Runtime ObjectHandle и GPU-ссылки не сохраняются.
Дополнительные поля документа, узлов и вложенных записей сохраняются при правках.
Удаление ноды убирает входящие ссылки и её координаты; undo возвращает их вместе
с прежними ID и началом истории. Сохранённый снимок отличен от текущего: отмена
до него снимает dirty, ветка после undo удаляет прежнее redo.

Сохранение использует общий AtomicFileWriter. Изменившийся на диске документ
не перезаписывается: черновик остаётся в памяти; повторное открытие предлагает
сохранить/отбросить/отменить. Открытие с ошибкой сохраняет предыдущий документ
и его историю. Ресурс отслеживается по AssetId после перемещения в Content;
Engine mount доступен только для чтения. Создание истории не меняет `.project`:
назначение стартовой истории для отдельного Player остаётся настройкой проекта.

## Проверки и границы

Локальные C++/Qt-тесты находятся в игнорируемом `Root/Tests` по AGENTS.md.
Проверки охватывают команды/dirty/ветвление undo, сохранение и повторное чтение
runtime, удаление связей, вложенные ID и дополнительные поля, конфликт внешнего
файла, Game/Engine mounts и перемещение ресурса. Qt-тесты отправляют события
в тестовые виджеты: добавление через меню, жест соединения, Delete, перенос ноды,
инспектор, pending-ввод, undo/redo и блокировка Play. Тест скрытой оболочки
проверяет маршрутизацию истории, Ctrl+S и запуск несохранённого черновика в PlayWorld.
Computer Use не используется. QWidget-снимок показывает UI, но не GPU swapchain.

Простота: обычные действия доступны через меню, порты и подписанные поля;
JSON, ID и пути свойств не нужны. Переносимость и редактируемость: сохранение
истории, позиций, идентичностей и дополнительных данных проверяется повторным
открытием; формат авторских пакетов и приёмка механики A → B → C здесь не
реализованы и не объявляются выполненными. Универсальность: история может
исполняться без героя/HP/оружия; объекты требуются только действиям, использующим
сцену. Физика и рендер не заменяются графом.

Ограничения: поддерживаются четыре нативных вида нод и переходы исполнения;
нет JS Event/function/value-нод, буфера обмена нод, экспорта авторских пакетов,
сохранения масштаба просмотра, запуска с выбранной реплики и слияния внешних
правок. Соединения допускают циклы. Проверка перед Play обходит достижимый поток
и не требует завершать неиспользуемые ветки.

Фактическая проверка 22.10.2026: Debug-сборки `SakuraEditor` и `SakuraPlayer`
успешны; локальный CTest — **21/21**, включая `Editor.Story.Graph.UI` и
`Editor.Story.Graph.Shell`. Проверка палитр и границы стилей — **52 токена**.
Запуск `SakuraEditor --project … --screenshot-editor …` на D3D12 завершился
успешно; лог подтвердил ширины 210 / 938 / 280 при окне 1440 и отсутствие
утечек, учитываемых MemorySubsystem. Снимок UI проверен визуально. В данной
среде агрегат собирался с `--parallel 1`, чтобы тестовые цели не копировали
ресурсы одновременно в общую директорию. В render-логе остаются прежние
предупреждения HLSL/Diligent; GPU-изображение этим снимком не проверяется.
