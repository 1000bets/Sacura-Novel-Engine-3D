# Python-компоненты нативного редактора

Исходники лежат в `Scripts` пользовательского проекта. Они импортируются при
открытии проекта; после изменения кода нужен новый процесс редактора.
Встроенный редактор кода и вкладка «Игровые механики» в этот этап не входят.

Пример готового компонента — `Samples/SampleProject/Scripts/health.py`.
Откройте SampleProject, выберите объект в иерархии, раскройте «Добавить компонент»,
выберите `game.Health` и нажмите «Добавить». Тот же тип доступен в меню компонентов.
Настройте Initial Health и Armor в Inspector. Добавление, удаление и изменение
полей используют обычную историю отмены; настройки сохраняются в сцене.

`@register_class` задаёт стабильный идентификатор типа. `field()` объявляет
настройки с типом, значением по умолчанию, названием и числовым диапазоном.
Каждое добавление создаёт отдельный экземпляр с собственными значениями.

Версия схемы в объявлении класса не задаётся:

```python
@register_class(type_id="game.Health")
class Health(ScriptComponent):
    InitialHealth = field(float, default=100.0)
```

У C++-макросов классов, структур и перечислений параметр версии также отсутствует.
Служебная версия существующего JSON остаётся совместимой; это изменение API
объявлений не добавляет автоматическое преобразование старых полей.

`OnCreate` вызывается при начале игры компонента, `OnUpdate(DeltaTime)` — при
обновлении, `OnDestroy` — при завершении игры или удалении играющего компонента.
В EditWorld эти callbacks не запускаются. Старые имена `on_create`, `on_update`,
`on_destroy` поддерживаются, но PascalCase имеет приоритет. Конструктор `__init__`
для зарегистрированного компонента не используется и не допускается.

Общего callback `OnInput` нет. Подключение к Enhanced Input должно выполняться
явными подписками на действие и фазу через делегаты, с освобождением при
завершении жизни владельца или сессии. Этот API дорабатывается в задаче Input;
автоматическая рассылка ввода всем компонентам удалена.

Обычные атрибуты Python, например `CurrentHealth`, принадлежат текущему запуску.
Они не сериализуются автоматически. Настройки `field()` клонируются в PlayWorld;
изменение PlayWorld не меняет исходную сцену. Это не система сохранения прогресса.

`@method(Parameters={"Amount": float}, Result=float)` публикует метод для внешнего
вызова. Аргументы обязательны и именованы; отсутствие Result означает отсутствие
возвращаемого значения. Допустимы типы общей рефлексии. Корутин, генераторов,
вариативных аргументов и значений аргументов по умолчанию на этом этапе нет.
Обычные внутренние методы декоратор не требуют.

Из другого компонента можно найти подключения своего владельца и вызвать метод:

```python
Components = self.owner.GetComponents("game.Health")
for Component in Components:
    RemainingHealth = Component.Invoke("TakeDamage", Amount=10.0)
```

Ссылка поля типа `engine.ObjectHandle` на конкретный компонент также предоставляет
`Invoke`. Вызов разрешён только у активного Python-экземпляра. Неверные аргументы,
неопубликованный метод и удалённый получатель дают диагностическую ошибку.
Ошибка внутри метода не откатывает уже выполненные им изменения.

Narrative-ноды реализованы отдельными Python-классами со своим контрактом выполнения.
Прямые вызовы опубликованных методов и собственные ноды доступны в графе истории.
Объявление пинов, ожидания и ветвление описаны в [Python Narrative](PYTHON-NARRATIVE.md).

Простота проверена добавлением типа через список Inspector без ручного ID.
Исходник остаётся редактируемым Python-файлом, настройки используют существующий
формат сцены. Отдельный импорт/экспорт пакетов компонентов и перенос A → B → C
в нативном редакторе этим этапом не реализованы и не объявляются проверенными.
Механизм регистрации и вызовов не зависит от Health или жанра проекта.
