# Редактор материалов

Двойной щелчок по Material или Material Instance в Content Browser открывает
отдельное окно. Повторная активация поднимает то же окно с тем же черновиком.
Материал создаётся существующим меню Content Browser; область Surface,
PostProcess или UserInterface выбирается при создании.

Во вкладке «Параметры» доступны числовые значения, цвета и векторы,
переключатели, выбор текстуры из Content, освещение и смешивание. Материал
позволяет добавлять и удалять определения параметров, менять их отображаемые
имена, группы и настройки выборки текстур. Имя параметра используется в HLSL;
новый параметр начинает влиять на изображение после его использования в коде.
Экземпляр меняет родителя и значения; «Наследовать» удаляет локальное
переопределение. Отсутствующая текстура и явно пустая текстура различаются.

Окно и диалог определения параметра используют общий EditorStyle и палитру
Sakura. Фон, панели, вкладки, поля, кнопки и прокрутка берутся из общих QSS;
цвета подсветки HLSL используют токены той же палитры. У списка параметров
есть прокрутка, поля не сжимаются по высоте до обрезанного текста.

Вкладка HLSL редактирует тот же исходник, который использует runtime.
Ввод объединяется до паузы в 500 мс и передаётся документу перед действиями.
«Отменить» и «Повторить» используют историю документа. Engine Content и
исходник экземпляра доступны только для чтения. Game Material, ссылающийся
на исходник Engine, также не разрешает менять этот HLSL.

«Проверить и показать» фиксирует текущий черновик, разрешает зависимости в
JobSystem и запрашивает компиляцию у Engine на Render Thread. Главное окно
не ждёт компиляцию. Предпросмотр показывает сферу, куб или плоскость; для
PostProcess и UserInterface используется соответствующий проход движка.
Ошибки выводятся под редактором. Неуспешная или устаревшая проверка не заменяет
последний успешный предпросмотр. Изменения родителей и include объединяются
перед обновлением предпросмотра и не создают локальных overrides.

«Сохранить» явно записывает общий ресурс и HLSL через MaterialDocument.
Предпросмотр черновика не назначает материал объектам сцены. Сохранённый
ресурс используется существующим механизмом горячего обновления движка;
общие изменения затрагивают всех его потребителей. Внешняя правка собственного
файла блокирует сохранение. «Перечитать» с подтверждением отбрасывает локальные
изменения. Перезапись внешней версии без перечитывания через этот UI не
предлагается. При закрытии, включая Escape и закрытие главного окна,
доступны сохранение, отказ от изменений и отмена закрытия.

## Консоль и MCP

Команда `material_document` использует ту же сессию, что окно. `path` —
виртуальный путь Material/MaterialInstance; `operation`: `inspect`,
`document`, `source`, `undo`, `redo`, `reload`, `save`, `compile`.
`inspect` возвращает документ, HLSL, dirty/read-only/conflict, ревизию,
состояние подготовки, ревизию предпросмотра и диагностику. Все остальные
операции требуют актуальный `revision`, полученный через `inspect`.
`document` принимает целый проверяемый объект `document`, `source` — строку
`source`. `reload` является явным отбрасыванием локального черновика.
Операции изменения запрещены во время Play. Вызов открывает или поднимает
соответствующее окно; отдельного файлового пути записи для MCP нет.

## Границы реализации

EditorCore MaterialEditingSession владеет документом, валидацией и ревизиями
запросов. Worker захватывает копию реестра и данные черновика, без QWidget или
сцены. Окно Editor отвечает за поля, диалоги и наблюдение за зависимостями.
Engine/RHI сохраняют владение компиляцией и GPU-ресурсами. Предложение
MaterialEditorUiContract.md описывает также ещё не реализованный расширенный
API; оно не является перечнем поддерживаемых команд.

Смена области существующего материала, переназначение исходника,
структурированная навигация по строкам ошибок и отдельная операция Apply
не реализованы. Новая область выбирается при создании материала.
Пользовательские определения параметров задаются полями; произвольный JSON
для обычной настройки не нужен. Для новой шейдерной логики нужен HLSL.
Наблюдение за удалённой или перемещённой зависимостью может требовать
перечитывания материала. Управление геометрией предпросмотра, фокусом и
диалогами остаётся только в UI; редактирование и компиляция доступны MCP.

## Проверки продукта

Простота: создать материал → открыть → изменить параметр → проверить →
сохранить; обычная настройка не требует JSON или GUID. Текстуры и родитель
выбираются из реестра. Универсальность: те же документы и окно используются
для Surface, PostProcess и UserInterface, без жанровых сущностей.

Редактируемость: сохраняются исходный HLSL, определения, значения и наследование,
GUID остаются прежними. Экспорт зависимостей отдельным авторским пакетом этим
изменением не добавлен. Приёмка переноса A → B → C этим тестом не подтверждается.

Локальный нативный тест `Editor.Material.Editing` проверяет ревизии, историю,
валидацию без частичных изменений, конфликт сохранения, read-only, наследование,
MCP, GPU-предпросмотр трёх областей, ошибочный HLSL и отмену закрытия. Артефакт
интерфейса: `build/MaterialEditorNative.png`; компактное окно —
`build/MaterialEditorCompact.png`, исходный код —
`build/MaterialEditorSourceNative.png`. Debug-сборка Editor и интеграционный
тест с D3D12 прошли 23 октября 2026 года; снимки проверены визуально.
