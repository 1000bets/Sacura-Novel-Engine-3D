# Авторский пакет v3: редактируемые исходники SDK

19 октября 2026. Реализованный контракт. Формат файла остаётся
`*.sacura-package.json`; `format: sacura-authoring-package`.
[Требования продукта](PRODUCT-REQUIREMENTS.md),
[данные v1/v2](AUTHORING-PACKAGE-V1.md),
[SDK](COMPONENT-SDK.md), [runtime и интерфейс](COMPONENT-AUTHORING.md).

## Разделение версий и доверия

- Экспорт данных без JS и без нового корня `component` по-прежнему пишет v2.
  Импорт поддерживает прежние пакеты данных v1/v2 и их null/typed привязки.
- Экспорт с `component.code`, `functions[].mechanicScript` или корнем
  `component` пишет **formatVersion: 3** с обязательным `sourceContract` ниже.
- У v1/v2 сохранён запрет ключей `script/scripts/javascript/code/install/
  postinstall`, опасных ключей прототипа и несериализуемых значений. Они не
  приобретают разрешение на исполняемые исходники через переименование поля.
  `component.code` и `mechanicScript` в старом контейнере отвергаются явно.
- V3 допускает исходники только в известных ресурсах `content.logicResources`
  вида `component.code` и в прежних `content.functions[].mechanicScript`.
  Запрет установочных полей/скриптов и регистрации native API сохраняется.
  `source` не переименован ради обхода старого валидатора: новый контейнер
  явно объявляет его назначение и проверяет связанную декларацию/индекс.

```json
{
  "format": "sacura-authoring-package",
  "formatVersion": 3,
  "sourceContract": {
    "version": 1,
    "language": "javascript",
    "runtime": "sacura-sdk",
    "execution": "gameplay-only"
  }
}
```

Это фрагмент оболочки; metadata, compatibility, roots, inputs, content,
references и assets обязательны по прежнему контракту. Semver
`metadata.version`, версия компонента, версия state и версия ресурса независимы
от `formatVersion`. Неизвестный контракт/версия блокирует импорт.

При чтении/preview статически разбирается исходник, сопоставляются сигнатуры
методов, схемы parameters/state/references, lifecycle и пользовательские сигналы
с индексом. Проверяются ссылки, операции, заявленные требования API, ресурсные
hashes и лимиты. Gameplay-код и hooks не исполняются. Синтаксическая ошибка
называет виртуальный путь, строку/столбец, если они предоставлены парсером.
Импорт выставляет `approved: false`, `status: review`; открытие кода не включает
его. Для запуска автор сохраняет локальный компонент, прежний JS-скрипт
компилирует в его редакторе. Отдельные trusted native extensions не входят в пакет.

Локальный промежуточный экспорт JS в v2 прежних этапов не является пакетом
данных v2: теперь он требует повторного экспорта из проекта в v3. Молчаливого
повышения доверия при загрузке такого файла нет. Прежний ключевой запрет виден
в [проверенной реализации](https://github.com/1000bets/Sacura-Novel-Engine-3D/blob/fea9d479071d2ee8f01ec080a7d633eeb8458d0e/engine-web-prototype/frontend/src/mechanicPackages.js).

## Определения и подключения

В центре реализации **Экспортировать компонент** открывает выбор определений
и начальных подключений. По умолчанию выбран только тип, без фиктивного owner
или экземпляра. Дополнительные компоненты и подключения выбираются флажками.
Предпросмотр отдельно показывает исходники, графы/деревья, определения,
подключения, Events, функции и файлы ресурсов. Поля ввода имеют редактируемые
понятные имена и подсказки; ручной JSON/ID для переноса не требуется.

Для `roots.kind: component`:

- `entries` — непустой список JSON Pointers в
  `/content/gameplay/mechanicDefinitions/N`;
- `instances` — выбранные корневые подключения в
  `/content/gameplay/mechanics/N`, допустим пустой список;
- `parameters` — object schema оболочки; параметры каждого типа остаются
  в его определении, не объединяются в неоднозначный общий каталог.

Один общий исходник/definition включается один раз. Выбранные экземпляры
содержат только авторские `scope/name/values/references/fieldBindings/enabled`.
Текущий runtime-state, HP, native открытость двери, lifecycle handles и задачи
из Play не читаются при экспорте. Вложенные экземпляры, необходимые по ссылкам,
тоже включаются транзитивно. Поэтому связанный HUD с вызовом второго счётчика
может потребовать второй экземпляр даже при одном выбранном корне; это видно
в составе и обязательных входах до скачивания.

Программный API того же экспортёра:

```js
await exportAuthoringPackage(project, definition, {
  kind: 'component', name: 'Посылки', author: 'Автор', license: 'CC0',
  version: '1.0.0',
  definitionIds: [definition.id, behaviorDefinition.id],
  instanceIds: [warehouseCounter.id, archiveCounter.id]
});
```

Прежние roots event/function/mechanic/template, включая несколько подключений
одного типа через includeInstances, остаются доступными. JS-зависимость любого
такого root автоматически выбирает v3, данные продолжают экспортироваться в v2.

## Замыкание, ссылки, применение

Сбор идёт по определениям, ресурсам реализации, method functions, графовым
узлам, Behavior Trees, SDK dependency tables, сигналам, Events, widget/input
вызовам и типизированным ссылкам. Native операции не копируются: передаются
`operation.*` / `command.*` requirements и версии установленных engine modules.
V3 сверяет заявленные требования с используемыми вызовами. Весь движок и
остальной исходный проект не включаются.

Внешние object/scene/variable/story связи превращаются в inputs. Внутренние
авторские компоненты/ресурсы копируются с собственными зависимостями; их owner
выбирается в принимающем проекте. Две связи разных дверей остаются разными.
Перенос использует типы и ID, display names не определяют адресата.
Method keys локальны для типа и сохраняются; IDs определений, функций,
экземпляров, сигналов, ресурсов и узлов переназначаются согласованно.
Произвольные строки JS не переписываются. Связи SDK хранятся отдельно от текста.

План строится на отдельной копии проекта и не изменяет оригинал. До применения
показываются состав, required slots, требования, повторный origin и конфликты.
Конфликты имён/путей разрешаются суффиксами и перечисляются в preview;
существующие записи не перезаписываются. Сохранение импортированного кода
также сохраняет уникальность имени в библиотеке. Изменение проекта после
preview делает план недействительным. Apply возвращает целую копию или ошибку;
Undo доступен через редактор. Закрытие/ошибка/незавершённое чтение после отмены
ничего не добавляют.

Metadata содержит автора, лицензию, версию и origins. При импорте эти сведения
сохраняются на локальных записях. Новый вариант имеет свежий package ID и
сохраняет происхождение всех включённых зависимостей в `metadata.sources`.
Это копирование, не удалённая связь с A/B. Подпись автора, автоматический merge
обновлений, магазин и облачная синхронизация не реализованы.

## Фактические проверки

`component-portability.test.js`: определение без экземпляра; набор 3 определений,
4 подключений, 2 JS-исходников, 1 Behavior Tree, Event, сигнал и PNG; A → B → C
с изменением формулы и переменных `result → scoreB → scoreC`; shared source
включён один раз, A неизменён. Реальное выполнение C и собранного standalone
проекта: два независимых счётчика дают 12/30. Проверяются ошибки source,
недостающая зависимость/API, старые data v1/v2, отмена/устаревший план,
review gate, происхождение, save/load двери, счётчиков и native таймера.

`package-ui.test.js`: выбор типа/подключений без fake instance, readonly preview
кода, обязательные bindings, атомарный import/Undo и отмена позднего чтения.
Составной браузерный обмен целиком вручную A → B → C не заявляется: создание,
импорт, правка и повторный экспорт выполнены автоматическими моделями и UI
тестами; фактическое выполнение полученного C проверено в редакторе и отдельном
HTML браузера. В живом UI также открыты исходники C и скачан повторный v3-пакет
с метаданными авторов A/B.

## SDK-поля обычных JS-механик — 20 октября 2026

Пакет со скриптом, использующим `SerializeField`, дополнительно требует
`mechanic.serialized-fields@1` в `compatibility.requiredCapabilities`.
Сохраняется прежний `mechanic.javascript@1`; версия оболочки остаётся v3.
Проверка выявляет отсутствие этого требования и неподдержанную версию до
применения. Учитываются опубликованный текст и черновик, в том числе ошибочный.

Исходник хранится в прежнем `functions[].mechanicScript`, сигнатура полей — в
производных `functions[].parameters` и схеме определения механики. Независимой
редактируемой копии схемы нет: компиляция обновляет индекс, валидатор проверяет
его по опубликованному исходнику. Импорт не запускает объявления или установку;
код требует просмотра и компиляции локальной копии. Точные ссылки на объекты
задаются в значениях экземпляра и проходят прежнее переназначение входов,
а не зашиваются в литералы SerializeField. Автоматически проверены изменение
A → B → C, независимость A, перенос ссылки на переименованный объект и
атомарный отказ на отсутствующее/неподдержанное требование SDK.

Данные V1/V2, политика запрещённых ключей и установка доверенных native-модулей
не меняются. [API полей](MECHANIC-JAVASCRIPT.md#поля-инспектора-прямо-в-коде--serializefield).
