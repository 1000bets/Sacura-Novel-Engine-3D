# Готовый Editor и экспорт игры для Windows

Editor и Player собираются разработчиком движка один раз. Пользователю готового
комплекта не нужны исходники движка, CMake, Visual Studio и установленный Python.
В первой версии распространяется обычная папка, без установщика и архивов ресурсов.

## Использование готового комплекта

Запустите `Bin/SakuraEditor.exe`, создайте или откройте проект. Перед экспортом
сохраните изменённые документы и остановите Play. В настройках проекта выберите
начальную сцену и, при необходимости, начальную историю.

Выберите «Файл → Экспорт игры в exe…» и укажите имя новой папки сборки.
Экспорт копирует сохранённые файлы с диска; несохранённые изменения не включаются
и не сохраняются автоматически. Существующие папки не перезаписываются.
Папка назначения должна находиться вне исходного проекта и runtime.

В результате получаются:

```text
MyGame-Windows/
    Game.exe
    *.dll
    platforms/
    imageformats/
    Python/
    python310._pth
    Engine/Content/
    Engine/Shaders/
    Engine/Config/
    Game/Game.project
    Game/Content/
    Game/Content/Scripts/
    Game/Config/
```

Версия Python в имени `_pth` соответствует сборке движка. `Game.exe` запускается
двойным щелчком и ищет `Game/Game.project` относительно собственного расположения,
независимо от рабочей директории. Передавайте всю папку целиком. Проект компилировать
повторно не нужно: это данные для уже собранного Player.

`.project` остаётся JSON; сцены, истории, ресурсы и `.meta` сохраняют существующие
форматы и идентификаторы. Весь Content (включая Scripts) и Config копируется без отбора
используемых ресурсов. Неизвестные поля дескриптора сохраняются, стартовые пути
приводятся к относительным. Saved, кеши Python и посторонние каталоги проекта
не включаются. Ссылки на файлы через символические ссылки не поддерживаются.
Исходный проект остаётся прежним; игровая сборка содержит независимую копию данных.
Исходники скриптов открыты, шифрования и защиты от чтения нет.

## Подготовка комплекта разработчиком движка

В существующем настроенном каталоге сборки:

```powershell
cmake --build build --config Debug --target SakuraEditorDistribution --parallel 4
```

Результат: `build/Distribution/Debug/SakuraEditor/`. Для публичного распространения
используйте конфигурацию Release в настроенной для неё сборке:

```powershell
cmake --preset windows-msvc-release
cmake --build --preset windows-msvc-release --target SakuraEditorDistribution --parallel 4
```

Debug предназначен для разработки: Microsoft не разрешает распространять отладочный
CRT как обычный redistributable. Release и Debug не смешиваются в одном каталоге
дистрибутива. Существующий результат не перезаписывается; выберите новый путь
через `SAKURA_DISTRIBUTION_DIRECTORY` при конфигурации или перенесите предыдущий
комплект. Цель строит Editor, Player и MCP bridge, собирает DLL, Qt-плагины,
Engine Content/Shaders/Config, стандартную библиотеку Python и пример проекта.
Папки исходников и инструменты сборки в комплект не входят.

Python работает с локальной стандартной библиотекой и DLLs через `_pth`, без
системного PYTHONPATH и site-packages. Сторонние Python-пакеты автоматически
не собираются; если проект их использует, их нужно отдельно поставлять в Content/Scripts
с совместимыми нативными библиотеками. Нативные расширения движка требуют новой
сборки runtime. Windows и драйвер видеокарты остаются требованиями запуска.
Tcl/Tk, tkinter, IDLE и тестовые пакеты Python в минимальный комплект не входят.
Экспорт не выполняет полный анализ работоспособности всех сцен и скриптов.

Windows SDK Python 3.12.10 загружается CMake из официального пакета NuGet с закреплённой SHA-256.
Пакет содержит интерпретатор, заголовки и библиотеки; системная установка Python для сборки не нужна.
Редактор и Player распространяются с DLL и стандартной библиотекой, а не с SDK целиком.

## MCP и консоль

Команда `project_export_game` принимает строку `destination` с путём новой папки.
Она использует тот же `GameExporter`, что меню, требует открытый проект и остановленный
Play и экспортирует сохранённые файлы. Сохранение документов остаётся явным.
Команда не запускает компилятор или shell и не изменяет сцену или историю Undo.
Выбор папки системным диалогом остаётся UI-only.

Экспорт готовой игры не заменяет авторские пакеты механик, Events и функций.
Приёмка их переноса A → B → C относится к отдельному формату обмена.
