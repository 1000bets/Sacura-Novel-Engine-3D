# Создание ассетов через фабрики

Поля перечислений объявляются настоящим отражённым Enum через `ENGINE_REFLECT_ENUM`, а не целым числом с диапазоном. Каталог настроек передаёт `enumValues` из дескриптора, и общая форма показывает список имён. JSON-настройки используют имена значений; допустимость проверяет общий reflection codec. Например, `value_type` действия ввода использует `engine.InputValueType`: `Boolean`, `Axis1D`, `Axis2D`, `Axis3D`.

`AssetCreationFactory` находится в EditorCore. Конкретная фабрика — обычный отражённый объект с `ENGINE_CLASS`, который сообщает тип ассета, расширение, название и категорию и реализует `Create`. Каталог собирается из конкретных наследников в опубликованном каталоге рефлексии. React и Electron Bridge не содержат списка создаваемых классов.

## Настройки

Редактируемые отражённые свойства фабрики становятся полями диалога. Используются идентификатор и тип свойства, значение по умолчанию, `RF_DISPLAY_NAME`, `RF_UI_RANGE` и `RF_ASSET_TYPES`. Обязательность задаёт `IsSettingRequired`. `DescribeSettings` позволяет фабрике расширить описание; сохраняемые значения должны соответствовать её отражённым свойствам.

Например, `CreateMaterialInstanceAssetFactory.Parent` — обязательный `AssetKey`, допускающий Material и MaterialInstance. Поэтому общий диалог показывает выбор родителя с миниатюрой и действиями ссылки. У персонажа тем же механизмом появляются необязательная модель и описание. Настройки действия ввода принадлежат его фабрике.

При каждом создании выделяется новый экземпляр фабрики. Значения применяются через ReflectionJson и PropertyAccess; проверяются обязательность, диапазоны и совместимость ссылок. Объект класса с настройками по умолчанию не изменяется. Electron сохраняет существующее представление int64 десятичной строкой на границе протокола.

## Подключение типа

1. Зарегистрировать тип ассета и его расширение через `AssetRegistry::RegisterAssetType` до сканирования Content.
2. Создать конкретного отражённого наследника `AssetCreationFactory` с устойчивым идентификатором класса.
3. Объявить его настройки обычными отражёнными свойствами и реализовать создание корректного документа через существующие средства соответствующего формата.
4. Обеспечить включение регистратора в модуль. Для встроенных фабрик статической библиотеки используется `ForceTouchBuiltinAssetCreationFactories`; расширение подключает свой регистратор обычным способом.

Менять React, Bridge или обработчик MCP для нового типа не требуется. Тестовый `test.CustomDocumentFactory` проверяет обнаружение стороннего типа, применение настроек, изоляцию значений по умолчанию и отклонение неверных полей.

## Общий путь создания

ПКМ в React Content Browser открывает каталог с поиском, затем форму имени и настроек выбранной фабрики. Совместимый ассет под курсором может заполнить поле ссылки; это определяется фильтрами свойства. Созданный ассет появляется и выделяется в целевой папке. Текущие сцена и история сохраняют своё состояние и несохранённые изменения.

Electron использует `assets.creationTypes` и `assets.create`; Qt console/MCP — `asset_creation_types` и `asset_create`. Обе пары вызывают EditorCore. Electron принимает путь относительно Game Content, MCP — виртуальный `/Game/...`. Создание разрешено только в существующей папке Game Content, с допустимым уникальным именем и зарегистрированным расширением. Во время Play оно запрещено. Сохранённый файл ассета является результатом явной команды создания; история текущей сцены не подменяется.

Встроены фабрики сцены, истории, Surface/PostProcess/UserInterface материалов, экземпляра материала, персонажа, действия и контекста ввода, префаба и библиотеки UI. Материал содержит HLSL внутри своего документа; фабрики отдельного исходника HLSL нет. Модели, текстуры, аудио и другие ресурсы, требующие исходных данных, остаются импортируемыми. Для них можно добавить фабрику, когда существует корректный способ создания. Старое контекстное меню Qt Content Browser этой правкой не заменяется; общий каталог доступен Qt через инструменты.

Проверки: `SakuraAssetCreationFactoryTest` (`Editor.AssetCreationFactories`), typed native bridge/contract tests и проектный Electron helper `--asset-transfer-check`.
