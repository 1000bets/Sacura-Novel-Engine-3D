# MCP, настройки и консоль SakuraEditor

## Подключение

1. Соберите `SakuraEditor` в Debug. Цель автоматически собирает `SakuraMcpBridge` и размещает его рядом с редактором, в том числе в `Stage/Bin`.
2. Откройте нужный проект в редакторе.
3. Выберите **Правка → MCP Server и Toolset…**.
4. Нажмите **Сгенерировать и скопировать конфигурацию**. Кнопка включает локальный сервер и копирует готовый JSON с абсолютным путём к мосту. Отдельная кнопка **Включить MCP** запускает сервер без копирования.
5. Добавьте запись `sakura-editor` из объекта `mcpServers` в конфигурацию MCP-клиента, поддерживающего stdio. Существующие записи других серверов сохраняйте. Если клиент использует форму настройки, укажите `command` как программу, а каждый элемент `args` как отдельный аргумент.
6. Переподключите сервер в клиенте. Проверьте вызовы `editor_status`, `actions_list` и `scene_inspect`.

**Сохранить конфигурацию JSON…** экспортирует тот же JSON в выбранный файл. Формат `mcpServers` используется рядом клиентов; для клиентов с другим форматом конфигурации перенесите команду и аргументы в их поля запуска stdio. Кнопка не изменяет настройки внешнего приложения автоматически.

Конфигурация относится к одному запущенному экземпляру редактора. После перезапуска редактора сгенерируйте её заново. Несколько проектов могут работать в отдельных процессах с отдельными конфигурациями; переименуйте ключи серверов в клиенте, если подключаете несколько сразу. **Отключить MCP** закрывает все подключения. Автозапуск включается отдельно в настройках редактора.

Это MCP-сервер управления SakuraEditor и его Toolset. Импорт и вызов сторонних MCP-серверов из самого редактора в эту реализацию не входят.

## Настройки

**Правка → Настройки проекта…**: название проекта, стартовая сцена и стартовая история. Пути задаются относительно проекта; ссылки за пределы корня и отсутствующие файлы отклоняются. Пустое поле отключает соответствующий стартовый документ. Изменения сохраняются в `.project`; неизвестные поля дескриптора сохраняются. Стартовые документы применяются при следующем открытии, текущая сцена не заменяется.

**Правка → Настройки редактора…**: скорость камеры, число строк консоли, автозапуск MCP. Эти параметры сохраняются для текущего пользователя через `QSettings`, отдельно от проекта. Скорость камеры и лимит консоли применяются сразу после сохранения. Закрытие окна без нажатия кнопки сохранения не применяет изменения полей.

## Консоль

Откройте **Правка → Консоль** или нажмите Ctrl+` (обратная кавычка). Также найдите консоль поиском в меню окон. Команды имеют формат `имя JSON-объект`. `help` выводит каталог со схемами аргументов, `clear` очищает отображение. Доступны автодополнение названий, история ввода стрелками вверх/вниз и журнал `PrintString`.

```text
editor_status
actions_list
components_list
object_create {"name":"TestObject"}
scene_inspect
scene_undo
scene_redo
```

Для дальнейших операций берите `objectId` из результата создания или сериализованной сцены. Компоненты имеют собственные постоянные ID. `component_property_set` принимает значение в формате сериализации соответствующего отражённого свойства; `components_list` показывает имена и типы свойств.

Консоль не является системной оболочкой или Python REPL. Команды консоли и MCP вызывают один реестр инструментов, используют одинаковую проверку аргументов и историю изменений сцены. Ошибки возвращаются с `isError: true`. Изменения сцены не сохраняются автоматически: используйте `scene_save` или обычное сохранение редактора.

## Расширение и протокол

Регистрируйте команду в `EditorToolset`: стабильное имя, описание, JSON Schema аргументов, обязательные поля, признак чтения и обработчик. Схемы текущего реестра проверяют обязательность, неизвестные поля, простые типы и перечисления; проверки диапазонов и вложенных предметных структур выполняет обработчик. Для новых операций используйте существующий сервис или команду документа. Операции с миром выполняются на Game Thread. Для устойчивых ссылок используйте постоянные ID; сырые указатели между запросами не храните.

Поддерживаются `initialize`, `notifications/initialized`, `ping`, `tools/list`, `tools/call` для handshake-версий MCP `2025-11-25`, `2025-06-18`, `2025-03-26`, `2024-11-05`. Незнакомой версии предлагается `2025-11-25`. HTTP/SSE, удалённое подключение, OAuth, sampling, prompts, tasks и подписки не реализованы. Каталог инструментов стабилен в течение соединения; динамическое расширение через плагины должно дополнительно учитывать уведомления об изменении каталога.

Локальное соединение разрешено текущему пользователю ОС. Порт TCP не открывается. Сервер принимает до восьми клиентов, ограничивает входящие сообщения 1 МиБ и отсоединяет клиента при переполнении очереди вывода. Мост ждёт ответ до 60 секунд. Вызовы инструментов записываются в журнал. Подключённый доверенный MCP-клиент может менять сцену и настройки; контроль подтверждения отдельных вызовов остаётся на стороне клиента.

Проверка:

```powershell
cmake --build build --config Debug --target SakuraEditor SakuraEditorMcpTest --parallel 6
ctest --test-dir build -C Debug -R '^Editor.Mcp.Integration$' --output-on-failure
```

Тест создаёт временный проект внутри каталога сборки, изолирует настройки пользователя и проверяет настоящий stdio-мост, handshake, каталог, изменение сцены и Undo/Redo, ошибки аргументов, сохранение настроек, консоль и кнопку генерации конфигурации. Внешние MCP-клиенты требуют отдельной проверки в их окружении.


## Префабы

Команды `prefab_create`, `prefab_instantiate`, `prefab_inspect` и `prefab_modify`
доступны через общий реестр консоли и MCP. `prefab_create` принимает `objectId`,
путь `path` относительно Game Content и необязательный `variant`.
`prefab_instantiate` принимает `assetId`. `prefab_inspect` возвращает связь и
список изменений экземпляра по `objectId`. `prefab_modify` принимает `objectId`
и `operation`: `revert`, `apply`, `unpack` или `unpackAll`.

Изменения сцены используют EditorCore commands. Apply явно записывает общий
ассет и очищает историю отмены. Сохранение сцены остаётся отдельной командой.
Во время Play изменения префабов недоступны. Редактирование отдельного окна
предпросмотра и выборочное применение отдельных свойств пока доступны только
в интерфейсе; обычные свойства экземпляра редактируются общими командами
объектов и компонентов.


## Python Narrative

Команды `narrative_*` редактируют активную историю через `StoryGraphController` и её общую историю изменений. Типы литералов, пины и циклы данных проверяются до изменения; установка литерала отключает прежний провод с возможностью Undo. Изменения запрещены во время Play. Сохранение выполняется явно. Аргументы и границы покрытия описаны в [Python Narrative](PYTHON-NARRATIVE.md). Проверка реестра и команд: `Editor.Narrative`; транспорт проверяется отдельно в `Editor.Mcp.Integration`.

## Материалы и физика меша

`mesh_material_assign` принимает `objectId`, `slot` и `materialId`. Слот `-1` назначает материал всем слотам; пустой `materialId` возвращает материал меша. Команда работает с первым MeshRenderer объекта и использует ту же операцию истории, что и основной Inspector. Назначение всем слотам отменяется одним действием.

`mesh_physics_set` принимает `objectId`, `enabled` и `simulate`. Коллизия и динамическая симуляция включаются отдельно; при `enabled: false` требуется `simulate: false`. Отключение сохраняет параметры существующего тела. При первом включении создаётся тело с коллизией из настроек меша, а при её отсутствии — Box по границам меша. Динамическая симуляция треугольной коллизии отклоняется. Контроллер персонажа и объекты с несколькими телами настраиваются через собственные компоненты. Обе команды запрещают изменения во время Play и не сохраняют сцену автоматически.


### Переход по ссылкам ассетов

`asset_open` принимает обязательный `assetId` и необязательный `subAssetId`.
Команда разрешает ссылку через AssetRegistry и открывает зарегистрированный
редактор типа. Если редактора нет, выделяет ресурс через `asset_focus`.
`asset_focus` раскрывает Проводник, снимает поиск/фильтр типа и выделяет ресурс.
Оба действия не изменяют сцену. Открытие документа сохраняет действующие
диалоги несохранённых изменений.

Общие поля AssetReferenceField используют эти же команды; очистка назначения
идёт через действующий обработчик поля и его историю. Для отражённых свойств
это обычная команда присваивания asset/companion, для материалов документа —
соответствующая документная команда. Отдельного обхода Play/read-only нет.

## Операции Content Browser

`asset_rename` принимает `assetId` и новое `name` без расширения; `asset_move` и `asset_duplicate` — `assetId` и виртуальную папку `folder`. `asset_delete` принимает `assetId`. Папки обслуживают `folder_create` и `folder_rename` (`folder`, `name`) и `folder_delete` (`folder`). Это операции AssetOperations с теми же ограничениями на Game Content, открытые сцены и Play, что у Qt Content Browser. Дублирование создаёт новые GUID, переименование и перемещение сохраняют существующие. Удаление не является командой истории сцены.

React использует соответствующие typed Bridge-команды `assets.rename`, `assets.move`, `assets.duplicate`, `assets.delete`, `assets.createFolder`, `assets.renameFolder`, `assets.deleteFolder`. `assets.folders` перечисляет реальные каталоги, включая пустые. Копирование/вырезание хранит выбранную идентичность в UI; вставка вызывает duplicate/move, не прямое копирование файлов. Диалоги подтверждения и системный буфер пути — UI-only.

### React texture inspection

Detached React texture windows use read-only `assetDocument.execute` open/get/preview snapshots through the existing typed Electron bridge. Texture pixels are decoded by Engine TextureLoader; compression and mip mutations are unavailable. Channel, background, zoom and pan controls are UI-only and excluded from MCP mutations. See [Texture editor](TEXTURE-EDITOR.md).

### Числовые поля трансформации Electron

Поля положения, поворота и масштаба поддерживают арифметику (`+`, `-`, `*`, `/`, `%`, `^`, `**`, скобки), десятичную запятую, научную запись и относительные операции `+=`, `-=`, `*=`, `/=`. Выражения разбираются локально без выполнения JavaScript. В команды передаются только вычисленные числа.

Перетаскивание использует типизированную Bridge-команду `transform.edit` с `objectId`, `transaction`, `operation` (`begin`, `update`, `commit`, `cancel`) и `transform` для update/commit. Предпросмотр не создаёт записей истории; commit восстанавливает исходное состояние и выполняет одну существующую EditorCore-команду. Отмена, смена выбора и другие мутации возвращают исходную трансформацию. Play запрещает редактирование. Выражения, чувствительность мыши и замок масштаба — UI-only; отдельные MCP-команды для этих настроек не нужны.
