# Авторский пакет Sacura, форматы v1/v2

Основание: [P1–P9 обязательных требований](PRODUCT-REQUIREMENTS.md).
Статус: локальный обмен новой typed authoring model реализован в этапе 5А.
Для пакетов данных экспортёр пишет v2; импортёр читает v1/v2.
Исходники SDK и корень component используют явный [контракт v3](AUTHORING-PACKAGE-V3.md);
импорт v1/v2 не получает новых разрешений на код. Фактические решения, проверки и
ограничения: [ADR-005](../engine-web-prototype/frontend/docs/adr-005-local-authoring-packages.md).
Ниже сохранён исходный контракт v1; следующий раздел задаёт совместимые дополнения.

## Реализованные дополнения v2

### Компоненты авторской логики (версия модели 1)

`mechanicDefinitions[].componentVersion: 1` расширяет существующее определение
публичными `methods`, `events`, `lifecycle`, `subscriptions`, схемой `references`,
`stateVersion` и `stateFromParameters`. Экземпляр остаётся записью `mechanics`
с собственными `values`, `references`, `enabled` и владельцем `scope`.
Пакет объявляет `mechanic.components@1`; графовые данные совместимы с v2,
кодовые исходники требуют v3.

Ключи методов/событий — локальные стабильные символы. Реализации
`methods[methodId].logic.functionId`, сигналы и типизированные ссылки входят
в прежнее транзитивное замыкание и получают локальные project IDs при импорте;
ключи методов не переназначаются. Живые state, lifecycle records и задачи
не включаются. JavaScript методов остаётся явно обозначенным исходником,
импорт не исполняет его и снимает `approved` до просмотра/компиляции автором.

Контракт, редактор и фактические проверки переноса:
[компонентный авторинг](COMPONENT-AUTHORING.md).

### Ресурсы компонентов и Behavior Tree (версия ресурса 1, код — пакет v3)

`content.logicResources[]` содержит именованные ресурсы `component.code`,
`component.graph`, `behavior.tree` с `id/version/name/path/definitionId`.
Capability — `component.resources@1`, дополнительно `behavior.tree@1` для дерева
и `mechanic.javascript@1` для JS. Старый импортёр отказывает до применения.

В v3 кодовый ресурс переносит единственный редактируемый `source`, `dependencies`
и `signalBindings`. Производные method-function записи ссылаются на ресурс
через `logicResourceId/componentMethodId`; второй compiled-текст не хранится.
Графовые методы остаются обычными function graphs; дерево переносит `nodes/root`,
связи методов и ссылки на task receiver. IDs ресурса/определения/функций/сигналов/
узлов переназначаются вместе, локальные ключи методов сохраняются. Конфликт
виртуального пути ресурса получает уникальный суффикс, без перезаписи.

Импорт статически проверяет декларацию JS, индекс методов и структуру дерева,
не исполняет код. Для JS принудительно устанавливает `approved: false` и
`status: review`; запуск требует открытия и успешного сохранения локального
исходника. Экспорт отвергает draft/error JS. Живые state, BT controllers,
подписки и выполняемые задачи в пакет не входят. Непереносимые project IDs
в литеральных метаданных исходника запрещены: используются именованные
ссылки экземпляра и прежняя таблица dependencies.

Транзитивный перенос и независимость исходников A → B → C проверяются
`component-resources.test.js`, перенос дерева с графовыми методами и кодовыми
задачами — `behavior-tree-resources.test.js`. Полная ручная приёмка двери
с ключом новым UI этим не объявляется.

### Графы поведения (версия модели 1)

Формат контейнера остаётся v2. Функция с `graphVersion: 1` хранит исполняемые
узлы и чистые вычислительные `value`-узлы. Провод данных —
`{op: "node", nodeId, port: "value"}`; поток исполнения хранится в
`next/trueNext/falseNext`, ветви ожидания — в `branches/body`, дочерние задачи
Behavior Tree — в `children`. Экспорт объявляет `function.typed-graph@1`;
старый импортёр без этой возможности должен отказать до применения.

Обработчики правил используют `handlerFunctionId`, вход/выход состояния —
`enterFunctionId/exitFunctionId`. Условия допуска находятся в функции
`admission.functionId`; видимый вызов и развилка обозначены
`callNodeId/branchId`. Исполнение проверяет условие на снимке сигнала один раз
и передаёт этот результат в тот же обработчик. Все эти ссылки, карты
`behavior.functions/implementation.functions/handlers`, позиции и провода
переносятся и получают новые локальные ID. Зависимости включают редактируемые
реализации штатных компонентов, а не только прежние Events.

Параметры и начальное состояние — авторские данные. Локальные значения вызова,
кэш результатов узлов, ссылки на выполняемую работу, подписки и текущий боезапас
не входят в пакет заготовки. Установленная операция может объявить
`engineModule`; отсутствующая версия модуля блокирует импорт. Путь к исходнику
берётся из установленной операции; пакет не устанавливает код расширений движка.
JavaScript игровых механик переносится только в v3 с явным SDK-контрактом.

Детерминированная миграция проекта описана в
[отчёте модели графов](AUTHORING-GRAPH-MIGRATION.md). Эта версия формата не
является заявлением о завершённой ручной приёмке всех механик.


Контейнер и оболочка сохраняются. `formatVersion: 2` независимо от semver
`metadata.version`. Добавлены native mechanicDefinitions/rules/FSM, типизированные
операции/ссылки, сигналы, Input Actions и state/variable bindings. Версии одного
определения различаются по `id@version`. `roots.parameters` содержит обычную схему
определения либо список параметров функции. Несколько экземпляров одного
определения можно включить одним экспортом без копирования определения.

Прямые внешние typed references заменяются маркером
`{kind: "reference", type, mode: "external", parameter: inputId}`; их JSON Pointer
в `references` имеет `typed: true`. V1 native null placeholders по-прежнему
поддерживаются. Контекстные ссылки и tag selectors не превращаются в ссылки на A.
Переменные выбираются с проверкой valueType; общая schema применяется к native
функциям/правилам/операциям до изменения проекта. Незаданные обязательные объектные
слоты предложены в export preview. Автор меняет имя/подсказку, получатель выбирает
свои объекты. Параметры значений остаются native редактируемыми параметрами.

Импорт создаёт копию, узнаёт повторный origin ID и предлагает новую копию или
отмену. Каждая экспортированная локальная вариация получает свежий package ID;
официальные обновления с прежним ID и merge не реализованы. `sources` сохраняет
автора/лицензию/версию не только root, но и импортированных зависимостей. При
экспорте packageSource переносится в происхождение; project IDs создаются отдельно.

Полный шаблон применяется к пустому проекту и переносит его startup/историю/
управление/HUD. Существующий сюжет или механики не перезаписываются: такой target
получает диагностику и может импортировать отдельные механики, Events и функции.
Начальные native значения сохраняются; runtime world/прогресс не экспортируются.

Лимиты v2: 150 000 000 UTF-8 байтов файла, 128 ресурсов, суммарно 100 MiB
декодированных байтов, 4096 записей с ID, глубина 64 и 100 000 значений структуры.
Ресурсы встраиваются с SHA-256 и восстанавливаются как native data URLs без
внешнего fetch. glTF buffers/images собираются при экспорте; внешние URI внутри
импортируемой модели отвергаются. Проверка не является sandbox или подписью
автора; полного анализа картинок/аудио до браузерного декодирования нет.

Узкий адаптер известного legacy signal callback переводит сравниваемый object ID
в reference-параметр экспортной копии функции; source project не меняется.
Произвольные строки не переписываются. Неизвестная операция/версия блокирует
применение с сохранением исходного файла. Requirements объявляют уже установленные
trusted engine capabilities; import не регистрирует код и не устанавливает зависимости.

Ниже: исходный контракт v1, сохранённый для совместимости и истории решений.

## Назначение и контейнер

Один локальный UTF-8 JSON-файл `*.sacura-package.json` содержит выбранные Events,
функции, механику или шаблон и замкнутый набор их зависимостей. JSON — внутренний
формат файла: пользователь создаёт и меняет его через редактор, а не вручную.
Будущий магазин передаёт тот же файл; скачивание не меняет способ исполнения.

Пакет — оболочка над существующими данными проекта. `content` хранит только
нужную часть обычной модели Sacura; определения Events, групп, действий,
функций и виджетов не переводятся в другой язык. Для механики корни пакета
указывают на составляющие её обычные определения и размещения. Нового типа
исполняемого узла «магазинная механика» или особого runtime нет.

| Поле | Обязательное содержание |
|---|---|
| `format` | Строго `sacura-authoring-package` |
| `formatVersion` | Целое `1`: версия оболочки, отдельно от версии авторского содержания |
| `metadata` | `id`, `version`, `name`, `description`, `author`, `license`, `sources` |
| `compatibility` | `projectSchemaVersion`, `requiredCapabilities`, `requiredEngineModules` |
| `roots` | Тип экспортируемой заготовки (`event`, `function`, `mechanic`, `template`) и непустой список указателей на её корневые записи в `content` |
| `inputs` | Понятные входы, их типы, описания, обязательность и безопасные значения по умолчанию для значений; пустой список допустим |
| `content` | Нативные данные выбранного содержания и транзитивных зависимостей, включая параметры, описания и оформление |
| `references` | Автоматически сформированные места внешних привязок в `content` и соответствующие ID входов |
| `assets` | Только используемые двоичные ресурсы, встроенные в файл; пустой список допустим |

### Метаданные и совместимость

`metadata.id` — автоматически созданный стабильный ID заготовки, а не ID её
размещения в проекте. `metadata.version` — версия содержания `MAJOR.MINOR.PATCH`.
`name` и `description` показываются перед импортом. `author` — указанное автором
имя, без требования аккаунта. `license` — явно указанная лицензия/условия
использования, без автоматического присвоения свободной лицензии чужому материалу.
Редактор запрашивает недостающие сведения короткой формой при экспорте.

`sources` — список источников: ID пакета, его версия, имя автора и лицензия;
ссылка `url` необязательна. У исходной заготовки список может быть пустым.
При изменении исходное авторство остаётся в записи происхождения; автор варианта
указывается отдельно в `author`. Независимый вариант получает новый ID пакета
и сохраняет источник. Новая версия той же авторской заготовки сохраняет её ID.
Локальное редактирование само по себе не обновляет оригинал.

`projectSchemaVersion` — версия нативной модели данных. `requiredCapabilities`
перечисляет реально использованные виды действий, узлов и привязок с версиями
их контрактов, например `{ "id": "action.door", "version": 1 }`.
`requiredEngineModules` содержит ID и точные версии необходимых модулей с кодом.
В v1 принимаются поддерживаемая версия модели, поддерживаемые версии возможностей
и уже установленные совместимые модули. Неподдерживаемое требование блокирует
импорт до применения. Пакет не поставляет код этих модулей.

Технические версии определяет редактор по данным. Номер npm-пакета интерфейса
сам по себе не доказывает совместимость. Старые форматы
`sacura-project-template`, `sacura-location` и игровая HTML-сборка сохраняют своё
значение; нельзя молча считать их пакетами v1 или менять их семантику.

### Входы и ссылки

Каждый вход имеет автоматически созданный `id`, понятный `name`, `description`,
`type` и `required`. Контракт допускает типы значений `number`, `boolean`, `string` и типы ссылок:
`object`, `item`, `event`, `function`, `story`, `scene`, `camera`, `widget`,
`variable`, `resource`. Тип уточняется существующей моделью редактора: например,
для «Двери» выбирается объект, поддерживающий действие открытия. В текущей реализации внешние входы имеют тип `object`, `scene`, `story` или
`variable`; остальные определения собираются как внутренние зависимости,
а параметры значений остаются в нативных функциях. Для `variable` сохраняется
`valueType`, и редактор предлагает переменные подходящего типа. Сложные параметры
остаются в нативной модели, без нового языка внутри пакета.

У значения допускается `default`. У ссылки на проект A такого значения нет:
редактор B/C показывает подходящие локальные объекты. Необязательное продолжение
можно оставить пустым, если его потребитель поддерживает отсутствие ссылки.
Невыбранный обязательный вход блокирует применение с короткой подсказкой.

Внутренние ссылки между включёнными определениями остаются нативными. ID локальны
для пакета и при импорте переназначаются. Внешние ссылки на конкретную сцену,
объект, предмет, реплику или переменную заменяются входами. Их места перечислены
в `references`: `{ "at": "/content/events/0/groups/0/actions/0/target", "inputId": "door" }`.
В транспортной копии поле в таком месте равно `null`, чтобы не оставлять ID A.
Все использующие один вход места получают выбранную привязку.

`at` и корни используют JSON Pointer: `/` внутри имени кодируется как `~1`,
`~` как `~0`. Эти указатели формирует редактор, пользователь их не вводит.
Импортёр разрешает только известные ссылочные поля нативных типов, проверяет
соответствие типа входа и восстанавливает значение способом этого поля.
Например, ссылка на переменную в выражении восстанавливает нативный путь
к выбранной переменной; имя глобальной переменной A не становится требованием
к проекту B. Если используется поле структуры, запись ссылки дополнительно
сохраняет `memberPath` — массив имён полей относительно выбранной переменной;
например, `["hasKey"]`. Типы и доступность этих полей проверяются до применения.
При переназначении внутренней переменной её пути также восстанавливаются
через типизированный адаптер, сохраняя обращения к полям. Путь не даёт пакету
право произвольно записывать поля проекта. Реализация отмечает путь глобальной
переменной полем `variablePath: true`; для нативных привязок виджета без префикса
`global` используется также `widgetPath: true`. Привязка ключа словаря
`gameplay.actors` отмечается `key: true`; другие ключевые привязки запрещены.
Неоднозначная ссылка требует понятного уточнения входа при экспорте, а не
попытки угадать её по тексту. Поиск/замена всех строк, похожих на ID, недопустимы.

### Нативное содержание, оформление и ресурсы

`content` сохраняет обычные разделы модели (`events`, `functions`, `widgets`,
библиотеки действий и групп, используемые переменные, правила, размещения и
другие необходимые записи). Включаются только те разделы и записи, которые
нужны корням. Внутренние данные графов сохраняются полностью: узлы, связи,
порядок групп и действий, позиции, подписи, комментарии, стили и авторские
параметры. Представление редактора не заменяется исполняемым результатом.
Если оформление хранится отдельно от определений, соответствующие нативные
записи тоже включаются. Переназначение ID затрагивает и их ссылки.

Для каждого двоичного ресурса `assets` хранит `id`, `name`, `mediaType`,
`encoding: "base64"`, `data` и `sha256` декодированных байтов. Нативная запись
ресурса в `content` использует транспортный адрес `package-asset:<id>`;
импортёр заменяет его обычным локальным адресом ресурса. Модели, текстуры,
звук и остальные необходимые файлы встраиваются автоматически, с учётом
зависимостей самих ресурсов. Внешний URL или `blob:` проекта A не заменяет
доставку ресурса. Если обязательный ресурс получить нельзя, экспорт завершается
понятной ошибкой. Контрольная сумма обнаруживает повреждение, но не является
подписью автора или разрешением на исполнение кода.

Состояние текущего прохождения, активные задачи runtime, токены доступа,
серверные настройки, настройки аккаунтов и постороннее содержание проекта
в авторский пакет не входят. При экспорте шаблона выбранное содержание может
составлять целый стартовый проект; это явный выбор автора, а не обход сбора
зависимостей для отдельной механики.

## Экспорт, импорт и копии

1. Экспорт строит транзитивное замыкание от корней по типизированным ссылкам:
   вызовы Events/функций, группы и действия, виджеты, ресурсы, переменные,
   правила и размещения. Для циклических вызовов используется набор уже
   посещённых записей: сбор завершается без дублирования; допустимость циклов
   проверяет обычный валидатор логики. Привязки к миру A становятся входами,
   встроенное содержание остаётся зависимостями. Автор может явно включить
   собственный объект шаблона вместо внешней привязки.
2. Редактор автоматически сохраняет зависимости, представление графов,
   параметры, происхождение и требования совместимости. Экспорт работает
   с копией и не меняет исходную заготовку или её экземпляры.
3. Импорт читает пакет во временную модель. Проверяет структуру, версии,
   поддерживаемые типы/команды/выражения, уникальность ID, целостность всех
   ссылок, наличие ресурсов и корректность графов до изменения проекта.
   Проверки имеют ограничения размера файла, ресурсов, глубины и числа
   записей; превышение объясняется до применения, без частичного импорта.
4. Предпросмотр показывает состав, автора/лицензию/источники, недостающие
   возможности и все входы. Конфликтующее имя получает явное предложенное
   новое имя; все входящие ID получают новые локальные ID. В v1 нет неявного
   связывания с одноимённой библиотечной записью и нет перезаписи существующей.
5. После выбора привязок импортёр создаёт независимую копию во временном
   проекте, переназначает все ID и ссылки (включая вложенные действия, узлы,
   размещения, overrides и оформление) и повторно валидирует результат.
   План импорта привязан к версии текущего проекта: если он изменился после
   предпросмотра, план пересчитывается до применения.
6. Добавление данных и ресурсов применяется атомарно, одной отменяемой
   операцией. Сбой или отмена не меняет проект/библиотеку, временные ресурсы
   удаляются. Импорт не запускает механику; запуск — отдельное действие автора.
7. Локальная копия открывается обычными редакторами. Параметры экземпляра
   изменяют только его. Для внутренней логики пользователь явно выбирает
   редактирование общей локальной заготовки либо независимой копии. Обновление
   источника не подменяет её автоматически. Повторный экспорт использует
   тот же контракт и пересчитывает зависимости изменённого варианта.

## Граница безопасности

Допустимы данные известных Actions/Events/функций и поддерживаемые ресурсы.
Импорт не исполняет функцию даже ради проверки. Загрузка JS-модулей,
lifecycle-скрипты и установочные хуки из пакета запрещены. Неизвестные
исполняемые типы и код расширений движка отклоняются до применения.

По явному указанию пользователя от 19 октября 2026 разрешён исходник
игровой механики в `functions[].mechanicScript` с capability
`mechanic.javascript@1`. Поля: `version: 1`, `source` (черновик),
`compiledSource` (последний успешно проверенный текст), `dependencies`,
`hasOtherwise`, `approved`. Проверка пакета проверяет форму и синтаксис
скомпилированной версии, не выполняя её. Импорт всегда устанавливает
`approved: false`, независимо от содержимого пакета. Для включения необходимо
открыть исходник и успешно скомпилировать его в редакторе механик.

`dependencies.functions/events/signals` содержат обычные
`functionId/eventId/signalId`, `references` — типизированные ссылки,
`globals` — пути `global.<имя>`, `operations` — ID и версию установленной
операции. Сбор зависимостей, внешние привязки и переназначение ID выполняются
на этих данных. Исходный JavaScript использует устойчивые имена этих привязок
и не переписывается поиском строк. Во время игры код исполняется в отдельной
VM с игровым API, лимитом памяти и прерыванием вычислений; доступ к DOM, сети
и установке модулей отсутствует. Детали: [JavaScript механик](MECHANIC-JAVASCRIPT.md).
Опасные ключи объектов и произвольные пути записи не допускаются; ресурсные
декодеры принимают только поддерживаемые форматы данных.

Если нужен отсутствующий кодовый модуль движка, импорт показывает требование
и останавливается. Установка доверенного расширения — отдельная явно
обозначенная операция, не часть импорта авторской заготовки.

## Условие готовности реализации

Контракт реализован только после прохода
[«Дверь с ключом», A → B → C](ACCEPTANCE-DOOR-WITH-KEY.md), включая редактирование,
зависимости, независимость копий и проверки отказа. Сначала реализуется локальный
цикл целиком; его нельзя откладывать ради рефакторинга или магазина.

## Компонентные подключения сцены и истории

Именованное подключение остаётся записью `gameplay.mechanics`, общий ресурс —
одной записью `logicResources` с определением. Повторное использование не
копирует исходник; независимая копия создаётся явной командой автора.

`mechanics[].fieldBindings` хранит `target` (`state` или `parameters`), `field`
верхнего уровня schema и typed `variable` reference. Общий сборщик ссылок
включает переменную в inputs, проверяет привязку и переназначает её при импорте.
Runtime-state заготовки не экспортируется. Связанное поле читает источник,
не создаёт второго сохраняемого значения.

Вызов в Event/Sequence, input action, widget action или `object.interactionCall`
использует общую операцию `sacura.component.call@1`: typed mechanic `instance`,
стабильный локальный `methodId`, schema arguments. Разовый аргумент-переменная
использует `{op: 'variable', variable: typedReference}`. Имена объектов/методов
не являются идентичностью. Отсутствующие links диагностируются; импорт не
назначает первый подходящий экземпляр.

`sacura.component.start@1` дополнительно содержит `lifetime` и typed
`lifetimeOwner` (scene/project/mechanic). Это ссылка владельца отдельной задачи,
а не live handle экспортируемого проекта. Требования к зарегистрированным
операциям собираются прежним механизмом capabilities.

Автоматически проверен перенос LockedDoor с постоянным источником в другой
проект: object/variable remap, просмотр и сохранение импортированного JS,
запуск с целевой переменной. Полная ручная приёмка «Дверь с ключом» A → B → C
этим тестом не объявляется выполненной. Импорт по-прежнему не исполняет JS.
