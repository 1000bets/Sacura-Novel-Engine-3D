# Аудит переиспользования UI: меню потока истории

Дата: 22 октября 2026. Область проверки: Qt UI потока истории, меню событий,
общие controls/styles/icons и соответствующий веб-прототип. Это не аудит всего
движка и не подтверждение полного переноса frontend.

## Что обнаружено

| Участок | Причина проблемы | Решение |
|---|---|---|
| Правый клик и «+ Нода» | Две независимые копии списка `Реплика / Выбор / Действие / Концовка` в `StoryGraphicsScene` и `StoryWorkspaceView` | Один `BuildStoryNodeMenu`, оба входа открывают `StudioActionMenu` |
| Панель первого скриншота | Веб-компонент `EditorContextMenu.jsx` поддерживает поиск, категории, заголовки групп и вложенные пункты; Qt использовал обычное меню без этой структуры | Общий Qt-компонент с тем же устройством, отдельные токены оформления |
| События в карточке и инспекторе | Раздельная ручная сборка меню, индексирование `QAction*` и блокирующий `exec()` | Общий `BuildStoryEventMenu`, поиск по именам/описаниям, асинхронное открытие |
| Контекстные действия карточек/связей | Ещё одна локальная сборка и отдельная поверхность меню | Та же `StudioActionMenu`, команды удаления/назначения начала сохранены |
| Доступность действий | Видимое совпадение меню не означало бы поддержку новых видов нод | Поддерживаемые действия вызывают существующий controller/document; остальные недоступны и объяснены в подсказке |
| Жизненный цикл | Старое синхронное меню могло читать `QGraphicsSceneContextMenuEvent` по ссылке; перенос на асинхронную поверхность сделал бы ссылку висячей | Координаты и идентификаторы копируются; меню закрывается при смене документа/прав редактирования, отмене взаимодействия и Play; обычное отложенное обновление графа его не закрывает; scene callbacks используют `QPointer` |

## Граница компонентов

`StudioMenuItem` — принадлежащее UI описание: стабильный ID, подпись, группа,
иконка, поисковые слова, пояснение, доступность, дочерние пункты и callback.
Ни сериализации, ни доступа к сцене/движку в нём нет.

`StudioActionMenu` — общая поверхность: заголовок, поле поиска, группы, вложенные
меню, пустой результат, клавиатура и закрытие. Основана на `QMenu`: штатный Qt
обрабатывает каскадные меню, захват мыши, выход за границы экрана и прокрутку
длинного списка. Поиск рекурсивно разворачивает категории и сохраняет
доступность их потомков. При наборе запроса не меняется документ.

`StoryMenuBuilder` — каталог и связывание семантики истории с описаниями меню.
Он не создаёт виджеты и не изменяет данные. `StoryWorkspaceView` передаёт
команды через существующие callbacks в `StoryGraphController` и
`StoryGraphDocument`; undo/redo, сохранение и формат истории остаются общими.

`controls.qss` — поверхность, заголовки и поле поиска. `ActionMenuStyle` — общая
строка команды: перенос длинных названий, высота по тексту, иконка, hover,
disabled и стрелка подменю. Цвета берутся из существующих палитр.
Иконки берутся из общего `MakeFrontendIcon` / `MakeStudioIcon`.
Локальные копии иконок и inline-стили для истории не добавляются.

## Как использовать в следующих панелях

1. Определить список `StudioMenuItem` с понятными названиями и стабильными ID.
2. Передать существующие команды через callbacks. Не выполнять изменения
   документа внутри визуального компонента.
3. Создать `StudioActionMenu(Title, Items, Owner)` и вызвать `Open(GlobalPoint)`.
   Корневое меню удаляется после закрытия; хранить его только в `QPointer`.
4. Копировать координаты/ID. Для callback с временем жизни вне владельца
   использовать `QPointer`, а при смене документа закрывать меню.
5. Переиспользовать каталог, если одна операция доступна из нескольких мест.
   Не копировать подписи, индексы видов нод и таблицы доступности в каждый view.

Обычные меню menubar не нуждаются в поисковой панели автоматически.
`StudioSelect` остаётся контролом выбора текущего значения, `StudioActionMenu` —
контролом вызова команды. У них разные контракты выбора, поэтому объединять их
в один универсальный виджет без конкретной необходимости не следует.

## Незакрытые разрывы переноса

В нативном `StoryNodeKind` есть только `Line`, `Choice`, `Action`, `End`.
Нет исполнения и сериализации value wires, переменных графа, математических
нод, конвертаций, сравнений, JavaScript-функций, gameplay/branch/gate/merge.
Соответствующие пункты первого скриншота показаны недоступными с пояснениями;
категории раскрываются для просмотра. `Игровая сцена` не подменяется `Action`.
Нативное `Действие` сохранено отдельным рабочим пунктом.

Следующий перенос этих возможностей должен включать модель, сериализацию,
runtime, редактор параметров, зависимости и пакеты. Одного включения пунктов
меню недостаточно. Возможность импорта/экспорта JS-графов веб-прототипа этим
изменением не заявляется.

Вне этого изменения остаются старые меню Content Browser, Hierarchy и shell.
Они могут использовать общий компонент при переносе соответствующего UX;
их массовая механическая замена не выполнялась. `StudioControls`,
`StoryActionFieldsView`, существующие style helpers и icons уже дают полезную
общую основу, но наличие этих файлов само по себе не обеспечивает визуального
совпадения всех панелей.

## Проверка продуктовых принципов

- Простота: правый клик / «+ Нода» → поиск → создание; для выбранной реплики
  доступен переход к выбору/созданию события. Пользователь не вводит ID или JSON.
- Переносимость и редактируемость: команды продолжают изменять тот же
  `StoryGraphDocument` с прежним сохранением и undo. Нового формата и новых
  зависимостей авторских данных нет. Полная приёмка «Дверь с ключом» A → B → C
  не относится к смене поверхности меню и здесь не заявляется.
- Универсальность: визуальный компонент не зависит от Story/Engine/жанра;
  события используют существующую модель и не требуют героя, HP или оружия.
- Ограничение: визуальная панель не устраняет перечисленные пробелы нативного
  исполнения.

## Фактическая проверка

- Debug-сборка `Editor`, `SakuraEditor` (включая Stage) и трёх UI test targets
  завершилась успешно с существующими собранными зависимостями.
- CTest: **12/12** — `Editor.UI.Foundation`, четыре проверки документов истории,
  `Editor.Story.Graph.UI`, `Editor.Story.Graph.Shell`, пять `Native.Story.Events.*`
  (включая команды, отмену/Play и пакеты).
- UI-тест истории дополнительно прошёл при масштабе **100/125/150/200%**.
  Проверены окно 800×800 с прокруткой и конфигурация экрана 1920×1080.
- Новые локальные проверки: общий компонент вне Story, мышь по многострочной
  команде, размещение у края экрана, достижимость нижнего пункта, рекурсивный
  поиск и пустой результат, недоступные команды, клавиатура/подменю/Escape,
  фактический context event, точка создания ноды, стабильный ID после undo/redo,
  создание события, отсутствие выбранной реплики, закрытие при Play.
- Qt-снимки меню и подменю просмотрены при 100% и 125%: подписи переносятся,
  пиктограммы и стрелки используют общую библиотеку, секции и поиск видимы.
  Computer Use не применялся. Снимки: `build/story-menu-captures/` и
  `build/story-menu-captures-125/`; последние логи сборки/проверок:
  `build/story-menu-final-build.log`, `build/story-menu-tests.log`.
- `Scripts/VerifyEditorUiSources.py` подтвердил 52 токена палитр и отсутствие
  inline-стилей в UI/Shell; `git diff --check` для затронутых tracked-файлов
  прошёл. Локальные тесты под `Root/Tests` остаются gitignored по AGENTS.md.
