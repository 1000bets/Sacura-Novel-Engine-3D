# Input Actions и Mapping Contexts

Система находится в Engine и используется Player и Editor Play. Клавиатура и
мышь поступают через Qt, геймпады — через SDL3. Ядро не принимает Qt-события и
не вызывает методы компонентов автоматически. Всё исполнение происходит на
Game Thread до обновления игрового мира.

## Настройка

Откройте «Окна → Ввод». Создайте действие, задайте тип значения и условие
срабатывания. Создайте контекст, добавьте привязку к действию и выберите
устройство. Клавиша назначается нажатием кнопки записи, затем самой клавиши.
Для WASD используйте четыре привязки одного действия Axis2D: W направьте по Y,
S — по Y с отрицательным масштабом, A — по X с отрицательным масштабом,
D — по X. Объединение с ограничением устраняет ускорение по диагонали.

В «Начальных контекстах» включите нужный контекст и задайте приоритет.
Настройки находятся в секции `input` существующего `.project`; прочие поля
дескриптора сохраняются. Изменённые ассеты и настройки применяются при следующем
запуске игры. «События» связывают действие и фазу с событием начальной истории.
Список событий берётся из сохранённого документа истории.

Файлы `.inputaction` и `.inputcontext` — обычные ассеты Content с `.meta`.
Идентичность берётся из GUID метаданных, поэтому переименование и перемещение
файла не требуют переназначения привязок. Engine Content доступен только для
чтения. Редактор документов поддерживает Undo/Redo и явное сохранение; изменение
файла извне блокирует перезапись до повторного открытия.

«Профиль» сохраняет переназначения и чувствительность в
`Saved/InputProfile.json`, не изменяя авторские привязки. Встроенные действия
продолжения диалога и паузы доступны как `engine.input.advance` и
`engine.input.pause`; их контексты можно отключить в настройках проекта.

## Исполнение

Типы значений: Boolean, Axis1D, Axis2D и Axis3D. Условия: Pressed, Released,
Hold и Continuous. Фазы: Started, Ongoing, Triggered, Completed и Canceled.
Модификаторы применяются сначала к привязке, затем к объединённому значению
действия. Поддерживаются масштаб, инверсия, перестановка осей, мёртвая зона и
нормализация. Дополнительное действие может служить условием сочетания;
циклические зависимости отклоняются.

Активные контексты обрабатываются по убыванию приоритета. Привязка с перехватом
занимает физический канал для нижележащих контекстов. Смена контекстов отменяет
текущие действия и требует отпустить удерживаемые кнопки. Короткое нажатие и
отпускание между кадрами сохраняются. Потеря фокуса отменяет ввод; текстовые
поля не передают клавиши игре. На паузе продолжают работать только действия,
у которых это разрешено явно.

## Явные Python-подписки

В проекте нет универсального lifecycle `OnInput`. Подписка выбирает действие,
фазу и произвольный callable. Декоратор `@method` для локального callback не нужен.

```python
import engine

@engine.register_class("game.Inspection")
class Inspection(engine.ScriptComponent):
    def OnCreate(self):
        self.InspectionSubscription = engine.BindAction(
            self,
            "/Game/Input/Inspect.inputaction",
            engine.InputPhase.Triggered,
            self.Inspect,
        )

    def Inspect(self, Value):
        print("Inspect input received")

    def StopInspection(self):
        engine.Unbind(self.InspectionSubscription)
```

`BindAction` принимает владельца-компонент, путь ассета либо идентификатор,
фазу и callback. Callback получает `InputValue` с полями Horizontal, Vertical,
Depth и методом Magnitude. Подписки освобождаются при EndPlay/удалении владельца
и закрытии сессии. `GetInputValue(Action)` читает текущее значение.
`SetInputContexts([(Context, Priority), ...])` заменяет активный набор.

C++ использует `InputSession::BindAction` и `Unbind`; callback получает
`InputActionEvent`. Можно задать идентичность владельца и проверку срока его
жизни. `UnbindOwner` отключает все подписки владельца. Внешние адаптеры передают
значения через `Feed`; импульсные оси отмечаются как transient. Состояние ввода
не сериализуется в сцену и не переносится из EditWorld в PlayWorld.

## Перенос

Экспорт выбранного действия или контекста собирает используемые действия и
транзитивные зависимости сочетаний. `.inputpackage` содержит редактируемые
данные и происхождение ресурсов. Импорт сначала проверяет версии, типы,
ссылки и циклы, показывает состав, затем создаёт независимые GUID и локальные
копии. Публикация выполняется перемещением подготовленного каталога; существующие
файлы не перезаписываются. Начальные контексты в новом проекте включаются явно.

Это пакет ресурсов ввода. Подписки конкретного проекта на события истории,
сама история, Python-код обработчиков и пользовательский профиль в него не
включаются. Проверка переноса Input не означает прохождение общей приёмки
«Дверь с ключом» для всех авторских механик.

## Console и MCP

Команды зарегистрированы в общем `EditorToolset`:

- `input_list` — действия, контексты, текущие значения и фазы.
- `input_create` — создание action/context.
- `input_document` — inspect/apply/undo/redo/save/reload через InputAssetDocument.
- `input_package` — export/inspect/import через InputPackage.

Мутации отклоняются во время Play. Изменение документа и его сохранение —
разные операции. При открытии одного файла одновременно в UI и MCP проверка
внешнего изменения защищает несохранённую копию от молчаливой перезаписи.
Запись физической клавиши, настройки начальных контекстов, визуальные подписки
на события и пользовательский профиль пока доступны через UI; отдельные
MCP-команды для них не зарегистрированы. Произвольное исполнение Python и
инъекция аппаратного ввода через MCP не предоставляются.

## Проверки и границы

Цели `SakuraInputTest` / `Engine.Input` проверяют ядро, делегаты, документы,
профиль, независимый перенос A → B → C и жизненный цикл Player/PlaySession.
`SakuraInputEditorTest` / `Editor.Input` проверяет нативный редактор, Qt-события,
текстовый фокус и создаёт `input-editor.png` и `input-editor-compact.png`.
Debug-прогон 23 октября 2026: Engine.Input, Editor.Input, Engine.Story.Runtime, Engine.Reflection.Python и Editor.Narrative прошли (5/5). Нативный SakuraEditor запущен на D3D12; снимки обычного и компактного окна проверены. Логи: build/input-regression.log и build/input-launch.log.

Первая версия использует одного локального игрока. Touch и External доступны
как каналы для адаптеров; визуальный конструктор экранного управления не входит
в этот этап. Физический геймпад требует отдельной аппаратной проверки.
