# Игровые механики: первоначальная реализация

Этот отчёт фиксирует первоначальный этап и его проверки. Актуальный обмен новой
typed model v2, совместимость с пакетами v1, template startup, происхождение,
изменённые файлы и фактические проверки этапа 5А:
[ADR-005](../engine-web-prototype/frontend/docs/adr-005-local-authoring-packages.md).

Исходная и рабочая ветка: `feature/new-ui-fix`. Стек: JS, React, Three.js.
Основание: [обязательные требования](PRODUCT-REQUIREMENTS.md).

## Что изменилось

Жанровая форма заменена каталогом готовых механик. Выбор объекта, сцены или
проекта определяет доступные механики. Дверь предлагает выбрать ключ, таймер —
время и событие. Внутренняя реакция раскрывается как «Когда / Если / Сделать /
Иначе», затем открываются существующая библиотека Events или граф функции.
Инвентарь, сочетания предметов, ввод и HUD доступны по запросу.

Механики создают обычные правила, Events, группы действий, функции и записи
существующих систем. `project.objects` остаётся источником идентичности объектов.
Движение, камера, здоровье, оружие, преследование и физика подключаются отдельно.
Пустому проекту не назначаются жанр, герой, HP, оружие или условие победы.
Старые проекты проходят адаптацию `preset` к независимой камере и сохраняют
прежнюю активацию на игровой ноде. Жанровые шаблоны остаются примерами данных.

Сигнал (`interact`, `pickup`, `timer` и другие) выбирает реакцию. Event остаётся
обычным определением с группами действий и своим жизненным циклом. Реакции и
ноды функций запускают Events через существующий `PreviewRuntime.binding`.
Сохраняются последовательность групп, параллельность действий, режимы ожидания,
пауза и остановка. Функция не продолжает граф после отмены ожидаемого Event.
Физика и рендер обновляются штатными системами, без покадровых Events.

`registerMechanic`, `registerGameCommand` и `registerGameSignal` предоставляют
точки регистрации доверенным модулям движка. Определение механики может описать
свои поля параметров. Импорт пакета не вызывает регистрации и не загружает код.
Runtime использует чистые модели и исполнители; React нужен интерфейсу редактора.

## Локальные пакеты

Пакет v1 переносит отдельную механику, Event, функцию либо явно выбранный шаблон
проекта. Собираются вызываемые определения, предметы, виджеты и ресурсы.
Ссылочные параметры функций выбираются из библиотек: объект, предмет, сцена,
Event или функция; сохраняются нативными строковыми параметрами с типом ссылки.
Внешние объекты, сцены, продолжения истории и переменные становятся именованными
входами. Переменные выбираются с проверкой типа; пути полей структуры сохраняются
автоматически. Привязки мира не превращаются в копию исходной сцены.

Предпросмотр показывает автора, лицензию, источник, состав и привязки. Все
внутренние ID переназначаются; конфликты имён показаны до применения. Импорт
готовит отдельную копию, проверяет её штатным валидатором и отклоняет устаревший
предпросмотр. Editor использует существующий путь изменения библиотеки ресурсов:
проверяет локальное сохранение до замены проекта. Отмена не меняет проект.

Изменённый вариант экспортируется отдельным пакетом с происхождением исходника.
Копии имеют независимые Events и функции. Импорт не подписывает на обновления.
Обмен работает без магазина; новые аккаунты, оплату и облачную синхронизацию
этот этап не добавляет.

## Воспроизведение

1. Из `engine-web-prototype/frontend` выполнить `npm run dev`.
2. Открыть пустой проект, добавить два объекта: дверь и ключ.
3. Открыть «Игровые механики», выбрать дверь в «Добавить к», добавить «Дверь
   с ключом» и выбрать ключ. Запустить: подобрать ключ, нажать на дверь.
4. Остановить, раскрыть «Обмен заготовками», экспортировать механику; указать
   название, автора и лицензию.
5. В другом проекте импортировать файл, выбрать собственные дверь и ключ,
   проверить импорт и добавить пакет.
6. Раскрыть «Когда / Если / Сделать / Иначе», открыть функцию условия.
   В ноде результата выбрать «И»: первый операнд — количество предмета из
   параметра «Ключ», второй — Boolean-переменная проекта. Открыть действия
   события, добавить подсветку, сохранить в библиотеку.
7. Экспортировать вариант и импортировать в третий проект. Выбрать свои
   объекты и переменную разрешения. Без ключа или разрешения дверь закрыта;
   с обоими условиями открывается и подсвечивается.

## Проверка трёх принципов и ограничения

- **Простота:** сценарий двери создан и перенесён через браузерный редактор;
  условие и действие изменены без JSON, ID, путей и программирования.
  Три теста интерфейса проверяют выбор объектов, раскрытие общей логики и
  запрет изменения во время запуска и выбор параметров функций из библиотек.
- **Переносимость:** автоматический A → B → C проверяет три комбинации условий,
  добавленное действие, граф, происхождение, конфликты и независимые копии.
  Через браузер реально скачаны пакеты A/B, B изменён в редакторе и импортирован
  в C. Именно скачанный пакет B дополнительно запущен штатным runtime.
  Отдельные тесты проверяют реальные байты WAV, контрольные суммы, замкнутость
  зависимостей, шаблон и вложенные ресурсы glTF. Звук в headless-тестах не
  воспроизводился; прослушивание через браузер не заявляется проверенным.
- **Универсальность:** тестируются таймер, осмотр и дверь во время диалога без
  героя/HP/оружия, независимость камеры/оружия/преследования и сохранения.
  Поворот двери применяется к обычному объекту в обеих существующих сценах.

Сохраняются ограничения существующих систем: одна активная управляемая сущность
и одна подключённая камера на проект; коробочная физика и простое преследование.
Импорт второй камеры/другого контроллера требует сначала отключить существующую
возможность; конфликт объясняется до изменения проекта. Экспорт всегда создаёт
независимый вариант `1.0.0`; обновление оригинала и слияние версий не реализованы.

Пакет ограничен 150 МБ; отдельный ресурс — 100 МиБ. Поддержаны WAV, MP3, OGG,
аудио WebM, PNG/JPEG/WebP, GLB и glTF 2.0. Внешние буферы и изображения glTF
встраиваются; GLB с внешними URI отклоняется. Требующие дополнительных декодеров
модели, другие MIME-типы и обязательные внешние модули отклоняются с объяснением.
Запреты обычного редактора на CSS URL/@-директивы сохраняются. Часть новых
подписей пока доступна только на русском. Полный набор сценариев из документа
приёмки, включая прослушивание звука и отказ хранилища в браузере, отдельно не
объявляется пройденным.
