# SDK авторских компонентов v1

Фактически работающий API на 19 октября 2026. Полный контракт lifecycle,
сохранений, переноса и карта файлов: [COMPONENT-AUTHORING](COMPONENT-AUTHORING.md).

В редакторе: **Создать → Компонент → Код · JavaScript**. Укажите имя,
напишите исходник, нажмите **Сохранить компонент** или ⌘S / Ctrl+S.
Выберите объект, сцену или проект и **Добавить экземпляр**. Опубликованный
тип также появляется в **Добавить компонент**. Для начала не нужны готовая
механика, Event, функция, JSON проекта или регистрация типа в движке.

Уточнение от 20 октября: объявленный аргумент `reference` поступает в метод
компонента типизированной ссылкой также при вызове из истории, ввода или UI.
Его можно передать в `engine.invoke(args.weapon, "select", {})` и сохранить
в объявленное поле состояния типа `reference`. Общий вызов не превращает
такой аргумент в строку ID. Native-операции продолжают разрешать ссылки
по своему контракту. Работающий пример — `Loadout.select` в шаблоне шутера;
выбор гранатомёта сохраняет ссылку на его конкретный экземпляр, обновляет
HUD и восстанавливается вместе с независимыми магазинами обоих Weapon.

## Counter: один исходник, любое число экземпляров

Этот пример работает в редакторе и PreviewRuntime. `step` появляется
в инспекторе; `value` принадлежит прохождению, а не defaults проекта.

```js
const component = {
  name: "Counter",
  parameters: {
    type: "object", properties: {
      step: { type: "number", label: "Шаг", default: 1 }
    }
  },
  stateVersion: 1,
  state: {
    type: "object", properties: {
      value: { type: "number", default: 0 }
    }
  },
  references: {
    type: "object", properties: {
      other: { type: "reference", referenceType: "mechanic", optional: true }
    }
  },
  signals: {
    changed: {
      name: "Changed",
      payloadSchema: {
        type: "object", properties: { value: { type: "number" } }
      }
    }
  },
  methods: {
    add: {
      name: "Add",
      parameters: {
        type: "object", properties: {
          amount: { type: "number", default: 1 }
        }
      },
      result: { type: "number" },
      async run({ args, params, state, engine }) {
        const delta = args.amount * params.step;
        if (!Number.isFinite(delta)) throw Error("Некорректное приращение");
        state.value += delta;
        await engine.emit("changed", { value: state.value });
        return state.value;
      }
    },
    multiply: {
      name: "Multiply",
      parameters: {
        type: "object", properties: { factor: { type: "number" } }
      },
      result: { type: "number" },
      run({ args, state }) {
        state.value *= args.factor;
        return state.value;
      }
    }
  }
};
```

`add` и `multiply` — стабильные ключи методов внутри этого типа. Отображаемое
`name` можно менять без изменения вызовов. Изменение ключа означает удаление
старого метода и создание нового; старый вызов сообщит об ошибке. Другой тип
может независимо иметь метод с ключом `add`.

После сохранения **Counter · Multiply** доступен в палитре любого графа.
Узел показывает получателя, `factor` и выход результата. Его получатель —
конкретный экземпляр Counter. Двойной клик открывает этот исходник; кнопка
со стрелкой **К месту вызова** возвращает граф с сохранёнными узлами и связями.
В обычном выборе операции используйте **Вызвать метод компонента**, затем
экземпляр и метод; список методов получается из определения проекта.

## Схемы и состояние

Метаданные — литеральный `const component`. Helpers, условия, циклы,
коллекции, вложенные функции и `async/await` разрешены в исполняемом JS.
Метаданные читаются статическим парсером: сохранение и импорт не запускают
верхнеуровневый код автора. Дублирующиеся ключи и вычисляемые метаданные
отвергаются с местом ошибки.

Поддерживаются schemas `number`, `integer`, `boolean`, `string`, `vector`,
`object` с `properties`, `collection` с `items`, типизированные `reference`,
`union` с `variants`; результат без значения — `{type: "void"}`.
`label`, `default`, `optional`, числовые `min/max` описывают инспектор
и валидацию. Параметры метода всегда object schema именованных аргументов.
Пропущенные `parameters`, `state`, `references` — пустые object schemas;
пропущенный `result` — void. Сохраняемые значения должны быть JSON-данными.
Функции, Promise, Map/Set и host handles не являются сохраняемым состоянием.

Начальное состояние: defaults `state` → `initialState` → `stateFromParameters`.
Например, настройки двери применяются один раз в новой игре:

```js
// Поля внутри component:
parameters: { type: "object", properties: {
  initiallyLocked: { type: "boolean", default: true }
} },
state: { type: "object", properties: {
  isLocked: { type: "boolean", default: false }
} },
stateFromParameters: { isLocked: "initiallyLocked" }
```

`state.isLocked = false` меняет только текущий экземпляр. Восстановленные
значения save имеют приоритет над defaults. При изменении несовместимой схемы
увеличивайте `stateVersion`: неизвестная версия save требует миграции и сейчас
даёт отказ до замены мира. Автоматических миграций ещё нет.

## Контекст метода и вызовы

`run(ctx)` получает:

| Поле | Значение |
| --- | --- |
| `args` | Аргументы текущего вызова |
| `params` | Настройки конкретного экземпляра из инспектора |
| `state` | Проверяемый proxy сохраняемого состояния экземпляра |
| `refs` | Назначенные в инспекторе именованные ссылки |
| `self`, `owner` | Typed reference экземпляра и его объекта/сцены/проекта |
| `context` | `source`, `target`, `initiator`, scene/instance/task IDs и emitter при наличии |
| `global` | Переменные проекта с переносимыми привязками |
| `engine` | Общие операции, методы компонентов, Events и ожидания |

Пример тела нового метода `run`:

```js
async run({ refs, self, state, engine }) {
  const received = await engine.invoke(refs.other, "add", { amount: 2 });
  const ownValue = await engine.invoke(self, "multiply", { factor: 3 });
  return received + ownValue;
}
```

`refs.other` назначается на экземпляр в инспекторе. `engine.invoke` одинаково
вызывает кодовый и графовый методы; он не запускает весь компонент.
Пропущенная связь вызывает ошибку. Подстановки игрока/первого объекта нет.
`state` общий для методов одного экземпляра, `args` и локальные переменные
отдельны для каждого вызова. Верхнеуровневый JS запускается заново при каждом
вызове; сохраняемые данные размещайте в `state`.

| Вызов SDK | Действие |
| --- | --- |
| `await engine.invoke(ref, methodId, args)` | Метод конкретного экземпляра, возвращает его результат |
| `await engine.emit("changed", payload)` | Собственный сигнал; проверяет schema, передаёт точный emitter |
| `await engine.operation("sacura.game.message", {message: "Привет"})` | Зарегистрированная операция через существующий API |
| `await engine.wait(seconds, "game")` | Ожидание игрового времени; также доступно `"real"` |
| `await engine.waitSignal("victory", timeoutSeconds)` | Отменяемое ожидание существующего сигнала; таймаут необязателен |
| `engine.ref("Имя объекта")` | Переносимая зависимость, разрешённая при сохранении исходника |
| `await engine.call("Имя функции", args)` | Существующая функция проекта через таблицу зависимостей |
| `await engine.event("Имя Event", options)` | Существующий Event; join/overrides по прежнему API |
| `console.log(value)` | Сообщение в прежний журнал наблюдений runtime |

Имена зависимостей в `engine.ref/call/event/operation/signal/waitSignal/start`
задаются строковыми литералами: компилятор сохраняет их привязки отдельно
и импорт переназначает IDs. Аргументы могут вычисляться. Для динамического
получателя компонента используйте `engine.invoke` и `refs`, а не сырые project IDs
в исходнике. Прямые ID-ссылки в метаданных запрещены как непереносимые.
Полный прежний API работ `start/join/cancel`, Events и операций описан в
[MECHANIC-JAVASCRIPT](MECHANIC-JAVASCRIPT.md).

JS исполняется в QuickJS с ограничением времени вычислений, памяти и глубины
вызовов. DOM, fetch, Node, npm/ES imports не предоставляются. `AbortSignal`
не пересылается в VM: `wait`, `invoke` и операции SDK наследуют отмену задачи,
проверки активности защищают записи и эффекты после await. Для обычного
ожидания не используйте недоступный `setTimeout`.

## Lifecycle и обработчики

Все hooks — обычные методы компонента без обязательных аргументов:

```js
// Поля внутри component; реализуйте методы с этими ключами в methods:
lifecycle: {
  initialize: "onNewGame",
  restore: "onRestore",
  enable: "onEnable",
  disable: "onDisable",
  destroy: "onDestroy"
},
subscriptions: [{
  id: "use-door",
  signal: "interact",
  methodId: "interact",
  match: "owner"
}]
```

`initialize` выполняет стартовые эффекты один раз; `restore` восстанавливает
временные ресурсы после загрузки; `enable` вызывается при активации владельца.
Подписки автоматически пересоздаются без дубликатов. Смена реплики той же
сцены не запускает hooks заново. Отключение/удаление владельца отменяет его
дерево, задачи и ожидания. Остановка Play очищает handles без вызова author hooks.

`signal` подписки — ключ своего `signals`, ключ привязанного сигнала или ID
установленного сигнала. `match` — `owner` (по умолчанию), `any` или `component`
с именем `reference` из `refs`. `passPayload: true` передаёт поля сигнала как
аргументы; schema метода должна им соответствовать. В графовом компоненте
hooks, ссылки, сигналы и обработчики настраиваются в **Параметры и методы**,
а тело обработчика открывается как обычный граф метода.

## Прежние графы и Behavior Tree

С 20 октября 2026 раздел компонентов создаёт и редактирует только JavaScript.
Описанный ниже интерфейс создания графов и деревьев удалён. Данные старых
проектов и пакетов по-прежнему читаются, исполняются и экспортируются;
автоматического преобразования в код нет. Следующее описание сохраняет
семантику прежнего формата для совместимости.

**Создать → Компонент → Граф** создаёт отдельную реализацию. Добавляйте методы,
объявляйте аргументы в панели **Переменные**, выбирайте результат метода.
Настройки/состояние/ссылки находятся в свойствах компонента. Палитра содержит
чтение этих данных, запись состояния, вычисления, ветвления и методы всех
компонентов проекта. Управляющие и информационные провода раздельны.
Кодовое представление графа — справочное: произвольный JS обратно в граф
не преобразуется. Для JS используется отдельный кодовый ресурс.

**Создать → Компонент → Behavior Tree** создаёт редактируемое дерево и компонент
поведения. В **Методы поведения** доступны его обычные графовые методы.
В дереве есть selector, sequence, condition, задачи компонентов и вычисления.
Соединяйте нижний выход составного узла с верхним входом ветви; порядок детей
задаёт приоритет. Выходы данных подключаются к боковым входам условий/аргументов.
Задача выбирает опубликованный метод и конкретный экземпляр. Двойной клик
открывает метод, возврат ведёт обратно к дереву.

Задача возвращает void/true → Success, false → Failure или строку
`"Success"`, `"Failure"`, `"Running"`. Пока Promise не завершён, задача Running.
Вернувший `"Running"` метод вызывается снова при следующем обновлении.
Selector выбирает первый не-Failure результат; sequence останавливается
на первом не-Success. Guard условия проверяются повторно: переключение
ветви отменяет старую задачу до запуска новой. Ошибка ресурса/задачи сообщает
путь и узел, останавливает дерево до перезапуска владельца; отказ возвращайте
через false/Failure, если это ожидаемый результат поведения.

Дерево обновляется native tick с интервалом 0,1 с и не публикует покадровые
сюжетные Rules. Состояние методов и прогресс исполнения принадлежат экземпляру.
Выполняющуюся JS continuation нельзя сохранить; save требует завершения работы,
после загрузки обход дерева начинается с корня на восстановленном state.
Старый встроенный pursuit не преобразован в дерево и не выдаётся за него.

## Ошибки и сохранение

Черновик сохраняется вместе с проектом, включая синтаксически неверный текст.
**Сохранить компонент** проверяет декларацию, зависимости и синтаксис QuickJS,
затем обновляет индекс методов. Ошибка показывает путь/строку/столбец,
runtime также добавляет компонент, метод или узел. При ошибке/черновике запуск
затронутого компонента блокируется; предыдущая реализация тайно не исполняется.
Правильный сохранённый текст применяется при следующем Play. Hot reload нет.

Экспорт компонента включает исходный ресурс и зависимости. Импорт не исполняет
JS и требует просмотра/сохранения локального исходника перед запуском.
Один текст остаётся авторитетным: индекс schemas/методов — производные данные,
отдельной редактируемой compiled-копии кодового компонента нет.

## Подключения, история, ввод и кнопки

Выберите объект в **Иерархии**, затем именованное подключение в **Компонентах**.
Параметры/refs изменяют экземпляр. **Открыть общую реализацию** открывает ресурс
в центре, с указанием числа его подключений; **Создать независимый вариант**
явно копирует исходник и зависимости. Простое подключение не копирует ресурс.
Во время Play здесь же доступны значения state только для чтения.

В фазах истории, Events/Sequence, редакторе ввода и действиях кнопок есть
**Вызвать метод компонента**. Выберите owner → точное подключение → метод →
аргументы. Например, два Weapon одного объекта выбираются по подключению,
а не по первому совпадению типа. Удалённый/выгруженный owner даёт диагностику.
Переименование owner не меняет получателя.

В **Взаимодействии с объектом** назначается тот же вызов. Готовая кнопка
**Добавить дверь с замком** подключает обычный общий редактируемый LockedDoor
и назначает его `interact`. Код примера открыт как ресурс, методов в ядре нет:

```js
// Тела методов LockedDoor; полная декларация доступна в редакторе ресурса.
// setLocked · аргумент value: boolean · результат boolean
run({args, state}) {
  state.IsLocked = args.value;
  return state.IsLocked;
}
// interact · результат boolean
async run({state, owner, self, engine}) {
  if (state.IsLocked) {
    await engine.operation("sacura.game.message", {message: "Заперто"});
    return false;
  }
  return await engine.invoke(self, "open", {});
}
// open · результат boolean
async run({owner, params, engine}) {
  await engine.operation("sacura.door.animate", {
    object: owner, open: true, seconds: params.OpenSeconds
  });
  await engine.emit("opened", {});
  return true;
}
```

`setLocked(false)` не открывает дверь. `open` — отдельная задача до завершения
анимации, отмена фиксирует достигнутый угол. Следующая реплика той же сцены
не сбрасывает `IsLocked` и не пересоздаёт экземпляр.

### Разовый аргумент и постоянная привязка

В аргументах явно выбирается литерал либо **Переменная истории · один раз при
вызове**. Значение выражения вычисляется до запуска метода. Оно не меняется
после await и не включает постоянную синхронизацию.

В инспекторе **Постоянные привязки к истории** назначают верхнеуровневое
объявленное поле state/parameters на типизированную переменную. Каждое чтение
`state.IsLocked` / `params.flag` получает текущее значение, включая чтение
после await. Тип проверяется при чтении. Связанное state-поле не сохраняется
отдельно от переменной. Запись в него, в том числе `push` связанной коллекции,
отвергается с объяснением: измените источник истории явно. Для этого используйте
обычное действие **Изменить переменную**. Двусторонней привязки нет.

Формат данных для инструментов/fixture (автор выбирает имена в UI):

```js
// Разовая передача:
call.parameters.args.value = {
  op: "variable", variable: reference("variable", variableId)
};
// Постоянный источник экземпляра:
instance.fieldBindings = [{
  target: "state", field: "IsLocked",
  variable: reference("variable", variableId)
}];
```

Коллекция/объект связывается целиком. Привязки вложенных полей, произвольные
формулы постоянного источника и двусторонняя синхронизация не реализованы.

### Явный запуск длительной задачи

**Дождаться завершения метода** использует `sacura.component.call` и связывает
вложенную работу с вызывающей задачей. **Запустить задачу и продолжить**
использует `sacura.component.start`: выберите время жизни и явного владельца
(сцена, проект или конкретный включённый компонент). Sequence получит work
handle и завершится; следующая реплика не отменяет работу. Остановка выбранного
владельца или целевого компонента отменяет задачу и её дочерние ожидания.

```js
// Для программного инструмента: те же данные создаёт общий UI.
const work = await game.execute({
  id: "sacura.component.start", version: 1,
  parameters: {
    instance: reference("mechanic", behaviorInstanceId),
    methodId: "start", args: {},
    lifetime: "scene", lifetimeOwner: reference("scene", sceneId)
  }
});
// work = {kind: "work", id: ...}; работа использует прежний graphRuns registry.
```

Новый Behavior Tree имеет обычные графовые методы `start` / `stop`; подключение
его подготавливает, а бой запускается явно из Sequence вызовом `start`.
Ожидающий `start` удерживает исполнение дерева до Stop/отмены. Для боя выбирайте
длительный lifetime через общий picker. Явно запущенное дерево обновляется
и на репликах с `mechanics: gameplay-node`, без покадровой очереди Rules.
Старые деревья с прежним autoStart сохраняют совместимость. Save ожидающей
continuation не добавлен; перед сохранением завершите/остановите работу.


## Перенос, готовая игра и сохранение

Экспорт исходника использует явный [пакет v3](AUTHORING-PACKAGE-V3.md), не
расширение native API. В **Экспортировать компонент** выберите определения и
при необходимости начальные подключения; пустой список подключений допустим.
Зависимости собираются автоматически. Import preview показывает source без
исполнения; после импорта сохраните локальные JS-компоненты перед Play.

HTML использует тот же SDK и включает используемые source/graphs. Синтаксически
неверный или не просмотренный используемый компонент останавливает экспорт с
объяснением. Исходные проекты A/B для работы HTML C не нужны.

Save v3 сохраняет объявленный state и identity/version/bindings экземпляра.
`initialize` после Load не повторяется. Сохраняйте контрольную точку после
завершения/остановки методов: произвольный ожидающий Promise не сериализуется,
отказ происходит до замены предыдущего save. Native timer сохраняет remaining.
Новая игра берёт initial settings, save/load восстанавливает runtime-state;
экспорт заготовки не берёт текущие значения Play. Подробности и ограничения:
[экспорт и сохранения](GAME-EXPORT-SAVES.md).

## Дополнение: шаблоны и native-адаптеры

Рабочие примеры исходников находятся в
`engine-web-prototype/frontend/templates/components/`; полный каталог и
упражнения — [COMPONENT-TEMPLATES.md](COMPONENT-TEMPLATES.md).

`await engine.writeBinding("value", next)` — явная запись **в сюжетный источник**
постоянной привязки поля `state.value`. Без fieldBinding метод объясняет ошибку.
Прямая запись `state.value = ...` в связанное поле по-прежнему запрещена.
Пример работающего Counter:

```js
const next = state.value + args.amount * params.step;
if (params.storySource) await engine.writeBinding("value", next);
else state.value = next;
await engine.emit("changed", {value: state.value});
return state.value;
```

`storySource` — обычный объявленный boolean параметр Counter. В инспекторе
новеллы включён этот режим, а поле `value` связано с переменной relationship.
Имена переменных/ID в исходнике не нужны. Второе подключение того же Counter
не имеет привязки и сохраняет собственный снимок.

Таймер: `engine.operation("sacura.timer.start", {owner, name:"reward",
seconds:1, repeat:true, restart:false})`. `restart:false` сохраняет уже
существующий remaining. Все таймеры SDK имеют namespace подключения.
Подписка `{id:"own-timer", signal:"timer", match:"timer", methodId:"tick"}`
обрабатывает только события таймера этого экземпляра. В PeriodicReward
state.running создаётся из autoStart только в новой игре; enable читает state,
поэтому загрузка остановленного таймера не запускает его снова. Stop/Disable владельца
очищает его handles; чужие таймеры не затрагиваются.

`engine.operation("sacura.spatial.observe", {owner, target:refs.target})`
возвращает `{available,distance,direction,lineOfSight,clock}`. Это геометрический
запрос; обнаружение/атака/урон определяются кодом EnemyAgent. Выданное через
`sacura.movement.direction` намерение принадлежит вызывающей задаче и очищается
при её завершении или отмене. Долгое движение удерживается ожиданием в задаче.

Для Health/Weapon шаблоны подключают явные native adapters к конкретному
экземпляру. Методы adapter.methods — стабильные ключи публичных методов.
Health использует поля состояния hp/maxHP/dead; Weapon — ammo/reserve/nextShot/
reloadUntil/enabled, параметр magazine задаёт предел магазина. Не переименовывайте
эти поля, сохраняя старое соглашение адаптера. Это контракт native-возможности,
а не проверка имени компонента. Формулы, расход, перезарядка и смерть остаются
в исходниках. Название типа и отображаемые имена методов можно менять.


## Ошибки и владение доставленным сигналом

Вложенный `engine.invoke` сохраняет ошибку конкретного получателя: владелец,
подключение, определение, метод и доступная позиция в исходнике/узле. Панель
ошибки редактора останавливает Play и открывает эту реализацию. Если автор
ловит ошибку и добавляет текст к `error.message` перед `throw error`, контекст
получателя сохраняется. Новая ошибка `throw new Error(...)` — уже ошибка самого
авторского обработчика.

Реакция на доставленный сигнал принадлежит получателю. Отмена издателя после
доставки не отменяет принятую чужую работу; отключение получателя отменяет его
подписки и задачи. Отменённый издатель не публикует поздних эффектов.
Проверенные примеры и границы: [COMPONENT-ACCEPTANCE.md](COMPONENT-ACCEPTANCE.md).

## Вызов графового метода и переход к реализации

В редакторе графового метода раскройте **«Вызов метода из JavaScript»** и
нажмите **«Копировать вызов метода»**. Подставьте объявленную ссылку получателя
вместо `refs.component`; стабильный ключ выбранного метода и начальные
аргументы уже включены. Например, для метода с ключом `scale`:

```js
const result = await engine.invoke(refs.graph, "scale", {factor: 3});
return result;
```

Графовые методы, созданные редактором, обычно имеют сгенерированный стабильный
ключ: используйте скопированный вызов. Отображаемое имя можно переименовать,
не меняя ключ. В графе выберите этот же метод в палитре, задайте конкретный
экземпляр-получатель, свяжите исполнение и выход результата со следующим узлом.
Код и граф исполняются общим диспетчером; результат — значение метода.

**«Вызовы компонентов»** над JS-редактором открывает реализацию для
`engine.invoke(self, "key", args)` или `engine.invoke(refs.other, "key", args)`.
Назначенные ссылки и версия определения уточняют цель; одинаковые имена других
компонентов её не подменяют. Обратная команда **«К месту вызова»** сохраняет
исходник/состояние редактора. Двойной щелчок по графовому вызову также открывает
код или граф метода; возврат сохраняет порты, аргументы и провода.
Это статическая навигация без исполнения исходника. Вычисляемый во время игры
ключ метода или JS-алиас `engine` не распознаётся этой навигацией; runtime-вызов
по SDK при этом работает, реализацию можно открыть из библиотеки.

## Поля обычного JS-скрипта и defaults

Для обычного скрипта с `main(ctx)` доступен `const amount = SerializeField(5,
{label: "Награда"});`. Поля объявляются на верхнем уровне и появляются после
компиляции у экземпляров; `amount` и `args.amount` читают один аргумент вызова.
Тип/default меняются в исходнике, значения подключения — в инспекторе.
[Синтаксис, типы, перенос и ограничения](MECHANIC-JAVASCRIPT.md#поля-инспектора-прямо-в-коде--serializefield).

У кодового компонента `const component` продолжайте объявлять `parameters`.
Новое поле, добавленное уже после подключения, показывает schema default,
пока у экземпляра нет своего значения. Инспектор и runtime используют одну
функцию разрешения значений; чтение не записывает defaults в проект. Явные
`false`, `0`, `""` имеют приоритет над default. Никакого автоматического
изменения сохранённого HP/прогресса из-за открытия инспектора не происходит.
