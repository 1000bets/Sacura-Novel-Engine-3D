# Экспорт игры и сохранения компонентов

19 октября 2026. Реализованный контракт поверх `gameExport.js`, `gameSave.js`,
GameSession и общего SDK. [Авторский пакет v3](AUTHORING-PACKAGE-V3.md) переносит
заготовку; HTML — готовую игру; save — прохождение конкретной программы.

## Готовая игра

`preparePlayableGame` строит копию данных, удаляет migration backup и случайное
поле `world`, собирает используемые определения, функции и исходники компонентов.
Подключения, native настройки, история, ввод, UI и доступные публичные legacy
функции сохраняются. Последние сохраняются консервативно из-за динамических
вызовов; это не минимизатор всех Events/медиа всего проекта.
Неиспользуемый кодовый ресурс без ссылок/подключений в HTML не включается.

До чтения/выдачи runtime-файла проверяются определения, соответствие JS
деклараций индексам, status/approval/fingerprint, сигнатуры и зависимости.
JavaScript проверяется парсером и синтаксическим режимом QuickJS (обёртка
функции, без исполнения gameplay тела). Ошибка использованного исходника
называет путь/метод либо имя legacy-скрипта и останавливает экспорт. Сломанный
неиспользуемый черновик остаётся редактируемым в проекте и не портит сборку.
Семантическую ошибку, возникающую только на конкретных игровых аргументах,
статическая сборка не обещает обнаружить; её сообщает общий runtime.

HTML содержит проектные данные, IIFE player и CSS. Native медиа встраиваются,
JS `</script>` экранируется, внешние CSS imports удаляются. Кодовый исходник
является частью исполняемых данных SDK, не загружается как host-модуль.
Player собирается из `play.jsx` и использует тот же PreviewRuntime/GameSession/
RuleRuntime/QuickJS/диспетчер методов, сохранения и отмену. Manifest сборки
проверяет отсутствие Editor/Workspace/SchemaFields. React-компоненты player
и native Three.js renderer остаются частью готовой игры; редактор не требуется.

C.html, полученный тестом A → B → C, запущен через локальный HTTP в отдельной
вкладке без вкладки-родителя редактора. Кнопки дали 12/30; сохранение → изменение
до 24 → загрузка вернула 30; следующие отдельные вызовы дали 24 и 60, то есть
восстановлены независимые значения 12/30. PNG и Event также доступны без A/B.
Запуск через file:// и все браузеры/платформы этим прогоном не проверялись.

## Save v3 и совместимость

Для проектов с компонентами `gameSave` пишет version 3. Без компонентов остаётся
прежний version 2. Чтение поддерживает versions 1/2/3; прежний v2 с lifecycle
компонентов по-прежнему проверяется через fingerprint/stateVersion.

Save v3 содержит:

- прежние `projectId`, compatibility fingerprint, beat/phase/history/interacted,
  сюжетные variables, choice state, native world/HP/патроны/двери/таймеры;
- `world.game.mechanicStates[instanceId]` — объявленное runtime-state;
- `componentLifecycles[instanceId]` — initialized/enabled/destroyed/stateVersion;
- `components: {version: 1, instances: [...]}` — идентичность экземпляра,
  `definitionId/definitionVersion/stateVersion`, scope, references и fieldBindings;
- прежние разрешённые удерживаемые эффекты без несериализуемого audio handle.

Таблица components сверяется с проектом; неизвестные версии/изменённые bindings
и несовместимая программа отвергаются **до остановки текущей игры**. Save не
является переносом между разными программами или редактируемым пакетом.
Миграций несовместимого состояния пока нет: понятный отказ сохраняет текущий мир.

Восстановленные значения приоритетнее defaults. `initialize`, стартовая награда,
starter inventory и события входа истории повторно не выполняются. Временные
подписки/handles восстанавливаются через restore/enable без дубликатов. Native
состояние адаптеров не зеркалируется в авторские defaults. Связанное state-поле
не хранится второй раз: его источником остаётся сюжетная переменная из save.
Значения конфигурации и код проекта из Play не перезаписываются.

## Асинхронная работа: явная контрольная точка

Произвольный Promise, VM continuation, AbortController и выполняющаяся ветвь
Behavior Tree **не сериализуются**. Поддержанная контрольная точка — момент,
когда компонентные методы/Events/graph work завершены или явно остановлены,
а runtime разрешает сохранение в прежней idle-фазе. Ожидающий метод вызывает
отказ с именами компонента/метода и предложением завершить/остановить задачу.
Проверка идёт до записи в storage: предыдущий save остаётся целым. Поздний
сигнал после отмены не продолжает старый метод.

Native таймер — уже сериализуемая задача: сохраняются remaining/seconds/repeat,
владелец, scene/component ID. После load продолжает оставшееся время один раз,
без повторного стартового Event. Для нового дерева нужен явный Start после
его остановки/idle-save; сохранение с enabled-деревом без сериализуемой
контрольной точки отвергается. Автоматический повтор Start не добавлялся.
Поддержка сериализуемых стадий произвольных авторских async методов — следующий
отдельный контракт, не обещание восстановления Promise.

Фактически проверены: unlocked дверь после load; независимые счётчики 12/30;
initialize-награда остаётся 1; подписки не удваиваются; native таймер сохраняет
remaining и истекает один раз; отказ при ожидающем Promise оставляет storage
прежним; неизвестная definitionVersion оставляет живой runtime прежним.

## Компонентные шаблоны

Пять поставляемых проектов перечислены в [COMPONENT-TEMPLATES.md](COMPONENT-TEMPLATES.md).
`npm run build:templates` обновляет их пакеты, `node scripts/export-template-players.mjs`
создаёт пять самостоятельных HTML. Исходники в каждой сборке проходят тот же preflight.
Пакет «Писем» включает сжатую музыку и голоса; audio Actions используют явные
переназначаемые assetId, в том числе резервное возобновление музыки. Явный assetId
не добавляет в сборку одноимённый старый встроенный аудиофайл.

У новых Health/Weapon canonical runtime data находится в mechanicStates.
Native actors/weapons — представления того же объекта. Save не записывает
их повторно; validate/restore подключает представления к сохранённому состоянию
экземпляра. Native selectedWeapons — вычисляемое представление типизированной
ссылки Loadout.selected и также не дублируется в save. PeriodicReward сохраняет
running: остановленный таймер после загрузки остаётся остановленным; работающий
продолжает с сохранённым remaining без второго handle. Старые native-проекты сохраняют прежние native maps. Активный бой
по-прежнему требует остановки перед checkpoint; произвольные Promise не восстанавливаются.


В редакторе тот же save/load доступен в панели Play через «Сохранить прохождение»
и «Загрузить прохождение». Диагностика компонента — временное состояние сеанса;
она не попадает в save. Итоговый протокол: [COMPONENT-ACCEPTANCE.md](COMPONENT-ACCEPTANCE.md).
