# Компонентные шаблоны и упражнения
Текущая повторная приёмка изменённых правил: [COMPONENT-ACCEPTANCE.md](COMPONENT-ACCEPTANCE.md). Ниже сохранён протокол этапа перевода шаблонов.

Актуальный каталог: **шесть стартовых проектов и один пакет компонентов**.
В «Начните с готовой идеи» находятся квест, шутер, новелла и хоррор;
UI-кликер перенесён в сворачиваемый раздел «Ещё».
Основной путь: создать проект → выбрать объект в иерархии → подключение в
инспекторе → «Открыть общую реализацию». Исходник открывается в центре.
Параметры меняют только выбранное подключение. Раздел «Игровые механики» →
«Разбор проекта и упражнения» содержит описание и команды открытия исходников.
Внутри ресурса также есть короткий разбор. Техническая справка не добавляется
на игровой экран.

`src/componentExamples.js` и `tests/fixtures/component*.js` — уже компонентные
локальные сценарии предыдущих этапов, отдельными публичными шаблонами не являются.

жанровые compatibility-тесты сохранены. Установленный native-модуль
`src/extensions/reward.js` остаётся примером расширения API; новые Reward его
не используют: формула находится непосредственно в исходнике компонента.

## Один исполняемый исходник

Исходники в `templates/components/*.js` — настоящие декларации SDK. Генератор
помещает их читаемый, форматированный текст в редактируемые `logicResources`; методы публикуются обычным
`publishComponentSource`. Runtime не проверяет имя/ID шаблона или компонента.
В исходниках нет ID врагов, номера элемента массива или названия сцены.
Различия задаются параметрами и типизированными ссылками подключений.

Синхронный конструктор «Писем» использует **генерируемый**, а не независимо
редактируемый `src/bundledComponentSources.js`. Его источники — те же файлы
`templates/components`. Порядок генерации гарантирует обновление до загрузки
модулей конструктора. Изменения импортированной игры остаются локальными;
повторная генерация встроенных поставок их не меняет.

```sh
cd engine-web-prototype/frontend
npm run build:templates
npm run build
node scripts/export-template-players.mjs
```

Результат последней команды: шесть самостоятельных HTML в `dist/examples/`.
Файлы содержат runtime, используемые реализации и медиа, не требуют вкладки
редактора, исходного проекта или Vite. Player manifest исключает модули редактора.
Музыка «Писем» поставляется как `public/sound/MainMenuSound.mp3`, производная
исходного WAV: `ffmpeg -i MainMenuSound.wav -codec:a libmp3lame -b:a 96k MainMenuSound.mp3`.
В пакет и HTML входят MP3 и три голоса; обращения к исходному WAV не требуются.
`public/game-templates/asset-manifest.json` связывает SHA-256 встроенных медиа
с установленными файлами. Только создание first-party шаблона использует их
вместо копирования base64 в localStorage. Обычный импорт остаётся автономным;
повторный экспорт включает файлы с теми же хешами. Это не новый native API
и не выполнение установочного кода.

## Владение состоянием и работой

- У Health одного героя и пяти врагов **одно определение**, шесть отдельных
  `mechanicStates`. У двух Weapon одно определение, отдельные ammo/reserve.
  Native-записи содержат явный адаптер `{version:1, instance:<typed mechanic>,
  methods:{...}}`. Native `damage/heal/shoot/reload` делегирует назначенным
  методам. Старые builtin-графы для этих записей не создаются и не запускаются.
- `state.actors[id]` и `state.weapons[id]` — ссылки на те же объекты состояния,
  используемые физикой, HUD и совместимым API. Это не изменяемые зеркала.
  Native selectedWeapons вычисляется из поля Loadout.selected; native Select
  изменяет ту же типизированную ссылку. Save не дублирует выбранное оружие.
  При записи Save эти представления удаляются; сохраняется только состояние
  экземпляра. При восстановлении представления подключаются снова.
- Health.damage вычисляет урон, выставляет hp/dead и публикует ровно один `hit`,
  при смерти — один `death`. Повторный урон мёртвому не публикует их заново.
  DeathReaction один раз выдаёт награду и проверяет Objective. Все эти правила
  открываемы. Остановка дерева/боя после смерти запускается как работа владельца
  целевого компонента: отмена атакующей ветви не отменяет очистку и Game Over.
  Projectile/raycast только доставляют попадание в тот же API.
- Objective принимает коллекцию объектов либо тег; пустая группа не завершает
  задание, проверка до begin ничего не завершает. Нет сравнения с числом 5.
- Loadout хранит ссылку на конкретный Weapon. Ввод вызывает Fire/Reload через
  общий API; выбор пистолета и гранатомёта меняет эту ссылку, не ищет первый тип.
- Загрузка сцены только подготавливает компоненты. Реплика явно запускает
  Battle.run с lifetime сцены; дочерние Start деревьев принадлежат запуску.
  Следующая реплика его не отменяет. Stop или отключение владельца отменяет
  ветви; native-намерение движения освобождается только владельцем этой работы.
  Health и другие постоянные компоненты остаются доступны.
- EnemyBehavior — общий редактируемый ресурс с условиями/задачами. Каждое
  подключение имеет своё состояние исполнения и ссылку на своего EnemyAgent.
  Геометрия/физика native; условия атаки, подготовка удара, урон и преследование
  находятся в EnemyAgent. Планировщик дерева не ставит AI через сюжетные Rules
  с копированием проекта на каждом кадре.
- Два LockedDoor имеют независимый IsLocked из InitiallyLocked. История
  вызывает SetLocked(false) только склада; открытия это не вызывает. Interact
  затем вызывает Open, либо история отдельно ждёт Open. Следующая реплика
  замок не сбрасывает. Проверка/расход ключа — код того же определения.
- В новелле Counter «Отношение» постоянно читает сюжетную переменную через
  fieldBinding; `engine.writeBinding` явно изменяет источник. Второй Counter
  получает выражение разовым аргументом. После следующего ответа первое
  значение меняется, снимок остаётся прежним. Hero/Health/Weapon отсутствуют.
- PeriodicReward использует сериализуемый native timer с ID пространства
  конкретного подключения. Подписка `match:"timer"` принимает только его события.
  Новая игра один раз создаёт state.running из autoStart. Enable обеспечивает
  таймер только при state.running=true с `restart:false`, сохраняя remaining
  при загрузке. Сохранённый Stop остаётся Stop после Load. Stop/Disable удаляет
  его, повторный запуск — явный Start. Кнопка и тик вызывают один Reward.award.

## Проверки и границы

Автоматический прогон включает запуск и сборку публичных пакетов, независимый
импорт, изменение формулы/условия в реальном source, расход/перезарядку,
отмену без позднего начисления патронов, один hit/death, лечение и награду,
явный запуск/отмену BT, изменение chase на отступление, цели по тегу,
двери и сохранения, отсутствие дубликатов таймера, live binding против снимка,
A → B → C из настоящего шаблона с новым публичным методом, ошибки source,
preview/отмену импорта. Старые migration/жанровые fixtures проверяются отдельно.
Команды и результат актуального прогона записаны в COMPONENT-AUTHORING.md.

Граница сохранения остаётся прежней: активные произвольные JS Promise/BT-задачи
не сериализуются. Бой нужно остановить для контрольной точки; сообщение
появляется до записи. Состояние дверей/счётчиков и native timer сохраняется.
Полный hot reload Play и преобразование произвольного JS ↔ граф не реализованы.
Замена метода/формулы применяется при следующем запуске. Старые пользовательские
проекты не переписываются автоматически под новые шаблоны.

## Браузерный протокол этапа

Проверены настоящий редактор Vite и пять сгенерированных HTML через локальный
статический сервер. HTML содержат runtime и исходники, редактор при этом им
не нужен. Это целевые сценарии, не полный перебор всех реплик и вариантов.

| Проект | Play в редакторе | Автономный HTML |
| --- | --- | --- |

| Шутер | Открыт BT, из задачи открыт EnemyAgent, исправлен chase и выполнен возврат к месту вызова. История запускает бой, следующая реплика его продолжает; выстрел 6 → 5, Reload → 6, Stop останавливает врагов. | Бой начинается явно, враги подходят/атакуют; выстрел расходует патрон. После Stop аптечка меняет HP 1 → 36; Save/Load сохраняет HP 36 и магазин 6. |
| Новелла | Два поддерживающих ответа дают отношение/снимок 1/1 → 2/1; выбор становится доступен по отношению. | Повторён тот же сценарий, независимый снимок остаётся 1. |

Автоматические проверки покрывают больше изменений исходников, чем ручной
прогон: урон ×2, расход 2 патронов, два ключа вместо одного, chase → отступление,
новый публичный bonus, отмену reload/деревьев, Game Over от AI без самопрерывания
очистки, сохранение выключенного таймера и его remaining. Полный `npm test`:
**732 passed, 0 failed, 0 skipped**; отдельно 20 сценариев universal-templates.
`npm run build:templates`, `npm run build`, экспорт всех пяти HTML и
`git diff --check` выполнены. Все 22 JS-ресурса проектов после генерации совпали
с каноническими файлами `templates/components/*.js`.

Три продуктовых принципа проверены фактически:

- **Простота:** двери и исходники открыты через иерархию, ссылки выбраны по
  названиям, инструкции доступны в проекте, игровой экран не стал справочником.
- **Переносимость/редактируемость:** автоматический A → пустой B → изменённый C
  переносит Reward + Counter из действующего шаблона, добавляет bonus, запускает
  формулу +7 и собирает HTML; A остаётся прежним. В браузере этот HTML C
  показал счёт 0 → 9 → 59 через award и новый bonus. Preview/undo не меняет проект.
  Полный ручной перенос «Дверь с ключом» A → B → C в этом этапе не повторялся.
- **Универсальность:** те же источники Reward/Counter используются для очков,
  монет и отношений; новелла/кликер не подключают Health/Weapon/боевой контроллер.

Дополнительный браузерный проход закрыл все 106 сюжетных блоков, 28 выходов
выбора и три концовки «Писем». Исправленные схождения пересобраны и повторно
пройдены. Журнал и доказательства — [COMPONENT-ACCEPTANCE.md](COMPONENT-ACCEPTANCE.md).
Четыре взаимодействия StoryFlag в трёх сценах теперь проверены также
браузерным проходом. Ручной Relay A → B → C, скачивание и повторное открытие
файлов выполнены на этапе интеграции; их границы указаны в текущем протоколе.
Оставшиеся ограничения проверки: другие устройства и browser engines не проверены.
В переполненном хранилище браузера остаётся прежний лимит localStorage: старые
проекты не удалялись, итоговая проверка «Писем» проведена на отдельном origin.
First-party manifest уменьшает размер нового проекта до <600 КБ, но не заменяет
сам механизм хранения. Большие чанки сборки пока дают предупреждение Vite.
