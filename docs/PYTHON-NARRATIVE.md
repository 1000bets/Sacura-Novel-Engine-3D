# Python-ноды Narrative

Классы находятся в `Content/Scripts/` открытого проекта и регистрируются при его открытии. В графе истории откройте «Добавить ноду → Скриптинг»: там доступны зарегистрированные классы и опубликованные методы компонентов. Для обновления Python-объявлений после изменения файла переоткройте проект в новом процессе редактора.

Пример готового графа: `Samples/SampleProject/Content/Stories/NarrativeDemo.story`. Реализации: `Samples/SampleProject/Content/Scripts/narrative_nodes.py`. Этот пример не меняет стартовую историю проекта.

## Вычисление

```python
from engine import NarrativeNode, NarrativeResult, pin, register_node

@register_node(type_id="game.Multiply", label="Умножить", pure=True)
class Multiply(NarrativeNode):
    Inputs = {"Value": pin(float, Default=10.0), "Multiplier": pin(float, Default=2.0)}
    Outputs = {"Result": pin(float)}

    def Evaluate(self, Context, Value, Multiplier):
        return {"Result": Value * Multiplier}
```

Вычисление вызывается по запросу подключённого входа действия, один раз в рамках этого запуска действия. У него нет входа и выходов исполнения. Оно может читать `Context.GetVariable(Name)`, но контекст запрещает запись, ожидание и вызовы методов компонентов. Это контракт API, а не изоляция Python-кода.

## Действие и ожидание

```python
@register_node(type_id="game.DelayedValue", label="Записать значение после ожидания")
class DelayedValue(NarrativeNode):
    Inputs = {"Value": pin(float, Default=0.0), "Seconds": pin(float, Default=1.0)}
    Outputs = {"Result": pin(float)}
    Exits = ("Done",)

    def Execute(self, Context, Value, Seconds):
        yield Context.Wait(Seconds)
        Context.SetVariable("LastValue", Value)
        return NarrativeResult("Done", Result=Value)
```

Ожидание использует время симуляции. Пауза Play приостанавливает его, Stop/Reset закрывает генератор. Для освобождения собственных ресурсов можно использовать `try/finally`; после отмены контекст больше не разрешает обращения к игровому состоянию. `async def`, `asyncio` и произвольные значения `yield` не поддерживаются.

Обычное действие может сразу вернуть `NarrativeResult`. Для ветвления объявите несколько имён в `Exits` и верните выбранное имя. Неподключённый выход завершает историю. Ошибка Python, неизвестный выход или неверный результат останавливают историю с диагностикой.

## Пины, параметры и компоненты

`Inputs` и `Outputs` — словари имён и `pin(Type, Default=..., Label=...)`. Для входа без `Default` требуется значение либо провод; при добавлении ноды редактор задаёт начальное значение её типа (например, 0 или пустую строку). Ссылку на компонент нужно выбрать явно. Используются существующие типы рефлексии: `bool`, `int`, `float`, `str` и строковые идентификаторы движковых типов. Имена аргументов `Evaluate`/`Execute` должны совпадать с входами. Каждый объявленный выход должен присутствовать в результате.

Инспектор показывает значения входов и выбор источника данных; провод также можно протянуть от выходного пина к совместимому входному. Delete удаляет выбранную связь, undo восстанавливает её. Результат другого действия доступен после его исполнения; нода-вычисление исполняется автоматически. Циклы данных запрещены, циклы потока выполнения допустимы и не исполняются целиком за один кадр.

Ссылка `pin("engine.ObjectHandle")` выбирается в инспекторе из объектов и компонентов сцены и сохраняется по постоянному ID. В Play ссылка разрешается на объект копии игрового мира. В пользовательской ноде:

```python
RemainingHealth = Context.Invoke(Health, "TakeDamage", Amount=Damage)
```

Либо добавьте готовую ноду `game.Health / TakeDamage`: она создаётся из опубликованного `@method`, отдельный класс Narrative для неё не нужен. Параметр `Target` выбирает экземпляр компонента, остальные входы соответствуют параметрам метода, выход `Result` — его возвращаемому значению.

Переменные контекста принадлежат одному запуску истории. Они не являются настройками проекта и пока не сохраняются в игровое сохранение. Экземпляр класса ноды создаётся для каждого вызова; долговременное игровое состояние следует хранить в компонентах.

## Проверки

`Engine.Reflection.Python` проверяет исполнения, зависимости, ожидания, отмену, ветки и компонентные вызовы. `Editor.Narrative` проверяет создание нод, типизацию соединений, инспектор, сохранение, удаление и undo без UI automation.

## MCP и консоль редактора

`narrative_catalog` возвращает зарегистрированные классы, типы пинов, значения по умолчанию и выходы исполнения. `narrative_graph` читает активный документ истории, позиции нод и состояние Undo/Redo.

Команды редактирования работают с тем же документом, что и интерфейс:

- `narrative_add`: `type`, `x`, `y`; возвращает ID новой ноды.
- `narrative_input`: `node`, `input`, `value`; проверяет тип литерала и отключает прежний провод этого входа одной отменяемой операцией.
- `narrative_connect_data`: `source`, `output`, `target`, `input`; пустой `source` отключает провод.
- `narrative_connect_exit`: `source`, `exit`, `target`; выход задаётся именем, пустой `target` отключает переход.
- `narrative_node`: `node`, `operation` (`delete`, `move`, `set_start`); для перемещения обязательны `x`, `y`.
- `narrative_document`: `operation` (`undo`, `redo`, `save`, `validate`). Сохранение всегда явно.

Историю сначала открывают в интерфейсе редактора. Создание и открытие документов, редактирование Python-исходников, Events и нативных нод не входят в этот набор команд. Чтение доступно во время Play, изменения запрещены. Команды не исполняют Python-код ноды при редактировании.

## Границы переноса

Граф и его параметры сохраняются в редактируемом `.story`, реализации — в Python-файлах проекта. Импорт/экспорт отдельного пакета Python-нод с автоматическим сбором импортируемых модулей и перепривязкой ссылок между проектами пока не реализован. Это незакрытая часть требований переносимости; сохранение графа не считается приёмкой A → B → C. Встроенного редактора Python-кода и горячей перезагрузки классов в этой задаче не добавлено.
