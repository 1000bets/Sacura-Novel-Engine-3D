# Приёмка: «Дверь с ключом», A → B → C

Основание: [требования Sacura](PRODUCT-REQUIREMENTS.md).
Статус: основной цикл выполнен автоматическими проверками и через браузерный
редактор 13 октября 2026 года. Полный дополнительный перечень, включая
прослушивание звука и отказ хранилища через браузер, пока не подтверждён.
[Фактическое доказательство и ограничения](MECHANICS-IMPLEMENTATION.md).
Проверяется через обычный редактор, без правок JSON, ID, путей свойств или кода.

## Подготовка

Три независимых локальных проекта с разными ID объектов и разными названиями.
В A есть дверь и ключ. В B и C — свои дверь, ключ и флаг «Разрешение получено».
Для этого сценария не нужны герой, HP, оружие или боевой режим.
В B заранее есть несвязанное событие с именем «Дверь с ключом»: оно проверяет
разрешение конфликта имён. Сохраняем исходное содержимое A, B и C для сравнения.

## Основной цикл

1. **Проект A, создание.** Через Events, группы действий и функцию собрать
   проверку наличия ключа и открытие двери. Без ключа дверь остаётся закрытой;
   с ключом открывается. Объекты выбираются в интерфейсе. Для пользователя
   механика показывает понятные входы «Дверь» и «Ключ» и обычные параметры.
   Внутренние Event и функция открываются по запросу в существующем редакторе.
2. **Проект A, экспорт.** Выбрать только механику, экспортировать авторский пакет.
   Функция и вызываемые Events собираются автоматически. Для проверки ресурсов
   добавить звук открытия; он попадает в пакет. Добавить несвязанный Event
   и несвязанный ресурс в A: они в пакет не попадают. Исходная дверь и ключ
   не копируются как скрытые обязательные объекты сцены.
3. **Передача.** Передать только файл пакета на другой компьютер или в отдельное
   хранилище браузера. Проект A и его серверные ресурсы недоступны. Для импорта
   не нужны аккаунт, магазин, облако и установка расширения с кодом.
4. **Проект B, предпросмотр.** Импорт сначала показывает название, автора,
   лицензию, состав, зависимости и необходимые привязки. Выбрать дверь и ключ
   B в списках объектов. Конфликт имени показывается до применения; импорт
   предлагает новое имя и создаёт новые ID. Существующее событие B сохраняется.
5. **Проект B, применение и запуск.** Применить импорт. Проверить закрытую дверь
   без ключа, открытие с ключом и звук. Проверить, что несвязанное содержание B
   не изменилось и ссылок на проект A нет.
6. **Проект B, редактирование.** Открыть внутреннюю функцию тем же редактором,
   которым она создавалась локально. Изменить условие: нужен ключ **и** флаг
   «Разрешение получено». Добавить обычное действие подсветки двери после
   открытия. Расположить узлы и сохранить описание изменения. Сложность
   раскрывается по запросу; отдельного исполнения расширенной версии нет.
7. **Проект B, независимость.** Создать независимую копию механики, привязать
   к другой двери и изменить только эту копию. Проверить исходный импорт,
   первоначальный файл пакета A и второе размещение: они не меняются случайно.
   Локальные параметры экземпляра не меняют общую заготовку; изменение общей
   логики требует явного выбора этой заготовки.
8. **Проект B, повторный экспорт.** Экспортировать изменённый вариант. Редактор
   сохраняет исходное авторство/источник, добавляет сведения об авторе варианта,
   собирает новые зависимости и сохраняет описания и оформление графов.
   Вход флага экспортируется как понятная привязка, а не имя переменной B.
9. **Проект C.** Импортировать только файл из B; A и B недоступны. Выбрать свои
   дверь, ключ и флаг. Без ключа дверь закрыта; с ключом без разрешения закрыта;
   с ключом и разрешением открывается, звучит звук и появляется подсветка.
   Граф доступен для редактирования, расположение узлов и описания сохранены.
   Прочее содержание C не изменено.

Если в качестве продолжения выбран «Диалог после открытия», ссылка тоже
становится входом. Пользователь выбирает своё продолжение в B/C, а не чинит
ссылку на реплику A. Включённые в саму заготовку диалоги переносятся как её
редактируемые зависимости, без копирования посторонней истории.

## Проверки отказа и изоляции

| Проверка | Ожидаемый результат |
|---|---|
| Отмена предпросмотра или невыбранный обязательный вход | Проект не изменён; для входа есть короткое объяснение |
| Совпадающие ID/имена в проекте | Новые ID и явное новое имя; существующие записи не перезаписаны |
| Битая ссылка, повтор ID внутри пакета, отсутствующий ресурс или неверный тип входа | Ошибка до применения с указанием проблемного элемента; частичного импорта нет |
| Неподдерживаемая версия или обязательный модуль движка | Причина и требование показаны до применения; код не устанавливается автоматически |
| Пакет с JavaScript, установочным скриптом или неизвестным исполняемым узлом | Отклонён до изменения проекта; произвольный код не выполнен |
| Ошибка сохранения во время применения | Проект и библиотека остаются в прежнем состоянии; доступна повторная попытка |
| Две двери с разными параметрами/состоянием | Открытие и изменение одной не меняет вторую случайно |
| Новая версия исходной заготовки | Локальные изменения B/C остаются; автоматической замены нет |

## Доказательство приёмки

Нужны пакеты A и изменённого B, результаты запуска трёх комбинаций ключа/флага
в C, проверка зависимостей и отсутствия внешних ссылок, независимости копий,
сохранности описаний/графов/авторства, а также результаты проверок отказа.
Автоматические проверки дополняют проход через редактор: проверяется и модель,
и доступность действий для обычного пользователя.

Экспорт проекта A целиком, HTML-игра или вручную исправленный файл не засчитываются.
Если механика стала сложнее создавать, переносить или менять, приёмка не пройдена.
