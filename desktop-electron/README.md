# Sacura Desktop Experiment

Отдельная Electron оболочка существующего React редактора.

**Qt ↔ Electron проекты / Windows Release:** [round-trip, запуск production-пакета,
матрица совместимости и ограничения](PROJECT-COMPATIBILITY.md).

**Native Bridge:** [контракт, архитектура, запуск и результаты проверок](NATIVE-BRIDGE.md).
**React панели:** [матрица функций, архитектура и проверки](NATIVE-EDITOR-PANELS.md).
Общие Hierarchy, Inspector, Transform, Content Browser и StoryFlow работают с
Engine/EditorCore. Play/Pause/Stop/Step используют C++ PlaySession. Web сохраняет
существующие данные, команды и Three.js; JS PreviewRuntime в desktop не создаётся.

**Интерактивный C++ viewport:** [архитектура, сборка, проверки и ограничения](INTERACTIVE-VIEWPORT.md).
Desktop всегда использует Engine/Diligent D3D12. GPU texture импортируется через
Electron sharedTexture и VideoFrame; React overlays компонуются поверх изображения.
Web сохраняет Three.js. Qt Editor не меняется. `npm run native:start` открывает
изолированную копию SampleProject; `desktop:dev` открывает стартовое окно с
созданием, открытием и недавними C++ `.project` (либо используйте `SACURA_NATIVE_PROJECT`).

Из `desktop-electron/`:

```powershell
npm install
npm --prefix ../engine-web-prototype/frontend install
npm run desktop:dev
```

Vite запускается на `127.0.0.1:5173`; Electron открывается после готовности Vite. Изменения React обновляются через HMR. Закрытие Electron завершает дочерний Vite.

Сборка без сервера:

```powershell
npm run desktop:build
```

Результат в `release/win-unpacked/Sacura Desktop Experiment.exe` на Windows. Внутри пакета лежит локальная Vite сборка, открываемая через внутренний протокол `sacura://`; интернет и backend для запуска не нужны.

Проверка без UI automation: `npm test` проверяет запись и повторное открытие проекта; `npm run smoke:editor` запускает упакованное приложение с временным проектом и ждёт сигнала монтирования редактора. `npm run smoke:hmr` проверяет обновление JSX модуля через Vite без пересборки Electron. `npm run desktop:dev -- --desktop-smoke` проверяет development запуск.

Desktop сначала открывает окно проектов. Editor монтируется после успешной
загрузки выбранного `.project`. Можно передать абсолютный путь через
`SACURA_NATIVE_PROJECT`. Создавать промежуточный Web `project.json` не требуется.
Ctrl+S сохраняет `.scene` или `.story` активной области. Импорт ресурсов идёт через
системный диалог и EditorCore AssetImporter. Для безопасной демонстрации используйте
`npm run native:start`: изменения попадут только во временную копию SampleProject.

Ограничения: Windows / Electron 45 / D3D12; обычный `desktop:build` содержит Debug host,
production-конфигурация — Release host, Qt/Python и Engine resources. Save As всего
проекта, экспорт, импорт папок и 3D preview ресурсов пока не подключены. Play использует startupStory проекта, а не произвольный
открытый граф. Actions и сложные отражённые свойства редактируются через JSON с
валидацией C++. Полная матрица — в отчёте панелей. Историческое сравнение HWND и
shared texture: [первый этап](NATIVE-VIEWPORT.md).

## Стартовое окно и создание истории

- Стартовое окно использует тот же `ProjectHome`, `ProjectArtwork`, Dialog и CSS,
  что и Web: шапка, навигация, featured-карточка, библиотека шаблонов и список
  проектов. NativeProjectHome только выбирает launcher/Editor и передаёт адаптер.
  Первый запуск обновлённого интерфейса выбирает Sakura Night как на веб-референсе;
  последующие переключения темы сохраняются. Аккаунт/приглашения не имитируются.
- Карточки «Письма после дождя», «Квест», «Шутер», «Визуальная новелла» и
  «Последний обход» создают отдельные C++ `.project` через ProjectGenerator.
  Каждый содержит нативную сцену, стартовую историю и README с точками
  расширения. Это заготовки: веб-механики FPS, инвентаря и интерактивного
  point-and-click в них не переносятся. UI-кликер остаётся веб-шаблоном.
- Без `SACURA_NATIVE_PROJECT` запуск всегда показывает окно проектов; последняя
  запись не открывается автоматически. Создание вызывает C++ ProjectGenerator,
  открытие — проверку ProjectSession и запуск native host. Editor появляется
  только после готовности host и Bridge; ошибка оставляет доступными действия запуска.
- Недавние проекты сохраняются в `native-recent-projects.json` в Electron userData:
  только путь, название, время открытия и идентификатор записи списка. Это не формат
  проекта. Поддерживаются поиск, обнаружение отсутствующего файла и удаление записи
  без удаления проекта. Старые проекты нужно один раз открыть через `.project`.
  Удаление записи доступно по ПКМ на строке проекта с подтверждением.
- «К проектам» закрывает native host и возвращает стартовое окно. Сохранение /
  отказ / отмена используют существующий guard сцены и истории.
- «Создать историю» открывает документ сразу с начальной Line, выделяет её и
  показывает в StoryFlow/Inspector. Создание ноды, GUID, startNodeId, положение,
  Undo/Redo и сохранение выполняет C++ StoryGraphDocument. Начальная история
  сохранена на диске; последующие изменения используют обычную историю команд.
- Повторное создание с типовым именем выбирает свободное `New2.story`, `New3.story`…
  Пользовательские имена проходят исходную проверку конфликтов AssetRegistry.

Проверка упакованной Release-сборки: `--compat-roundtrip` проверяет отсутствие Editor
до выбора проекта, создание, возврат к списку, открытие недавнего через preload,
создание истории тем же React handler, выделенную ноду и Qt round-trip.
`build/compat-launcher-3/report.json` и соседние PNG — результаты после перезапуска
с сохранёнными недавними проектами. Проверки recents и Bridge:
`node --test tests/native-recents.test.cjs tests/native-project.test.cjs tests/native-bridge.test.cjs`
(для Release задайте `SACURA_NATIVE_HOST`).

Продуктовая проверка: основной путь сокращён до выбора проекта и создания истории;
данные остаются редактируемыми `.project` / `.scene` / `.story` с прежними GUID
и сериализаторами. Стартовое окно не добавляет игровых сущностей или runtime;
новая Line относится только к явно созданной пользователем истории. Обмен пакетами
механик A → B → C этим изменением не затронут и повторно не проверялся.

## Контекстные меню нативной истории

- ПКМ по графу или ноде использует общий Web `EditorContextMenu`: поиск,
  группы, подменю, стрелки клавиатуры, Enter и Escape. Типы Line / Choice / Action /
  End вызывают `story.addNode` с координатами графа; выпадающий список типов удалён.
- В меню выбранной реплики выберите фазу события, либо нажмите «+» у фазы/группы.
  Меню создаёт Wait / MoveTo / CameraCut / NavigateTo или размещает существующий
  Event из текущего StoryGraphDocument. Выделяется возвращённый C++ binding ID.
- `story.addEvent` принимает необязательные `actionKind`, `eventId`, `batchId`.
  C++ валидирует тип, фазу, ноду, событие и группу. Создание события с выбранным
  действием и его размещение — одна команда EditorCore с одним Undo/Redo.
  Qt-вызовы используют прежние значения по умолчанию; форматы файлов не менялись.
- Web-only Script/If/переменные/ожидание взаимодействия отключены с объяснением,
  не подменяются локальными JS-нодами. Настройка сложных Action/Event свойств в
  Inspector пока использует существующий JSON-редактор.

Проверки: `nativeStoryMenu.test.js`, `nativePanels.test.js`, `native-bridge.test.cjs`
и packaged `--compat-roundtrip` (меню, реальные C++ команды, Undo/Redo, Qt round-trip).

## Экран загрузки

Стартовый HTML показывает логотип Sacura и анимированный индикатор ещё до загрузки
React. Окно Electron сразу открывается с таким же тёмным фоном до готовности HTML.
При ошибке загрузки модулей появляется сообщение и кнопка повторного запуска.
Создание и открытие проекта показывают этапы из main process: проверка проекта,
создание файлов, загрузка сцены и запуск движка. Экран исчезает после готовности
Native Bridge; ошибки и отмена освобождают состояние загрузки. Проценты не имитируются.
Пока экран виден, команды клавиатуры редактора блокируются; reduced-motion отключает
анимацию. Форматы проектов, C++ сериализация и игровые механики не меняются.

CLI-проверка: `SACURA_TEST_BOOT_DELAY=1` вместе с `--compat-roundtrip` задерживает
загрузку React-модуля только в тестовом режиме для снимка `electron-loading.png`,
сохраняет `electron-project-loading.png`, проверяет успешное завершение загрузки
и сброс состояния после ошибки. Обычный запуск не имеет искусственных задержек.
