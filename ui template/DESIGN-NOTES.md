# Решения UI/UX и отличия от Miro

## Прочитанные источники

1. Полный MD «Архитектура Events, Action Groups и Actions», 4 272 строки, предоставленный пользователем.
2. Доска [3d Renpay SacuraNovel Sudio](https://miro.com/app/board/uXjVHr1G4Rw=/): концепция, устройство сабсцены, Blueprint, Timeline, Sound, Events, Groups/Actions, общая схема и сценарии перекрытия.
3. Дополнительно изучены актуальные документы [06 · Narrative](https://miro.com/app/board/uXjVHr1G4Rw=/?moveToWidget=3458764683022421391) и [07 · Event Runtime](https://miro.com/app/board/uXjVHr1G4Rw=/?moveToWidget=3458764683022421392).
4. Приложенный скриншот предыдущего интерфейса — референс проблем, а не обязательный шаблон.

**Доска не редактировалась.** Часть схем Miro уже обновлена по MD; ниже не объявляем эти исправления новыми идеями макета.

## Главная смена представления

Редактор открывается на истории. Автор читает её сверху вниз: реплика → постановка → выбор → общий путь. Свёрнутый эпизод показывает фактическое количество блоков, событий и ошибок. Варианты ответа показывают условие и объём ветки. Содержимое ветки раскрывается по запросу.

Режим «Карта веток» показывает направления переходов и общие точки схождения. Это обзор, а точное редактирование текста/условий выполняется в ленте и инспекторе. Вложенные выборы показаны отдельными развилками внутри своего эпизода; это не свободный нодовый редактор с перетаскиванием проводов.

Слои навигации: **Глава → Сабсцена → Смысловой эпизод → Блок → Размещение события**. Эпизод добавлен как редакторская организация; он не создаёт новый ownership scope runtime.

## Сопоставление понятий

| В архитектуре | В интерфейсе | Что сохранено |
|---|---|---|
| Event Definition | Шаблон события | Переиспользуемая постановка, без runtime-state |
| Event Binding | Событие в сцене | Фаза, join, условие и локальные параметры |
| Event Instance | Выполнение в предпросмотре | Отдельный ID запуска, владелец, состояние |
| Action Group | Шаг события | Шаги всегда последовательны |
| Actions в Group | Действия вместе | Параллельный запуск внутри шага |
| Event Batch | По очереди / Вместе | Применяется к размещениям в одной фазе реплики |
| Wait Target / Join | Когда перейти дальше | Не определяет время жизни эффекта |
| Scope | Остановить самое позднее | Граница, которая обязана остановить процесс |
| Retention | После выполнения шагов | Завершить, удерживать до Stop или Replace |
| Event Channel | Что заменяет это событие | Требуется для долгоживущего общего слота, не для каждого действия |
| Resource Claim | Объект · управляемое свойство | Определяется типом Action автоматически |

## Отличия и уточнения

1. **Вертикальная смысловая лента вместо широкой сетки Channels.** Фон отделён в компактную полосу. Нет ручного создания дорожки для каждого движения, звука или эмоции.
2. **Условия и ошибки видны там, где они действуют.** У ошибки есть объект, причина, место и конкретное исправление. Глобальный счётчик ведёт к той же диагностике.
3. **Доказанный конфликт двух Move считается ошибкой.** MD местами допускает предупреждение для параллельных Batch. Для явно совпадающего exclusive-ресурса макет блокирует Preview, как просил пользователь.
4. **SEQUENTIAL не является магической защитой.** При NONE/STARTED события могут пересекаться. Исправление конфликта меняет и порядок, и joins. BEFORE и AFTER не считаются одновременными только из-за общего режима Batch.
5. **Настройка placement отличается от настройки шаблона.** Можно менять первую экспонированную команду только в одном месте, открыть исходный шаблон и сбросить локальные параметры. В полном редакторе это стоит развить в явно объявленные exposed parameters.
6. **Время до подсказки не ограничивает игрока.** Ожидание осмотра продолжает жить, пока условие не выполнено; технические timeouts Actions показаны отдельно.
7. **Pause/Resume музыки и sidechain уточнены как понятные команды.** Sidechain на Miro уже означает аудиокомпрессию. Это не побочная ветка истории. UI показывает связь голос → музыка, а остановка/пауза/продолжение различаются.
8. **Звук не называется вторым Event.** В UI используются «звук» и «музыкальная композиция», чтобы не смешивать аудиоклип и narrative-событие.
9. **MVP и исследовательские возможности различимы.** QUEUE нельзя считать готовой безопасной политикой. В Miro 07 базовая реализация ограничена FAIL_NEW, явной заменой Channel и атомарным захватом ресурсов.
10. **Ошибки асинхронных подсистем имеют отдельный разбор.** ATOMIC не откатывает уже начавшееся движение; неподтверждённый cleanup не разрешает отдать ресурс следующему владельцу. Эти случаи показаны в лаборатории, а не ложно воспроизведены как работающий resource arbiter.

## Границы проверок

Живые ошибки вычисляются из данных: одинаковые ресурсы при одновременных запусках, внутренний конфликт группы, конфликт от локального изменения цели, отсутствующие объекты и события, несуществующий переход, выключенное взаимодействие, отсутствие безусловного ответа, continuous + COMPLETED/SELF, held + EVENT_END, отсутствующий slot для Replace, QUEUE без timeout, циклическая зависимость событий.

Граф ожиданий демонстрационный: он проверяет зависимости размещённых событий и не является полным символическим анализом ветвей. Потенциальные динамические конфликты, сложное смешивание анимаций, arbitrated audio playback, очистка и quarantine требуют отдельной реализации C++ runtime.

В «Состоянии выполнения» дополнительно показаны экраны и порядок реакции для частичного старта, исчезновения цели, сбоя cleanup, устаревшего handle и закрытия владельца. Для производственного движка именно эти контракты должны подтверждаться тестами subsystem-интеграции.

## Почему так проще

Новичок начинает с текста и действия, а не с ресурсов, enum и channel namespace. Человек, открывший чужую историю, видит смысловые эпизоды, условия веток, места остановки и ошибки. Технические подробности остаются доступны при настройке действий, но не занимают всю рабочую поверхность.
