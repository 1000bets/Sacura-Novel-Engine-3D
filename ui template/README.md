# Sacura Studio · интерактивный UI/UX-макет

Локальный макет редактора 3D-визуальных новелл и point & click на **React + Vite + Three.js**. Это исследование интерфейса, а не реализация C++-движка.

## Запуск

```powershell
cd 'F:\projects\Sacura-Novel-Engine-3D\ui template'
npm install
npm run dev -- --port 5173
```

Открыть http://127.0.0.1:5173/. Также можно запустить `start.cmd`. Пакеты уже установлены при создании макета.

## Что попробовать

1. На первом экране выбран конфликт: два события одновременно перемещают Алису. В свойствах нажмите **«Выполнить по очереди»**. Ошибка исчезнет, потому что изменятся реальные настройки размещения и ожидания.
2. Откройте **«Проверка проекта»**, изучите цикл ожиданий двери и разрешения Боба. Исправление заменяет цикл ожиданием действия игрока.
3. Нажмите **«Протестировать»**. Продвигайтесь по репликам, выбирайте ответы. В сцене поиска осмотрите письмо; до этого сценарий не продолжится. В исправленной сцене двери доступно отдельное взаимодействие.
4. Изучите **«Карту веток»**. В ленте ветки изначально свёрнуты; выбор карточки раскрывает путь, «Раскрыть все ветки» показывает содержимое для сравнения.
5. Перейдите в **«Библиотеку»**: создайте событие, добавьте несколько действий в шаг, следующий шаг и готовую группу. Выберите действие для настройки. Кнопка **«В сцену»** добавляет размещение к выбранному блоку.
6. Вкладка **«Объекты» → «Добавить объект»** создаёт персонажа, активный меш или декорацию. Новый объект появляется в гостиной и списках целей. Активные меши можно выбирать как условие ожидания.
7. В размещении настройте фазу запуска, ожидание, условие и локальные параметры первого действия. Шаблон остаётся отдельной сущностью; локальные изменения можно сбросить.
8. **«Состояние выполнения»** показывает запуски событий, фоновые экземпляры и лабораторию пяти сбоев: частичный старт, ошибка очистки, потеря цели, устаревший экземпляр, выход из сабсцены.
9. В проверке проекта есть дополнительные повреждённые примеры: ожидание конца музыки, зацикленное действие, удалённая цель и отсутствие безусловного ответа.

## Демонстрационная история

«Письма после дождя», сабсцена «Вечер в гостиной»:

- 6 смысловых эпизодов;
- **89 блоков**, включая **73 реплики и 10 развилок**;
- вложенные ответы, условия доверия и наличия письма, общие точки схождения;
- **53 размещения** 17 переиспользуемых шаблонов событий;
- 5 объектов, интерактивные письмо и дверь;
- музыка, пауза, продолжение и остановка, сайдчейн от голоса;
- закат, ночь, рассвет, дождь и гроза;
- последовательные/параллельные размещения, последовательные группы и параллельные действия;
- 2 намеренные исходные ошибки с исправлениями.

Сложность находится в данных и вложенных путях, а не в количестве обязательных дорожек. События привязаны к репликам; длительность чтения и исследования не изображается как известное число секунд.

## Сохранение

Автосохранение в localStorage этого браузера. Экспорт и импорт JSON позволяют перенести проект. **Ctrl+Z** отменяет изменения редактора, **Ctrl+K** ищет по всей истории, **Esc** закрывает окна. Сохранение не меняет исходные seed-данные репозитория.

**Настройки проекта → Восстановить демо** возвращает исходную историю и две намеренные ошибки. Это действие тоже можно отменить.

## Где макет упрощён

- Конечные действия применяют результат сразу; `duration` и таймауты редактируются для UX, но не исполняются настоящим планировщиком.
- BEFORE и ON_START выполняются при входе, AFTER — при выходе. Конкретные асинхронные барьеры подсистем не реализованы.
- Runtime-предпросмотр использует отдельный снимок Definitions. Выделение в редакторе не перемещает выполнение. История «назад» восстанавливает переменные, путь и состояние.
- Аудио показано состояниями и визуальной волной. Звуковые файлы и аудиодвижок не подключены. Сайдчейн демонстрируется временным снижением уровня с восстановлением.
- Свойства времени, погоды, положения, цвета, видимости и камеры влияют на сцену. Произвольные анимационные клипы/меши не импортируются: используются примитивы.
- Лаборатория runtime-сбоев — явно обозначенная UX-симуляция ожидаемых экранов, не реальные отказы C++-подсистем.
- Статический валидатор проверяет конкретные смоделированные случаи. Полного анализа всех достижимых состояний, динамического resource arbiter, карантина реальных ресурсов, script execution и production save/load здесь нет.
- QUEUE помечена исследовательским режимом. Безопасная производственная реализация требует runtime-графа ожиданий, детерминизма и timeouts.
- Локальные overrides экспонируют первое действие события. Редактор самого шаблона позволяет настроить любое действие. Готовая группа копируется в событие, а не связывается как живая изменяемая ссылка.
- Эпизоды — организационные разделы одной демонстрационной сабсцены. Переключение между несколькими реальными сценами/локациями не реализовано.

## Проверка

```powershell
npm test
npm run build
```

В `tests/scenario.test.js` — проверки ресурсных конфликтов, фаз и joins, локальных параметров, held/continuous, недоступного взаимодействия, deadlock repair, переходов по выбору, AFTER и состояния аудио.

В браузере проверены создание и отмена персонажа, создание/размещение события, диагностика и исправления, выбор ответа, ожидание/взаимодействие. Сборка содержит крупный bundle Three.js и иконок: оптимизация сознательно не является целью этого макета.

Исходники: `src/App.jsx` — интерфейс и авторские операции; `src/model.js` — история, диагностика и симуляция; `src/Scene.jsx` — 3D-примитивы; `src/FailureLab.jsx` — разбор сбоев. Подробные решения и сравнение с Miro — в **DESIGN-NOTES.md**.
